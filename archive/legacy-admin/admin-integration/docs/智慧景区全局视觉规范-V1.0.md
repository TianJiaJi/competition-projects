## 一、定位与使用方式

**总体基调：浅青底色、浓青绿山水、持续缓动、液态玻璃；标题有东方韵味，信息与操作清晰直接。**

设计方向为“当代青绿山水”，五端采用“同源分级”：共用品牌语言，根据展示、阅读和操作任务调整装饰强度。

### 1.1 风格元素的职责

| 元素 | 负责表达 | 使用边界 |
|---|---|---|
| 《千里江山图》参考 | 青绿设色、远近层次、长卷构图与空间节奏 | 进行数字界面转译；本文色值不宣称是原画取色 |
| 轻水墨 | 虚实、留白、景物间的柔和过渡 | 以淡青、石青、石绿晕染为主，避免大面积黑墨与脏污纸纹 |
| 液态玻璃 | 悬浮层、空间感和少数视觉焦点 | 折射集中于边缘，文字所在的中央阅读面稳定 |
| 宋体与书法 | 标题的东方韵味 | 正文、数据与操作使用黑体，功能名称直接易懂 |
| 青绿体素景区 | 可辨识、可操作的三维空间 | 统一体素尺度与设色，界面文字不做像素化处理 |

总体遵循“精简但能直接办事”：减少重复说明、装饰和并列信息，通过详情、图层与抽屉承接更多内容，保留任务所需的完整条件和结果。

默认构图以约 **70% 浅色空间、25% 青绿景物、5% 强调元素**为起点。这是视觉面积的构图参考，不要求逐像素统计；地图主视图允许提高景物占比，后台和核销降低景物占比。

强色集中在主景、主要操作和需注意的状态。赭金只用于少量细节，不以金色边框包围所有容器。当前版本只定义浅色主题；夜间闭园通过状态与景观表达，不自动切换深色驾驶舱。

### 2.2 颜色语义与可读性

- 品牌绿不自动代表“成功”，石青不自动代表业务状态；业务状态始终附带明确文字，必要时加图标。
- 忙闲等级沿用业务数据，不由前端根据颜色自行推断；“关闭”“维修”“断线”分别标注，不用“空闲”代替关闭。
- 普通文字对比度至少 4.5:1；大字号文字至少 3:1。大字号按至少 24px 常规字重，或至少约 18.7px 粗体判定，不仅凭标题角色判定。
- 必须依靠轮廓识别的输入框、选中标记与焦点指示，目标对比度至少 3:1。浅分隔线不能作为控件的唯一识别依据；此时使用更深的边界色。
- 透明容器按最终合成背景测量，不能用设计色值的对比度代替实际叠加结果。

以下为实色组合按 WCAG 相对亮度公式计算的对比度，保留两位小数；不代表玻璃效果已通过验收。

| 前景 | 浅青底 `#EAF3EF` | 内容底 `#F8FCFA` |
|---|---:|---:|
| 主文字 `#193B35` | 10.80:1 | 11.81:1 |
| 次文字 `#536B63` | 5.08:1 | 5.56:1 |
| 品牌主色 `#175F54` | 6.63:1 | 7.25:1 |
| 成功 `#226B4D` | 5.66:1 | 6.19:1 |
| 注意 `#8A580E` | 5.33:1 | 5.83:1 |
| 错误 `#B33F36` | 5.04:1 | 5.51:1 |
| 信息／石青 `#255D78` | 6.37:1 | 6.96:1 |

主按钮使用深青绿底与纯白文字，对比度约 7.50:1。

### 2.3 “现代”的具体实现

- 使用清晰网格、对齐关系和充足间距；不依靠仿古边框组织页面。
- 每个主要视图设置一个视觉中心、一个主要操作，其他内容分级呈现。操作型页面的视觉中心是任务或结果，地图页的视觉中心是景区空间。
- 用字号、字重和留白建立层级，同一区域内相关信息优先直接排版，减少层层套卡片。
- 主按钮采用实色深青绿，次按钮采用浅底或描边，低优先级操作使用文字按钮。
- 文化感来自设色、山水、宋体和少量书法。按钮直接写“入园预约”“查看路线”，不以生僻雅称代替功能名称。
- 不使用霓虹描边、科技线框、成排仪表盘、无意义数字滚动或持续闪烁来表达现代化。

### 2.4 字体与尺度

| 内容 | 字体 | 默认尺度 |
|---|---|---|
| 超大展示标题 | 可使用定制书法图片；缺省为宋体 | 手机 40–56px，大屏 64–96px |
| 页面／景点标题 | 思源宋体或 Noto Serif SC，600 字重 | 手机 28–32px，桌面 32–40px |
| 栏目标题 | 宋体，600 字重；紧凑工具区可使用黑体 | 20–24px |
| 正文、导航、按钮、状态 | 系统中文黑体 | 手机 16px，后台 14–16px，触控屏 20–24px |
| 数据 | 黑体，启用等宽数字 | 手机概览 28–36px，园方屏核心指标 40–56px |
| 单位、辅助文字 | 黑体 | 手机与后台不低于 12px；大屏关键标签不低于 18px |

正文行高默认 1.6，标题默认 1.25。普通正文使用 400 字重，按钮与强调内容使用 500–600，关键数字使用 600–700。中文正文不额外拉大字间距；单位弱于数值，但不能使用过浅颜色。

书法素材规范：

- 仅用于固定、短小的展示标题，每个视图最多一处；不要求每页都出现。
- 可以生成书法图片素材，必须人工核对字形与内容，导出透明背景，并按目标显示尺寸至少 2 倍准备清晰素材。
- 提供可访问的文本名称；若页面已有等价可访问标题，装饰图片不重复播报。
- 动态标题、按钮、状态和数值使用真实文字；素材未准备好时直接使用宋体。
- 不将书法图片拉伸变形，不添加厚重金属描边。宋体字体文件随项目资源提供，加载失败时使用本地宋体回退，避免依赖现场外网字体服务。

### 2.5 间距、圆角与图标

- 使用 4px 基础单位，主要间距为 8／12／16／24／32／48px。
- 手机左右留白默认 20px，后台 24px，大屏 32px；内容容器内边距默认手机 20px、桌面及大屏 24px。
- 控件圆角 12px，内容容器 20px，主要玻璃浮层 24px；胶囊形仅用于短标签和导航。2026-09-11 确认的液态玻璃公共按钮默认采用 **14px 小圆角**，通过 `radius` 参数调整，见 [液态玻璃公共组件](液态玻璃公共组件-V1.0.md)。
- 图标采用同一套圆角线性图标，24px 网格、约 1.75px 线宽；建议统一使用 Lucide，并统一覆盖默认线宽。不混用 emoji、毛笔图标与多套图标库。
- 手机触控目标至少 44×44px，游客触控屏至少 56×56px；图标本体可小于点击区域。
- 地图、图表与界面共享相同设施图标和状态语义，装饰图案不得伪装成可点击控件。

## 三、材质、景观与动效

### 3.1 画面层次

从后向前固定为：**浅青底 → 山水与云水景观 → 玻璃边缘及背景处理 → 稳定阅读面 → 文字、图标与焦点状态**。

背景流动、玻璃折射与内容分别处理。正文和点击区域不随背景移动；高细节山体经过容器后，阅读面仍有足够遮蔽。

### 3.2 液态玻璃

**2026-09-11 公共操作按钮更新：** 实测后优先采用 CSS 通透玻璃，默认 14px 圆角、2px 轻模糊和 18% 底色浓度，无纹理噪点、无 WebGL 折射；以细亮边和悬停反光表现材质。下表中高遮蔽阅读面与较大模糊用于内容浮层设计，不套用到当前轻透按钮。实时折射属于后续可选视觉效果，未作为正式公共组件能力，见 [组件说明](液态玻璃公共组件-V1.0.md)。

采用**边缘有明显厚度与折射、中央稳定清晰**的表现。液态感由边缘折射、左上高光与背景关系共同形成，不靠降低整块容器的不透明度。

| 参数 | 默认值／范围 | 约束 |
|---|---|---|
| 中央阅读面 | `#F8FCFA`，90% 不透明度起步 | 复杂背景下提高至 96% 或实色 |
| 背景模糊 | 默认 20px，范围 16–24px | 局部使用，不给整页叠加模糊 |
| 折射表现区 | 默认 3px，范围 2–4px | 位于边缘，独立裁切，不影响内容 |
| 细亮边 | 1px 半透明白色 | 统一左上光源，不做彩虹霓虹边 |
| 内高光 | 顶部轻微内高光 | 与边缘折射结合，不覆盖正文 |
| 外阴影 | 柔和、低饱和青黑阴影 | 不使用厚重黑色投影 |
| 同视口实时折射容器 | 最多 2 个 | 不嵌套，避免大面积重叠 |

适用：悬浮导航、地图工具、景点浮层、展示型重点容器。正文长文、表格、聊天记录、表单与二维码使用稳定浅色底；二维码另用纯白底。

实现时，背景模糊只是玻璃的一部分，不能把单独的 `backdrop-filter` 模糊当作完整液态折射。折射限于装饰层或背景采样区域，不扭曲文字、图标、二维码与点击区域；装饰层不拦截指针事件。

无折射能力或性能降级时，保留圆角、细亮边、内高光与稳定底色，以磨砂玻璃维持相同空间层级。

### 3.3 水墨与持续缓动

展示页保持轻微、持续的山水流动，主要位于远山、云雾、水面和留白边缘。

| 动效 | 默认值 | 允许范围／行为 |
|---|---|---|
| 背景山水循环 | 40 秒 | 首尾自然衔接，无明显重启点 |
| 背景轻微位移 | 8px | 4–12px，不移动内容布局 |
| 背景透明度变化 | 最大差值 0.04 | 不使阅读区亮度明显呼吸 |
| 点击与状态反馈 | 150ms | 120–180ms |
| 浮层展开 | 280ms | 240–320ms |
| 主场景过渡 | 750ms | 600–900ms，不阻塞操作 |

- 每个视口只设一个主要动态景观层；云、雾、水可作为该层协调运动，不各自形成争抢注意力的动画。
- 晕染使用青绿扩散与虚边，避免黑墨飞溅、满屏纸纹和高频颗粒变化。
- 背景以平缓曲线循环，界面开合以平滑减速结束，不采用夸张弹跳。
- 不让正文漂移，不持续改变容器尺寸，不在每次点击后播放整页晕染。
- 手机展示区和双大屏保留缓动；手机预约、聊天与阅读区域、后台、核销不设置持续装饰动画。
- 地图镜头默认保持稳定，通过选择点位或用户操作移动，不持续自动旋转。数据刷新不触发重新入场动画。
- 系统开启“减少动态效果”时停止装饰循环与液态动态形变，镜头直接定位或短淡入，保留必要状态反馈。
- 页面不可见时暂停装饰动画，恢复可见时继续平滑播放，不补播隐藏期间的动画。

### 3.4 青绿体素景区与二维地图

- 体素模型采用统一尺度；山体轮廓明确，植被、水面与建筑减少孤立碎块和细碎噪点。建筑的体素细节服务于景点辨识。
- 近景采用较浓石青石绿，远景降低饱和度并趋近雾白；统一柔和光照与接触阴影。
- 园方屏和游客屏共享同一景区模型、地形、点位和配色，分别配置运营与公共导览覆盖层。
- 手机二维地图沿用相同空间关系、名称、设施图标与青绿层级；不要求复制每一个体素块。
- 地图标签、路线与状态使用清晰界面图形，不做像素化文字，不用装饰纹理覆盖路线。
- 默认路线采用深石青实线与浅色外描边，起终点带明确标记；选中点位增加轮廓或标记，不依靠与山体近似的绿色区分。
- 关闭、维修和拥堵状态通过文字、图标及局部覆盖层表达，避免将整座山染成红色。
- 点位较多时按缩放级别显示标签，优先保留选中点、关键设施和当前路线；不把全部标签堆在一个镜头中。
- 照片用于介绍真实景观细节；体素用于空间导览；水墨用于氛围。景点照片自然、清晰，避免强滤镜和文字压在高细节区域。

## 四、信息密度、组件与五端统一

### 4.1 信息减法规则

| 对象 | 默认显示预算 | 深一层承接 |
|---|---|---|
| 游客首页首屏 | 一句主标题、一句必要说明、一个主行动、最多四个常用入口 | 完整服务列表与专题内容 |
| 概览卡片 | 一个核心数字或结论、一条状态、至多一条辅助信息 | 数据详情与变化依据 |
| 园方屏常态概览 | 四项核心指标 | 选点、图层、详情与趋势 |
| 预警 | 哪里、发生什么、建议动作 | 原因、影响范围、处理记录 |
| 普通概览说明 | 默认不超过两行 | 完整公告、长文、AI 回答进入阅读区域 |
| 主要任务区域 | 一个主按钮 | 次要操作降低视觉权重，但保持可发现 |

以上预算用于组织概览，不能成为截断必要信息的理由。预约时间、人数、取消条件、核销失败原因和风险操作后果必须在相应决策或结果区域完整呈现。允许页面自然滚动，不为满足首屏数量而缩小文字。

后台保留合理信息密度，使用表格、筛选与抽屉；减少装饰卡片、重复标题和重复单位。数值的单位、时间范围与“预计”性质必须清楚，不能因简写改变业务含义。

文案示例：

| 原表达／做法 | 规范表达／做法 |
|---|---|
| 当前在园游客总人数 | 实时在园 |
| 停车余位 128 个，下方再写“当前可用停车位为 128 个” | 只保留“停车余位 128 个” |
| 厕所空闲，实际处于维修关闭 | “维修中”，并显示关闭标记 |
| 操作失败 | “凭证已核销”，或显示后端返回的准确原因 |
| 一组数字，未说明实际或预计 | “今日累计入园”与“今日预计总量”分别标注 |

### 4.2 基础组件规则

| 组件 | 统一要求 |
|---|---|
| 按钮 | 主按钮深青绿底白字；次按钮浅底或描边；文字按钮用于低优先级操作。危险操作配合准确文案，不只变红 |
| 输入与筛选 | 黑体、稳定底色、持续可见的字段名称；错误定位到字段，并给出纠正方法；不只用占位符解释字段 |
| 状态标签 | 明确文字加图标或形状；颜色作为辅助。选中、成功、繁忙、关闭分别表达 |
| 数据概览 | 数字为主、单位清楚、标签简短；同类数字对齐。零值正常显示，缺失或断线不伪装成零 |
| 表格 | 稳定底色、数字列对齐、轻分隔线；详情与低频操作进入抽屉，不用逐行玻璃效果 |
| 浮层与抽屉 | 重要信息靠前；背景景观降低干扰；关闭入口明确，键盘焦点可见并在关闭后回到触发处 |
| 图表 | 以折线、柱状等直接表达比较与趋势；轻网格、清晰单位，不添加装饰性三维效果；预计趋势使用虚线并明确标注 |
| 地图工具 | 图标统一，触控范围足够；选中态与地图颜色有清楚区分；当前图层与状态可识别 |
| 反馈 | 加载提示具体动作；成功展示实际结果；失败说明原因和可用下一步；断线持续可见且不遮挡核心任务 |
| 二维码 | 黑色码点、纯白底、四周完整静区，不加玻璃、纹理、圆角裁码与变形动效 |

默认、悬停、按下、键盘焦点、选中、禁用、加载、成功与错误状态均沿用同一组件语言。触屏关键操作不依赖悬停才出现；禁用状态不能只降低透明度，还应在必要时说明不可用原因。

核销成功只在后端确认后展示；重复核销、错码与网络异常必须区分。实际 AI 回答、预置阅读内容及请求失败保持可辨识，不通过视觉包装把失败伪装成生成成功。

### 4.3 五端分级

| 终端 | 构图与信息重点 | 山水与动效 | 玻璃使用 |
|---|---|---|---|
| 手机游客端 | 首页呈现山水主景与直接入口；任务页聚焦操作 | 首页较强，预约、聊天和阅读页克制 | 悬浮导航与少量展示浮层 |
| 园方大屏 | 体素沙盘占主内容区约 55%–65%；外围指标与预警有序分布 | 青绿景区明显，远景缓动，数据区稳定 | 地图工具与选点浮层，指标阅读面稳定 |
| 游客触控屏 | 沙盘占主内容区约 65%–75%；突出景点、设施和路线查询 | 五端中最具游览氛围 | 大触控工具与景点浮层 |
| 后台及演示控制 | 固定导航、表格、筛选与抽屉详情 | 浅青底，无持续装饰动画 | 默认稳定内容面，少量浮层保留材质语言 |
| 核销终端 | “待扫描／核销结果”为中心，近期记录次之 | 极简，无持续装饰动画 | 结果区稳定实底，不做动态折射 |

全端统一颜色语义、字体职责、图标、按钮层级、圆角和反馈方式。分级只改变景物面积与效果数量，不改变同一状态、景点和设施的名称与含义。

### 4.4 尺寸适配

- 手机按 390×844 设计，并检查 360px 宽度；左右默认 20px 留白，内容与文字自然重排，底部导航避开系统安全区域。
- 后台以 1440×900 检查，园方和游客大屏以 1920×1080 检查；尺寸均指 CSS 视口，实际设备另查缩放比例与观看距离。
- 大屏按可用宽度重排，空间不足时先收起次要面板、减少同时展示的次要指标或改用详情入口，不整体等比缩小文字。
- 游客触控屏横竖屏分别保证地图主体与主要操作可见；竖屏将侧边详情改为底部面板。
- 操作面板不能覆盖当前任务的选中点或路线焦点；打开面板后调整地图可视范围。
- 长标题允许换行；关键条件和失败原因不省略。长表格局部滚动或调整列显示，不让整页产生无意义横向滚动。

## 五、三类典型构图

以下为全局规范的构图示例，用于验证共同语言，不构成全部页面的逐页蓝图。示例指标来自既有业务范围，数量是排版预算，不增加业务接口要求。

### 5.1 展示首页：手机游客端

自上而下：**简洁顶栏 → 山水主景与短标题 → 一个主行动 → 常用入口 → 后续内容**。

| 区域 | 内容与布局 | 材质与视觉重点 |
|---|---|---|
| 顶部 | 景区身份和必要状态，避免重复大标题 | 浅青底，黑体信息 |
| 主景 | 页面上部约三分之一的山水构图；标题落在留白处 | 浓青绿主景、淡墨远山、缓慢云水；可放一处书法标题 |
| 主行动 | 标准示例为“入园预约”，配一句必要说明 | 深青绿实色按钮，直接可见，不藏在景观内部 |
| 常用入口 | 最多四项，使用短名称；默认 2×2 排布 | 统一图标，避免每个入口各自折射 |
| 后续内容 | 推荐景点、路线或公告按内容重要性延续 | 简洁图片与文本，较长内容进入详情 |
| 悬浮导航 | 与系统安全区域留出间距 | 可使用一处液态玻璃，不遮挡首屏主行动 |

短屏或文字放大时，先缩减主景高度并允许内容向下滚动，不压缩主要操作与必要信息。常态保持精简，停运或关闭等会影响当前任务的公告优先显示。

### 5.2 地图大屏：园方与游客共用骨架

共同结构为：**轻量顶栏＋占主导的体素景区＋少量外围工具＋按需详情**。图表、标签和容器不争抢地图主景。

| 对象 | 园方大屏 | 游客触控屏 |
|---|---|---|
| 地图区域 | 主内容区约 60%，允许 55%–65% | 主内容区约 70%，允许 65%–75% |
| 概览 | 默认四项：实时在园、今日累计入园、当日有效预约人数、停车余位；时间口径保留 | 显示公共游览与设施信息，不堆放内部运营指标 |
| 周边内容 | 一侧概览与可切换趋势，一侧预警摘要；详情按需展开 | 景点、设施、路线分类工具与选中点详情 |
| 地图选择 | 选点后定位区域并显示状态及可执行动作 | 选点后展示景点／设施信息与路线入口 |
| 浮层预算 | 地图工具与选点详情最多两处实时折射 | 同左，触控尺寸按 56px 最小目标设计 |
| 信息边界 | 内部预警与调度显示在园方端 | 不显示个人订单、内部预警或游客聊天记录 |

常态先看清景区与四项概览；预警出现时突出位置、问题与建议动作，选中后展开依据。空间不足先收起趋势等次要面板，保持地图与关键预警可见。

### 5.3 操作界面：后台与核销

**后台构图：固定导航 → 页面标题与筛选 → 主内容表格 → 抽屉详情。**

- 内容按统一网格对齐，宋体用于页面标题，导航、表格、筛选与操作使用黑体。
- 浅青底与稳定浅色内容面形成层次，主内容区不放动态山水；避免将每行记录做成玻璃卡片。
- 筛选与操作靠近作用对象，主操作明确；保存结果和错误反馈出现在相关任务附近。

**核销构图：连接／工作状态 → 大字号待扫描或结果 → 必要凭证信息 → 次要近期记录。**

- 主要结果字号桌面默认 40–56px，说明 18–20px，根据现场观看距离放大；结果用图标、文字和局部状态色共同表达。
- 待扫描、提交中、成功、重复核销、错码、请求失败分别显示准确状态。提交中不能提前出现成功视觉。
- 近期记录位于次要区域，不与当前结果争夺字号与色彩；手动输入凭证作为清楚可见的备选入口。
- 二维码展示场景使用纯白稳定区域，标准 QR Code 静区至少四个模块；不在扫码区域上叠加晕染、玻璃与高光。

## 七、正确／错误用法与性能降级

### 7.1 正反示例

| 目标 | 正确用法 | 错误用法 |
|---|---|---|
| 青绿山水 | 浓青绿主景与大面积浅青留白形成主次 | 每块卡片各铺一幅浓山水 |
| 东方气质 | 一处书法主标题、宋体标题、黑体正文 | 按钮写成难懂雅称，表格也用书法图片 |
| 液态玻璃 | 边缘折射明显，中央文字稳定清楚 | 整块容器透明，正文随背景变形 |
| 持续缓动 | 远山和云水轻微流动，阅读区安静 | 全页卡片、数字、光带同时循环动画 |
| 信息减法 | 概览给结论，详情给依据 | 删除预约条件、截断失败原因 |
| 体素景区 | 统一颗粒尺度与青绿层次，标签清晰 | 山体碎块繁杂，标签也做成像素字体 |
| 跨端一致 | 同一景点、状态与设施名称和图标一致 | 同一维修状态在手机显示灰色“关闭”，大屏显示绿色“空闲” |
| 状态反馈 | 成功文字、图标和色彩共同表达 | 只依靠绿色背景或扫码枪蜂鸣表达核销成功 |
| 数据可信 | 明确“预计”，缺失数据明确提示 | 为填满卡片新增未定义指标，断线时显示零 |

### 7.2 性能与降级顺序

在实际演示设备上使用“体素沙盘＋缓动背景＋最多两个实时折射容器”的组合场景验证。以活动页面持续低于 30fps 为降级条件，实现时默认用连续两个 5 秒观察窗口判定，避免因单次加载抖动频繁切换。

按顺序降级，每一级后重新观察：

1. 关闭动态折射，保留静态细亮边、内高光和容器布局。
2. 降低背景动效，必要时冻结为静态山水。
3. 关闭背景模糊，改用稳定磨砂近实色底；仍不达标则记录为性能未通过，进一步优化三维场景后复测。

同次会话不自动反复升降效果等级。浏览器不支持所需滤镜时直接使用稳定磨砂样式；减少动态效果模式直接停用装饰循环，不需要等待低帧率出现。

以上为后续实现要求，本文没有完成真实设备性能测量。
