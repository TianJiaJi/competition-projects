## 1. 约定

### 1.1 传输与鉴权

| 项 | 约定 |
| --- | --- |
| 基地址 | 同源 `/api/v1`，前端不拼接域名，也不在组件中拼 URL |
| 响应包装 | 成功 `{ "data": ..., "meta": {...} }`；失败 `{ "error": { "code", "message", "fieldErrors?", "details?" }, "meta": {...} }` |
| 鉴权 | staff 身份 + Cookie 会话（真实版本）；前端不保存密码，不使用 `localStorage` 保存凭证 |
| 运行域 | 与样例运行相关的接口必须带 `X-Run-Id`（默认 `run_admin_mock_20260912`）；全局内容接口不带 |
| 写幂等 | 取消／改期／配额／撤回／禁言等写请求带 `Idempotency-Key`；同一标识重复提交必须返回首次结果，不得重复扣减配额 |
| 错误分支 | 前端按 `code` 判断分支，不匹配中文 `message` |
| 分页 | `page`（默认 1）、`pageSize`（默认 20，可选 20／50）；**服务端必须先完成全部筛选再分页** |
| 时间 | 上海业务时间（`+08:00`）；日期 `YYYY-MM-DD`，时间 `HH:mm`，时间戳 ISO 8601 带偏移 |
| 排序 | 默认按 `updatedAt` 降序，相同时间按稳定 ID；时段按开始时间升序；设施按共享配置顺序；告警见 3.11 |

### 1.2 错误码

沿用基线已有语义（`VALIDATION_ERROR`、`AUTH_REQUIRED`、`FORBIDDEN`、`NOT_FOUND`、`RUN_EXPIRED`、`SLOT_FULL`、
`ORDER_STATE_CONFLICT`、`FACILITY_CLOSED`），并新增下列**应用内**错误（前端本地 Mock 已使用，后端可用同名字段表达）：

| code | 含义 | 前端表现 |
| --- | --- | --- |
| `MOCK_STORAGE_FAILED` | 本地保存失败／存储不可用（应用内，真实后端不返回） | 保留草稿与旧数据，提示“本地保存失败”，不显示成功 |
| `MOCK_STORAGE_CONFLICT` | 其他标签已更改后台业务存储（应用内，真实后端不返回） | 保留草稿，拒绝旧快照写入与恢复操作，提示重新加载 |
| `RETURN_PATH_BLOCKED` | 该设施变更会造成返程通路中断或出口不可用 | 拒绝保存并列出受影响节点／区域名称 |
| `INSPECTION_PLAN_CONFLICT` | 同一设施已有一份启用中的检修计划 | 拒绝保存并给出设施名称 |

`fieldErrors` 为 `[{ "field": "servicePhone", "message": "..." }]`，前端把消息显示在对应字段旁；`details` 为受影响对象名称列表。

### 1.3 校验限制（服务端必须再次校验）

| 内容 | 限制 |
| --- | --- |
| 景区／景点名称 | 1—60 字 |
| 文章／公告标题 | 1—100 字 |
| 简介／摘要 | 1—300 字 |
| 地址与营业说明 | 1—200 字 |
| Markdown 正文 | 1—20,000 字 |
| 公告正文 | 1—2,000 字 |
| 操作原因／撤回原因／禁言原因 | 1—200 字 |
| 举报处理说明 | 1—300 字 |
| 检修说明 | 1—500 字 |
| 服务电话 | 7—20 位，仅允许数字、`+`、空格、连字符 |
| 图片 | 景点 0—6 张且去重；封面与正文图片必须来自随包素材清单 |
| 配额 | 非负整数，且不得低于已占配额 |
| 禁言时长 | 1—1440 整数分钟（默认 10） |
| 周期天数 | 正整数 |

字符一律按 Unicode 码点计数，必填字符串 trim 后不得为空。

### 1.4 枚举

| 枚举 | 取值 |
| --- | --- |
| `reservationStatus` | `confirmed` 有效／`cancelled` 已取消／`expired` 已失效 |
| `visitStatus` | `not_entered` 未入园／`in_park` 在园／`exited` 已离园 |
| `parkingStatus` | `not_arrived` 未到场／`waiting` 等候入场／`parked` 已进场／`departed` 已离场 |

| 公告生效状态 | `unpublished` 未发布／`pending` 待生效／`active` 生效中／`expired` 已过期（左闭右开） |
| 设施 `availability` | `open/maintenance/closed/unknown`（`unknown` 只读，不接受写入） |
| 消息 `source`／订单 `source` | `onsite` 现场／`background` 背景模拟批次 |

## 3. 接口明细

### 3.1 登录与会话（`staffLogin` / `getMe` / `logout`）

`POST /api/v1/auth/login`

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| `username` | string | 是 | 1—64 字 |
| `password` | string | 是 | 1—128 字 |

- 成功：`{ "data": { "userId", "username", "nickname", "expiresAt" } }`，并下发会话 Cookie。
- 失败：账号或密码错误统一返回 `AUTH_REQUIRED`（**统一提示，不区分账号不存在或密码错误**）；字段缺失返回 `VALIDATION_ERROR`。
- 演示账号 `admin_demo` / `AdminDemo123!` 仅用于公开样例，**不得作为生产凭证**。

`GET /api/v1/auth/me` → `{ "data": { "userId", "username", "nickname", "expiresAt" } }`；未登录或过期返回 `AUTH_REQUIRED`。
`POST /api/v1/auth/logout` → `{ "data": { "loggedOut": true } }`，服务端销毁会话；前端退出后不能继续读写业务页。

### 3.2 工作台 `getAdminOverview`

`GET /api/v1/admin/overview/summary?date=2026-09-12`

| 响应字段 | 说明 |
| --- | --- |
| `businessDate` | 统计业务日期 |
| `admissionPeople` | 当日有效入园预约人数，`reservationStatus=confirmed`，含现场与背景批次、含已入园／已离园 |
| `parkingVehicles` | 当日有效停车预约辆数，口径同上 |
| `pendingAlertCount` | 运行内 `pending` + `processing` 告警总数 |
| `pendingReportCount` | `pending` 举报总数（不受其他页面筛选影响） |
| `latestAlerts[]` | 最新 5 条未完成告警：`id/title/severity/location/startedAt` |

- **后端必须提供汇总读取**，不能要求前端把单页结果累加成全量。
- 数据缺失时返回 `null` 并在 `meta` 说明，前端显示“未知”，**不得用 0 冒充未知**。

### 3.3 景区资料（`getScenic` / `saveScenic`）

字段：`name`（1—60）、`summary`（1—300）、`address`（1—200）、`servicePhone`（7—20 位）、`coverUrl`（素材清单 ID／URL）、`openingText`（1—200）。

- `saveScenic` 为全局内容写入，不带 `X-Run-Id`；成功返回最新对象与 `updatedAt`。
- 校验失败返回 `VALIDATION_ERROR` 与 `fieldErrors`；前端保留输入、不关闭表单、不更新已保存内容。
- “营业说明”是展示文案，服务端不得据此改动预约或设施营业规则。

### 3.4 资讯与指南

`GET /api/v1/admin/articles?keyword=&category=news|guide&published=true|false&page=&pageSize=`
响应 `items[]`：`id/category/title/summary/body/coverUrl/published/createdAt/updatedAt/revision`；`total/page/pageSize/pageCount`。

- `keyword` 匹配标题与摘要（trim、英文不区分大小写）；**先筛后分页**，栏目筛选必须基于完整结果集。
- `createArticle`：新增默认 `published=false`；显式传入 `published=true` 时在同一次保存中创建并发布，失败不留下草稿；返回稳定 ID 与 `createdAt`；`POST /admin/articles`，请求体同下。
- `saveArticle`：`PUT /admin/articles/{articleId}`，请求体 `{ category, title, summary, body, coverUrl, published? }`；更新 `updatedAt` 并使 `revision` 递增。
- `deleteArticle`：`DELETE /admin/articles/{articleId}`。
- `body` 为 Markdown：只允许安全链接与素材清单图片；服务端需拒绝 `javascript:`、`data:`、`blob:` 等可执行 URL 并返回 `VALIDATION_ERROR`。

### 3.5 景点介绍

`GET /api/v1/pois?kind=attraction` → 共享点位（**仅** `kind=attraction`）。

`GET /api/v1/pois/{poiId}` → 共享字段 `name/regionId/nodeId/description` + 内容覆盖 `override: { name, summary, body, imageUrls[], sourceIds[] }`。
**共享常量、点位 ID、区域与节点不得被覆盖改写**，后台设施列表使用覆盖后的显示名。

`PUT /api/v1/admin/pois/{poiId}/content`

| 字段 | 校验 |
| --- | --- |
| `name` | 1—60 字 |
| `summary` | 1—300 字 |
| `body` | 1—20,000 字 Markdown |
| `imageUrls` | 0—6 张、去重、来自素材清单 |
| `sourceIds` | 可为空；未知来源 ID 必须拒绝（`VALIDATION_ERROR`） |

`GET /api/v1/admin/knowledge-sources` → 景点编辑的来源下拉：`[{ id, title, publisher, publishedAt? }]`（旧 `getSource` 仅支持单条读取，见 D-06）。

### 3.6 公告

`GET /api/v1/admin/notices?keyword=&audience=public|internal&published=&effectiveState=&page=&pageSize=`
响应含 `effectiveState`（服务端按 `startsAt <= now < endsAt` 计算）与 `startsAt/endsAt`。

- `createNotice` / `saveNotice`：`{ title, body, audience, startsAt, endsAt, published? }`；新增默认不发布，显式 `published=true` 时在同一次保存中创建并发布，失败不留下草稿。
- 校验：`startsAt` 必须严格早于 `endsAt`；允许创建过去区间样例；时间按上海业务时间。
- 发布过期公告仍返回 `expired`，不得提示“正在展示”。
- `internal` 公告只在工作人员视图可见；`deleteNotice` 不自动生成告警。

### 3.7 订单

`GET /api/v1/admin/orders`（`X-Run-Id` 必带）

| 参数 | 说明 |
| --- | --- |
| `type` | `admission`｜`parking` |
| `date` | 预约日期（默认样例当天） |
| `source` | `onsite`｜`background`｜`all` |
| `reservationStatus` | `confirmed`｜`cancelled`｜`expired`｜`all` |
| `fulfillmentStatus` | 按类型取 `visitStatus` 或 `parkingStatus` |
| `keyword` | 匹配订单 ID、联系人姓名／电话、停车车牌；背景批次只匹配订单号与批次号（无真人信息） |
| `page`/`pageSize` | 见 1.1 |

响应 `items[]`：`id/type/slotDate/slotStart/slotEnd/source/batchId?/contactName?/contactPhone?/people?/vehicles?/plate?/parkingLotId?/actualParkingLotId?/reservationStatus/visitStatus/parkingStatus/invalidReason?/createdAt/updatedAt/enteredAt?/exitedAt?/arrivedAt?/departedAt?/history[]`。

`GET /api/v1/admin/orders/{orderId}` 同上单条；详情需含本地取消／改期记录 `history[] = { at, actor, action: 'cancel'|'reschedule', fromSlot, toSlot, note }`。

`POST /api/v1/admin/orders/{orderId}/cancel`
请求：`{ "reason": "游客行程变化" }`（1—200 字）；响应：最新订单对象。
资格（服务端与前端一致）：`source=onsite`、`reservationStatus=confirmed`、入园 `visitStatus=not_entered`／停车 `parkingStatus∈{not_arrived, waiting}`，且在有效窗口内
（入园当日 17:00 前；停车到档结束后 30 分钟，右边界不含）。否则 `ORDER_STATE_CONFLICT`，背景批次返回 `FORBIDDEN` 语义（只读）。

`POST /api/v1/admin/orders/{orderId}/reschedule`
请求：`{ "targetSlotId": "slot-admission-2026-09-12-16", "note?": "" }`；响应：`{ ...order, "unchanged": false }`。

- 目标必须同类型、当天未结束档或次日档、停车目标场地开放、目标配额足够；否则 `ORDER_STATE_CONFLICT`／`FACILITY_CLOSED`／`SLOT_FULL`。
- 同档同场视为无变更：返回 `unchanged: true`，**不重复消耗名额**。
- **原子性**：校验最新存储 → 在事务内应用订单与两档配额变更 → 一次提交；任何失败必须保持原订单与原配额，不允许部分写入。
- 配额口径：`interactiveBooked` 包含该档尚有效未消费与已消费的现场配额；取消／失效的未消费订单释放配额一次；消费后不因离园／离场释放；背景批次不占现场配额。

### 3.8 预约配额

`GET /api/v1/admin/booking/slots?date=&type=admission|parking&lotId=`
响应 `items[]`：`id/date/type/lotId?/start/end/unit(person|vehicle)/interactiveQuota/backgroundQuota/interactiveBooked/remaining/bookable/unbookableReason?`。

- `remaining` 与 `bookable` 分别返回：有余量不等于一定能进场（场地停用、时段已结束都不可约）。
- 场地停用的未来档仍可调整配额，`unbookableReason` 保持不变。

`PUT /api/v1/admin/booking/slots/{slotId}/capacity`
请求：`{ "interactiveQuota": 40 }`（非负整数、≥ 已占配额）；响应最新时段视图。
**只允许修改 `interactiveQuota`**，不得修改时段起止、背景预约量或实体容量（停车实体余位不随之变化）。

### 3.9 设施运行

`GET /api/v1/admin/facilities?category=&regionId=&state=&keyword=`（运行域）
响应 `items[]`：`id/name/category/regionId/regionName/state/stateReason?/stateUpdatedAt/readonly[]/impact[]/relatedAlertCount/activePlanCount`。

`category` 覆盖：`attraction/road/parking/toilet/cable/safety/commercial/terminal/entrance`；道路的显示名由起终点名称组成，ID 保持共享值；
索道以 `cable-main` 表示一条运行对象，关联 `upper`／`lower` 两点与共享索道路段。

`GET /api/v1/admin/facilities/{facilityId}` 追加：`relatedAlerts[]`、`plans[]`；卫生间追加分项明细；道路／出入口／索道追加 `pathCheck`（现状可达性）。

`PUT /api/v1/admin/facilities/{facilityId}/state`
请求：`{ "state": "open|maintenance|closed", "reason?": "1—200 字（非 open 必填）" }`

- 道路只接受 `open`／`closed`；`unknown` 只读，写入返回 `VALIDATION_ERROR`。
- `gate-out` 是唯一配置出口，任何非 `open` 值都必须拒绝并返回 `RETURN_PATH_BLOCKED`。
- 通路校验（§4.2）：以所有开放景点节点、各开放区域代表通行节点（Z0→`entry`、Z1→`r1`、Z2→`r2`、Z3→`r3`、Z4→`r4`、Z5→`r6`、Z6→`r7`、Z7→`r5`，Z8 检查 `entry` 与 `r1…r7`）以及仍有样例占用的可定位节点为起点，检查**步行**通路可达出口；
  候选状态新增不可达 → 拒绝并返回受影响节点／区域名称；现状已不可达单独展示，不阻断提交；出口要求不得只依赖索道。
- 索道整线操作：上下站状态在同一笔中同步更新；排队与在途人数保留，不清零；不提供上下站或索道路段单独停用入口。
- 状态变更不得借机修改名称、营业时间、容量、路网或设备参数。

### 3.10 卫生间分项暂停

`GET /api/v1/admin/facilities/{facilityId}/restroom`

响应：整座 `state`（`open/maintenance/closed`）与四分项 `parts[]`：
`key(female|male|maleUrinals|accessible)`、`total`(N)、`occupied`(O)、`queue`(Q)、`baselinePaused`(B)、`requestedPaused`(R)、
`effectivePaused`(S)、`pendingRelease`(W)、`available`(A)，以及 `dataIssue?`。

`PUT /api/v1/admin/facilities/{facilityId}/restroom`
请求：`{ "state": "open|maintenance|closed", "reason?": "1—200 字（非 open 必填）", "requested": { "female": 10, "male": 0, "maleUrinals": 0, "accessible": 0 } }`

计算规则（服务端与前端一致，§4.3）：

- 整座开放：`S = max(B, min(R, N-O))`、`W = max(0, R-S)`、`A = N-O-S`。
- 整座关闭／维护：`S = N-O`、`W = O`、`A = 0`，原人工申请 `R` 保留，重新开放时按 `R` 重新计算。
- 守恒：`N = O + A + S`；四分项相加得到整座数字；**不改变 O 与 Q，不提前清退使用者**。
- 原有 `Q > 0` 时必须满足 `O + B = N`；若读取数据违反 `0 <= B <= N-O` 或 `Q>0 且 O+B≠N`，返回 `dataIssue` 并**禁止分项保存**。
- `R` 必须是非负整数且不超过该分项 `N`；负数、小数返回 `VALIDATION_ERROR`。

### 3.11 检修计划与告警

`GET /api/v1/admin/inspection-plans?keyword=&enabled=&due=due|upcoming|all`
响应 `items[]`：`id/facilityId/facilityName/intervalDays/nextDueDate/instructions/enabled/dueStatus(due|upcoming|disabled)/relatedAlertCount/createdAt/updatedAt`。

`POST /api/v1/admin/inspection-plans`（全局配置，不带 `X-Run-Id`）
请求：`{ "facilityId": "aed-entry", "intervalDays": 30, "nextDueDate": "2026-09-12", "instructions": "1—500 字", "enabled": true }`

- 检修对象必须是 15 处预置安全设施之一；`intervalDays` 正整数；`nextDueDate` 合法上海业务日期。
- 同一设施只能有一份**启用中**计划，冲突返回 `INSPECTION_PLAN_CONFLICT`（含设施名）。
- 计划有记录后不可更换关联设施；不提供删除，通过停用退出使用。

`PUT /api/v1/admin/inspection-plans/{planId}`、`PUT /api/v1/admin/inspection-plans/{planId}/enabled`（`{ "enabled": true|false }`）

- **到期生成**：`enabled` 且 `nextDueDate <= 业务日期` 时，生成一条 `severity=reminder`、`category=inspection`、`status=pending` 的告警；
  去重键为 `(runId, planId, nextDueDate)`，计划、生成记录与告警必须在同一次持久化中保存；刷新或重复保存不得重复生成。
- 未来日期不生成；计划停用或改成未来日期不删除已生成事件；本期不自动补齐过去多个周期、不自动推进下次检修日期。
- 告警标题为 `{设施名}定期检修`，位置来自共享数据，首次生成记录的 `actor` 为“检修计划”，标题与说明保留生成时快照。

`GET /api/v1/ops/alerts?scope=current|history&severity=&category=&status=&regionId=&from=&to=&keyword=&page=&pageSize=`（运行域）
`current` 含 `pending`／`processing`，`history` 含 `resolved`。

- 日期范围按上海自然日**包含起止当天**；`keyword` 匹配标题、原因与位置。
- 排序：当前按 `critical → important → reminder`，同级按 `startedAt` 倒序；历史按完成时间倒序，相同时间按 ID。
- `GET /api/v1/ops/alerts/{alertId}` 返回 `records[]` 处理时间线（时间、处理人、说明）与 `previousAlertId?`。
- **完全只读**：没有 acknowledged／recovered 状态、没有派单／开始／完成动作；没有处理记录时不得伪造处理人与完成时间。
- 负载回落不自动结案；恢复后再次超限是**独立事件**（`previousAlertId` 指向上一次），不得合并或自动回退状态（见 D-04）。

### 3.12 用户管理

## 4. 服务端必须保证的规则摘要

1. **先筛后分页**：所有列表筛选必须在完整结果集上完成；分页只是显示方式。
2. **原子写**：订单取消／改期与两档配额、设施状态与索道上下站、检修计划与生成记录／告警，都必须在一次事务中提交。
3. **幂等**：写请求携带 `Idempotency-Key`；超时重试返回首次结果，不重复扣减配额或重复生成记录。
4. **不假成功**：任何失败都不得返回成功包装；写入失败时前端保留草稿，服务端不得部分落库。
5. **只读边界**：告警、知识、订单车牌／联系人／人数与预约类型、设施位置与容量、共享点位 ID／区域／节点均为只读；后台没有扫码入园、代客聊天或设备控制能力。
6. **运行隔离**：运行内数据按 `X-Run-Id` 分区，未知或失效运行返回 `RUN_EXPIRED`，不得回落到默认运行。
