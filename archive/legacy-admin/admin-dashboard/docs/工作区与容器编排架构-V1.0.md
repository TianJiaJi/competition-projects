# 工作区与容器编排架构 V1.0

更新：2026-09-13。当前部署基线；PG 本地迁移已通过，生产集群及主备仍待部署。

## 工作区与业务边界

当前仓库统一管理 apps、packages、assets、docs、infra、scripts、experiments。六端为 mobile（H5/小程序，容器仅 H5）、ops、visitor、admin、gate（前线处置）、demo（演示控制）。共享 contracts/client/ui/scenic 保持职责边界；前端通过 HTTP 与 WebSocket 对接单活动 Node.js 后端，不跨应用引用业务源码。

实际代码已经覆盖平台业务与 QA，当前使用一个 PostgreSQL 17 数据库，保留平台与 QA 两组表名。接口及实现范围以 [六端交付记录](implementation/六端当前接口与交付记录.md) 为准，不能沿用早期“只有问答后端”的说明。产品流程仍以各专项需求最新变更为准，部署准备不改变识别设备、OA、仿真和告警业务。

## 部署决定

| 事项 | 当前决定 |
| --- | --- |
| 正式业务 | 现有内网 K8s，scenic-demo 命名空间 |
| 应用 | 六个静态前端，单活动后端、Recreate；模板默认后端 0 副本待 PG 就绪后启用 1 |
| 数据库目标 | PG 17 内网一主一备，异步物理复制、人工切换；本地迁移已实现；生产复制仍待实施 |
| 数据库现状 | 平台与 QA 两库已导入本机 PG；原 SQLite 一致性备份保留用于审计和回退 |
| Compose | 独立本地联调，单 PG；不承担正式主备 |
| 香港 | 拟购 2 核 2G，HTTPS 主入口，不保存业务数据库 |
| 备用公网入口 | my_server 记录的 92.5.152.95，接入既有 edge-caddy |
| 穿透 | 尚未选型；两个入口均回到同一内网业务，不固定 frp |
| 域名 | m、ops、visitor、admin、gate、demo.starhusk.com |
| 存储 | PG 主备各自持久卷，Retain；路径、节点、容量与宿主机关系部署前确认 |
| 发布 | pnpm 10.17.1、Node 24、ARM64 本机 / AMD64 服务器；同发布标签、分架构归档 |

旧“本机 Compose 备用、正式 SQLite 本地卷、固定 frps/frpc”方案已替换。旧方案仅保留在 [历史归档](archive/工作区与容器编排架构-2026-09-11.md)。

## 同一套数据

六端同源 `/api`、`/ws` 均由入口分流至唯一活动后端，后端连接统一主库 Service。不做备库读流量分担，不并行启动两套后台时钟或 AI。runId、业务时钟、revision 和业务快照由后端统一维护，各端按权限展示同一事实。断线显示真实连接状态，重连重读快照；明确指定 runId 的历史回放入口与当前展示分开。

主备复制允许滞后，关键是切换后各端统一连接新活动环境；不承诺数据零丢失。香港与备用 VPS 切换期间也必须转发到相同内网业务，不能转发到 Compose。

## 环境事实与未核实项

2026-09-11 检查记录：172.25.5.19/node1 单控制面、172.25.5.20/node2 工作节点；K8s 1.27.6、containerd 1.7.27、已有 ingress-nginx，HTTP/HTTPS NodePort 为 31101/31374。记录时没有列出 StorageClass/PV，根盘余量约 7.1/15 GiB，均需复查。

两节点是否位于同一物理宿主机未知，不宣称具备物理机容灾。单控制面失效也不保证可执行调度和切换。旧服务、旧 ngrok、旧命名空间和入口不被本次部署材料修改；不为新服务重建或升级集群。
