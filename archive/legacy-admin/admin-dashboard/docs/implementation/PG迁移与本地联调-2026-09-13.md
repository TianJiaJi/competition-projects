## 失败与回退演练

- 相同备份再次导入返回 `already-imported`，不会重复数据或覆盖开放后的写入。
- 非法 JSON 在写目标前失败；重复命令约束冲突时整批事务回滚，目标 accounts 行数仍为 0。
- 在专用 `scenic_fault` 数据库暂停插入，强制终止导入进程及其测试连接，确认 accounts 为 0，再次导入验证通过。详见 `interruption-audit.json`、`retry-after-interruption.json`。
- 基线备份 `.local/pg-migration/baseline.dump` 已恢复到独立 `scenic_restore`，documents 共 148 行，选中运行与导入基线一致。原 SQLite 成套备份仍保留。
- 正式开放后已有新写入，不能直接切回旧 SQLite。回退须先停写、备份 PG、登记增量，再决定前向修复或回迁。

## 实现与验证

平台、认证、HTTP、仿真、快照、QA 与 AI 调用链已异步化。事务使用同一池连接；数据库 advisory lock 保护跨进程幂等、配额及版本。运行对象从数据库反序列化为独立对象，失败不泄漏内存修订；WS 成功通知在事务提交后发送。后台时钟不会重叠运行，AI 停机等待正在执行的任务。独立应用实例锁避免同一业务 schema 双活动。

故障恢复只处理未完成 QA 并写 journal 审计，不在普通启动播种或重置运行；历史检查点清理由发布迁移处理。健康检查区分存活与数据库就绪。测试使用独立 schema 和假模型上游。

## 最后并发复查

六端同时访问曾暴露连接池耗尽及 WS 异步异常退出问题。事务现先在进程内排队再获取池连接，保留数据库 advisory lock；WS 心跳不再查询数据库，初始读取失败会关闭连接并允许重连。修复后六端并发30轮，共180次快照请求全部200，最大响应82ms，就绪探针200。该短时检查不替代现场30分钟持续运行验收。
