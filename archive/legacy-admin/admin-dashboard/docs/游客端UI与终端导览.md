# 游客端 UI 与终端导览

2026-09-11 实现。仅包含游客前端、公共组件和演示快照；不包含设备管理后台、服务端或真实求助呼叫。

## 操作与布局

底部保留并列操作：景点、设施、路线，以及互斥的 **游览、人流、卫生间、安全**。每次刷新固定点亮游览，不记忆上次模式；再次点击已选模式保持当前状态；返回默认展示必须点击游览。点亮状态使用公共预览第 3 款品牌色，普通按钮使用第 4 款透明材质（14px 圆角、2px 模糊、9% 底色），容器使用第 1 款（18% 底色）；左上角“青岚山境”图标、标题及导览状态，以及右上角时间、天气、实时在园和停车余位，分别整体使用第 4 款透明玻璃框（9% 底色）。

查询列表、详情、路线、天气、公告及手机导览共用右侧面板，同一时间只打开一个面板。1920×1080 面板宽 360px，1366×768 宽 330px，顶部避开数据区、底部避开导航，长内容内部滚动，不使用遮罩或跟随点位的气泡。

点击任何景点或设施（含卫生间、安全、停车、索道、出入口、补给及游客终端）打开详情时，镜头约用 1.05 秒平滑放大并将对应图标锚点移到屏幕正中央，暂停自动旋转。再次点击当前点位、点击沙盘空白或关闭详情均平滑恢复首次打开详情前的目标、距离及角度；连续选择其他点位仍保留这一原始镜头。默认镜头持续自动旋转，无需等待；手动拖动期间暂停，松手后继续。拖动旋转不视为点击空白。减少动态效果设置下直接到达终点。

卡片同时只连一根线：详情连选中点位；景点、设施列表或路线面板连对应底部按钮。所有连线固定接入卡片左边缘、屏幕高度正中间，不随卡片内容长度和内部滚动变化；详情不会回退到连接底部按钮。缩放工具固定在屏幕左侧，加减按钮通过平滑运镜改变距离，连续点击累计调整目标距离。

- 游览：原有景点、停车、索道、补给、出入口图标及四台游客终端；不显示卫生间和安全设施图标。
- 人流：地面热力及九个区域的人数。零值显示 0，缺失或断线显示“人数未知”，关闭区域显示“未开放”。数字来自快照，不随机生成。
- 卫生间：只显示卫生间图标，卫生间模型同步按忙闲状态着色。其他景物大幅降低饱和度及对比度，呈浅灰雾感，保留很淡的原色；不整体压黑。
- 安全：只显示六类安全设施图标，模型同步按可用状态着色，其他景物使用同样的浅灰雾感。绿色可用，红色关闭或维修，灰色未知。
- 所有模式都保留当前终端的“图标 + 我在这里”横向胶囊。当前定位不会被手动选择的路线起点改变。
- 切换模式清除当前详情及路线；从列表选点自动进入相应模式。三维点击拾取与图标可见性使用同一规则。

## 终端网址

具体切换步骤和四个终端的可点击演示地址见 [游客端使用文档：更换当前终端](../apps/visitor/README.md#更换当前终端)。修改网址参数后需重新加载页面。

只读取网址参数 `terminalId`，不读取部署环境变量。

| 参数 | 终端 |
| --- | --- |
| `terminal-entry` | 入口广场 |
| `terminal-bamboo` | 竹间驿附近 |
| `terminal-summit` | 山顶平台 |
| `terminal-market` | 归云集附近 |

示例：`http://localhost:5173/?terminalId=terminal-summit&alwaysOpen=1`。其中 `alwaysOpen=1` 是原有演示常开选项，与终端配置独立。

未提供参数默认入口终端；空值或未知编号显示“终端编号无效，已使用入口终端”。点击其他终端只查看详情，不改变本设备的位置。每次新建路线及两分钟空闲重置后默认从当前终端出发；游客仍可手动选择其他起点。山顶终端及望岳台可规划到归云集的步行或索道下行路线，索道停运或接驳道路关闭时拒绝不可用方案。二维码携带实际路线起终点及交通方式。

## 公共数据与接口

- `PointKind` 增加 `terminal` 和 `safety`。`ScenicPoint.safetyKind` 可为 `aed / first-aid / help / lifebuoy / extinguisher / shelter`，对应 AED、急救点、一键求助点、救生圈、灭火器、应急避难点。
- `packages/scenic/src/visitor-points.ts` 集中保存四台终端、15 处安全设施的位置及接入节点。新增接入边使用 `access-<点位ID>`，既有道路编号保持稳定。
- 状态继续使用 `PublicSnapshot.points[id]` 的 `availability`、`load`、`reason`。安全设施只按 `availability` 着色，不把忙闲当作可用性。演示数据中竹间驿灭火器及峡谷求助点处于维修；生产接口未提供的新点位状态显示未知。
- 设备关闭不等于共享前庭步道关闭；相邻卫生间检修不会切断终端通路，步道封闭仍以 `closedEdgeIds` 控制。
- `GET /api/public/snapshot` 和 `/ws` 连接方式不变。终端和安全点位要在生产环境可导航，需要服务端提供它们及所在区域的有效状态；不会回退到演示可用状态。
- `ScenicViewMode` 为 `default / crowd / toilet / safety`，`default` 的产品名称是“游览”。`ScenicMap` 增加 `viewMode`、`currentTerminalId`；传 `viewMode` 时以它决定显示及拾取，原有 `heat / showToilets / filter` 保留给未传新参数的宿主。
- `ScenicMap` 增加 `focus(id)`、`restoreFocus()` 方法和 `blank` 事件，便于宿主管理详情运镜及空白点击关闭。投影事件增加 `region-<区域ID>` 锚点；`ScenicScene.update` 末尾增加可选模式参数。
- 浏览器 `configure_scenic_view` 支持 `viewMode` 及可选 `pointId`，旧 `heat` 映射到人流或游览；不能与 `viewMode` 同传，也不能在指定模式中选择隐藏类别的点位。
- 安全设施详情支持查询、说明和到此路线；一键求助点没有实际呼叫按钮。
- SVG 公共底图包含新增终端及安全符号；卷轴传 `showVisitorFixtures=false` 保留原有画面。

## 索道

上、下站站房补有平台底座、落地支撑和顶部承接缆线的门架。途中三根支撑保持原有纤细尺寸。吊厢动画与真实容量分别配置，不根据画面中可见吊厢数推算人数。

详情新增全线容量、方向排队、预计等待与在途人数。容量参数与新数值规则统一归档于 [数值设计总文档 §6.3](景区24小时数据与数值仿真设计方案-V1.0.md#63-索道容量排队与忙闲)。

## 2026-09-12 触屏与开场更新

触屏电脑与横竖屏平板共用相同材质，单指即可操作；保留鼠标和 Mac 触控板。右侧长内容主面板底色提高至 82%，初始常驻容器保持原参数；人流标签改用公共第 4 款，定位胶囊及圆形标识等高。游览旋转中心固定，详情允许临时以设施为中心；回默认视角改为平滑过渡，卷轴使用共享透视相机和独立背景层，不随沙盘缩放拉长，独立深度避免挡住云雾。开场准备和 GPU 首帧预热移到可见动画之前，取消起卷后才开始构建。详细范围及浏览器缩放限制见 [触屏适配与验收](../apps/visitor/docs/触屏适配与验收.md)。

准备阶段使用左右向中间延伸的水墨进度条及中央百分比，进度来自实际构建、编译和首帧预热阶段；不再显示旧加载提示文本。
