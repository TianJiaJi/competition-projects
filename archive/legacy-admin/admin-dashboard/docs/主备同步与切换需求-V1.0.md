# 主备同步与切换需求 V1.0

日期：2026-09-13。状态：仅需求文档；不提供复制、提升、重建脚本或 PG 工作负载。

## 拓扑及故障边界

业务与 PG 主备全部位于内网 Kubernetes。六端连接一个活动 Node.js 后端，后端只连接 `scenic-pg-primary:5432`，不向备库分流读请求。Compose 是独立联调环境，不作为正式备用、不复制正式数据。

香港 2 核 2G 为拟购主入口；`92.5.152.95` 为既有 VPS 备用入口。两者都经各自穿透连接到同一内网 Ingress，不运行业务、仿真或保存数据库。备用入口不等于数据库备用节点。

现有资料记录 node1 `172.25.5.19` 为单控制面、node2 `172.25.5.20` 为工作节点，不能据此断言两者位于不同物理服务器。部署前确认虚拟机→宿主机→磁盘映射。相同宿主机只能覆盖部分实例故障，不能覆盖宿主机宕机；共享磁盘也不能视作独立存储容灾。单控制面故障可能使调度、Service 更新和切换操作无法执行，不承诺自动恢复。

## 数据库复制要求

- PG 17 同主版本、固定并记录小版本/镜像摘要，一主一备，异步物理流复制。基础备份建立备库后持续回放 WAL，不用定时复制数据目录替代复制。
- 主备按已核实的节点拓扑分开放置并使用各自持久卷；节点反亲和不代表物理宿主机隔离。若控制面不允许调度，先落实额外内网节点或获准的调度方案，不擅自解除旧集群污点。
- 使用独立复制账户、限制来源和认证加密。主库、备库、K8s API 不开放公网；入口穿透不得转发 PG 管理端口。
- 不承诺零数据丢失或固定 RPO/RTO，允许备库滞后；主库在复制断链时继续业务。切换时记录最后回放位置、断链时长及可能丢失的时间范围，未知时明确写未知。
- 记录复制连接、发送/接收/回放 LSN、时间与字节延迟、WAL 占用、复制槽保留量、磁盘及备份时间。设置有限 WAL 保留预算；断链超过预算后允许重建备库，不能为了追赶耗尽主库磁盘。
- 初始告警建议：复制断链或有写入时回放滞后持续 60 秒、磁盘使用率超过 80%、备份超过 24 小时未成功。阈值是运维初值，不是恢复承诺；空闲期结合 LSN 判断，避免用旧事务时间误报。
- 独立备份：每日基础/全量备份、连续 WAL 归档，初始保留 7 天，容量核定后调整；保存到不随主备共同丢失的受控存储，位置上线前确认。备库会复制误删，不能替代备份。

## 人工切换及回归

1. 宣告维护，两个公网入口和内网入口一起停止写入；记录活动 runId、revision、业务时间、当前主库及副本状态。
2. 停止/隔离旧活动后端和旧主写入。网络分区下必须确认断电、网络或存储隔离等有效 fencing；看不到旧主不等于旧主停止。无法确认隔离时保持维护，不提升。
3. 检查候选备库完整性和回放进度，记录接受的丢失窗口后人工提升；更新唯一主库 Service 的实际后端，只允许一个可写目标。role 标签本身不实现选主或 fencing。
4. 以 1 个后端实例重新加载新主库状态，恢复唯一业务时钟和后台任务，验证 schema、可写性及健康状态；开放前执行六端同源检查。
5. 统一开放入口；旧 WS 连接主动断开，客户端重新获取当前运行和快照。旧修订可能因异步数据损失回退，客户端需丢弃旧缓存，不能仅因 revision 较小就拒绝新快照。
6. 旧主回归先保持隔离，再从新主重建或经过验证的 rewind 回到备库角色；不得凭原地址/旧标签自动接回。计划回切重复停写、追平、隔离和验证步骤，不自动抢回。

后端单副本与 Recreate 仅是正常发布约束。节点失联时不得通过强删 Pod 就宣称旧进程已停止；恢复活动实例前同样确认隔离，避免双时钟、重复 AI 和两套数据。

## 公网入口切换

备用入口提前完成域名路由、穿透及证书准备。六个域名作为同一批切换 DNS，建议提前设 TTL 300 秒；DNS 缓存期间两个入口必须仍指向同一内网后端。不得把一部分域名切到 Compose 联调环境。

主入口失联时已有连接可能要超时后重连；切换时验证 HTTPS、登录、WS、AI 流式响应。备用证书不能假定在域名未解析到备用时自动签发成功：切换前通过已验证的 DNS 验证或受控证书预置方案准备证书，并验证续期。

## 核心验收与记录

- 六端按权限展示同一运行的数据：同 runId、同 revision 的相同字段一致；动态刷新无需同一毫秒绘制。默认跟随展示运行，固定 runId 的回放链接须显式区分，不算当前展示入口。
- 预约→订单统计、任务→OA→处置、公告发布/到期、聊天及场景切换均跨端核对。暂停业务时钟可用于稳定比较；每次比较记录 runId、revision 和时间。
- 断线不伪造样例成功；切换后所有端重新读取快照，不继续展示旧进程的独立计算结果。暂定正常网络下操作后 5 秒内完成相关端刷新，作为待实测验收目标。
- 演练：备用入口故障、主入口故障、后端重启、主库故障、复制断链、旧主回归、备份恢复；主备共享宿主机时注明未覆盖宿主机故障。
- 每次记录触发时间、恢复时间、LSN、潜在丢失范围、六端核对结果、操作者及回退点。不把模板渲染或 Pod Ready 等同于容灾演练通过。
