## 1. 项目定位与价值主张

### 1.1 一句话定义

**青岚山境智慧景区演示系统**是一个面向"竞赛评审 + 真实业务预演"双场景的单仓库（monorepo）演示平台：在内网用六端联动模拟一个 24 小时连续运营的景区，覆盖游客导览、园方监控、游客移动服务、前线处置、管理员运营与演示控制六大角色，并以统一 Node.js 后端 + PostgreSQL 提供数据持久化、AI 问答、客流仿真与实时消息广播。

### 1.2 目标用户

| 角色 | 触达端 | 关注点 |
| --- | --- | --- |
| 普通游客 | 游客大屏（触控）、手机游客端（H5/小程序） | 找景点、查设施、预约入园/停车、扫码识景、AI 问答、聊天室 |
| 园方运营 | 园方大屏 | 全园指标、客流趋势、调度任务、告警与处置状态 |
| 一线员工 | 前线处置终端 | 领取任务、提交反馈、申请 OA、查询历史 |
| 管理员 | 管理员后台 | 内容、订单、设施、OA 审批、用户、服务状态、聊天与知识 |
| 演示控制员 | 演示控制端 | 切换场景、控制时间、注入事件、模拟员工启停 |

### 1.3 价值主张（相对传统景区方案）

1. **六端共享一份运行态**：写请求通过幂等键 + 版本号双保险，提交后通过 WebSocket 广播；六端重新拉快照，杜绝"多端对不上账"。
2. **公式驱动的客流仿真**：用确定性哈希种子 + 业务日期推算入园需求、车辆/索道批次、停车占用、卫生间释放、天气、区域人数与告警；同一运行同一业务时刻可复现。
3. **24 小时场景回放**：六个内置场景（工作日平稳 / 周末午高峰 / 局部拥堵 / 设施维护 / 求助 OA / 闭园跨日），倍速 1×/5×/30×/60× 与暂停控制便于现场演示。
4. **真实 AI 接入**：文字问答、聊天生成与言论审核走统一 DeepSeek 代理；密钥只配置在服务端，前端不得携带。
5. **可演示 ≠ 已上线**：所有 README 与文档显式区分"已实现 / 仅原型 / 演示数据 / 待验"，避免对竞赛与甲方做出虚假承诺。

### 1.4 当前阶段

- ✅ 迁移 PostgreSQL 17，本地联调与端到端联调完成。
- ✅ 六端共享运行；写请求幂等 + 版本校验 + WS 广播。
- ✅ 模拟员工自动领取与完成告警；OA 仍人工审批。
- ⚠️ 模拟数据驱动，客流、设施、到离园尚未连接真实硬件。
- ❌ 生产主备、公网部署、人脸设备、正式微信真机扫码仍待验收。
- ❌ 高拟真校准、细场景事件、RAG 会话管理与模型端到端验收仍需补齐。

### 2.3 后端架构

- Node.js HTTP 原生服务器（无 Express），统一路由前缀 `/api/v1`。
- 鉴权：`Authorization: Bearer <token>`；运行绑定 `X-Run-Id`；写请求带 8—128 字符 `Idempotency-Key`；版本更新需 `expectedVersion`。
- 响应统一封装：`{ data, meta }` 或 `{ error, meta }`；响应头携带 `X-Run-Id`、`X-Revision`。
- WebSocket `/ws?app=<端>&runId=<运行>` 只广播失效通知，客户端必须重新拉快照。
- 数据库单活动实例锁 + 事务 advisory lock；所有写入走事务，提交后广播。
- CORS：白名单来自 `ALLOWED_ORIGINS`，默认包含 5173/5174/5175/5176/5177/5178/5179 的 localhost 与 127.0.0.1。
- 健康检查：`/api/v1/health/live` 仅验进程；`/api/v1/health/ready` 验数据库连接、schema 版本、可写主库、选中运行；`/api/v1/health` 保留兼容入口。

### 3.2 模块边界原则

- **应用间不互相 import 源码**：业务实现集中于 `apps/server/src/platform`；跨端类型与客户端 SDK 经 `packages/contracts`、`packages/client` 复用。
- **共享组件 vs 应用专属**：液态玻璃、唱片架、SVG 沙盘、等高线、滚动条放 `packages/ui`；单端控件放各自 `src/components`。
- **本地 Mock 与真实实现并存**：管理员、前线、园方大屏保留本地原型；当前默认入口已切换到真实后端（如 admin 5179 直接连 8787）。
- **共享资源**：`assets/景点二维码/` 内 7 张图片与映射清单；`assets/scenic-*` SVG 被多个端复用。

### 3.3 共享包 (`packages/`)

## 4. 六端详解

> 共同点：所有写请求走统一后端；本地 Mock 仅保留作为离线演示与单元测试兜底；游客大屏与园方大屏免登录；其余需登录态或管理员态。

### 4.1 游客大屏 `apps/visitor`（端口 5173）

- **定位**：公共三维导览触控终端，部署在景区入口广场、竹间驿、山顶平台、归云集四个位置。
- **能力**：3D 沙盘、客流热力、景点与设施查询、步行选路、四种展示模式（游览 / 全景 / 设施 / 模式切换）、触屏单指交互、平板布局、页面缩放拦截、男女及无障碍卫生间数据、索道容量与排队、公共玻璃组件。
- **终端切换**：通过 URL `?terminalId=terminal-entry | terminal-bamboo | terminal-summit | terminal-market` 切换；测试生产同一规则。
- **数据模式**：`VITE_DATA_MODE=sample | live`；默认 sample，连真实后端失败不回退。
- **二码能力**：默认不配置 `VITE_MOBILE_URL`，不生成指向不存在页面的二维码；保留二维码参数生成能力以备未来独立手机导览对接。
- **测试**：单元 + 触屏验收 + 滚屏 + 索道/卫生间详情 + 设施聚焦 + 客流。
- **归档**：2026-09-11 数据清单；触屏适配 2026-09-12。

### 4.2 园方大屏 `apps/ops`（端口 5175）

- **定位**：免登录只读运营监控；演示用三维沙盘 + ECharts。
- **能力**：运行指标、趋势（客流、车位、索道、卫生间）、任务与告警展示、调度结果、玻璃/气泡/等高线背景。
- **样例快照**：默认 2026-09-12 14:30，5461 人在园、8236 累计入园、288 余位、7 未完成告警；集中在 `src/mock.ts`，可经 `?preview=1` 切换六种样例。
- **未实现**：真实后端连接、派单、结案；前线终端与人脸识别本轮不实施。
- **测试**：`pnpm test:ops`（Vitest + Playwright `dashboard.spec.ts`）。
- **数据归档**：2026-09-12 归档；运行时可由 `node scripts/archive-ops-data.mjs <输出目录>` 重新导出。

### 4.3 手机游客端 `apps/mobile`（端口 5176）

- **定位**：uni-app 同源构建 H5 与微信小程序；面向游客个人服务。
- **四栏布局**：首页 / 导览 / 预约 / 我的。
- **能力**：二维码导览、注册预约、扫码识景、聊天室、AI 文字问答（调用 `deepseek-flash`）、我的收藏与游览记录、模拟入园/设施状态/重置（演示路由）。
- **数据隔离**：预约/收藏/聊天室/游览记录在本地（按运行 ID 隔离）；AI 问答与景区开放状态来自服务端。
- **地图**：共享 PNG + 点选层，路线为真实路网八条模板；距离米、含步行与停留估计。
- **构建**：`dist/build/h5`、`dist/build/mp-weixin`；小程序服务地址通过 `.env.local` 中 `VITE_API_BASE_URL` 编译时设置；密钥不得入 `VITE_*`。
- **测试**：默认本地 mock；`RUN_LIVE_QA=1 pnpm test:mobile` 显式调用真实模型。
- **未验收**：原生模拟器、真机、键盘、安全区、扫码；真机不能访问电脑 `127.0.0.1`，当前无局域网/合法域名配置。
- **依赖**：图标许可证见 `THIRD_PARTY_NOTICES.txt`；地图与路线资源由 `pnpm --filter @scenic/mobile assets` 更新。

### 4.4 前线处置终端 `apps/gate`（端口 5177）

- **定位**：员工手机网页，本地完整 Mock 原型；演示员工任务领取、文字完成反馈、OA 申请/撤回、历史筛选、独立演示审批。
- **设计**：浅青底、宋体标题、共享静态等高线背景。
- **演示闭环**：待办领取 → 提 OA（待审批时不能结案）→ `#/demo` 模拟批准/驳回 → 提交文字结果 → 记录中查看。
- **演示账号**：`chen_demo`、`li_demo`（`GateDemo123!`）；会话存 sessionStorage，12 真实小时到期。
- **构建选项**：默认关闭演示审批；显式 `VITE_GATE_DEMO_APPROVALS=true pnpm build:gate` 才开启；真实系统必须移除 Mock。
- **数据隔离**：业务键 `qinglan.gate.mock.v1`，与其他端独立；恢复不调用 `localStorage.clear()`；Web Locks 保护同源标签写入。
- **目录**：`src/core`（类型/校验/规则）、`src/mock`（样例）、`src/services`（异步存储边界）、`src/components`（列表组件）、`tests/`（单元 + Playwright）、`scripts/`（契约生成与校验）。
- **测试**：14 单元 + 8 浏览器；`pnpm check:gate-api` 校验契约结构。
- **未实现**：真实后端、跨端联动、设备控制、转派、地图/照片、部署。

### 4.5 演示控制端 `apps/demo`（端口 5178）

- **定位**：管理员切换运行、控制时间、注入事件、模拟到离场。
- **核心 API**：`POST /demo/clock`（paused、speed=1/5/30/60、time；向后跳创建分支）、`POST /demo/config`（demandScale=.5—1.5、botMax=0—2、announcementMinutes=1—60）、`POST /demo/bots`、`/demo/employees`、`/demo/alerts`、`/demo/orders/{id}/enter`、`/exit`。
- **场景**：内置六个场景（weekday / weekend / crowd / maintenance / oa / closing），由 `createRun(mode, scenario, time)` 创建回放/实时。
- **前端**：单文件 `App.vue`（Vue 3 + Vite），无独立路由。

### 4.6 管理员后台 `apps/admin`（端口 5179）

- **定位**：青岚山境后台管理；当前在线入口为 `App.vue` 直接接 8787，旧 Mock 仅作历史追溯。
- **登录**：`admin01/admin02`，密码 `123456`；公开样例账号 `admin_demo` / `AdminDemo123!` 仅登录页与文档出现。
- **路由（hash）**：`#/login`、`#/overview`、`#/content/scenic`、`/articles`（`/new`、`/:id/edit`）、`/pois`（`/:id/edit`）、`/notices`、`/orders`、`/booking/slots`、`/facilities`、`/inspections`、`/alerts`、`/users/visitors`、`/users/staff`、`/chat`、`/knowledge`、`/service-status`。
- **能力（本期范围）**：15 个业务模块；游客/员工拆分为独立页面；订单取消/改期与配额原子保存；全类别设施状态；卫生间分项暂停（§4.3）；检修计划到期去重；只读告警；用户禁用；聊天撤回/举报/禁言；知识只读；服务状态样例。

### 5.2 持久化与并发

- PostgreSQL 17，应用 + QA 同库（schema 隔离）。
- 后台进程持数据库单活动实例锁；业务写入使用事务 advisory lock；嵌套事务共用连接；提交后广播。
- 退出流程：停止时钟 → 取消 AI 流 → 等待事务 → 释放连接。
- 检查点：每个回放运行保存 `checkpoints/<businessTime>`，含运行状态与文档快照；修复了嵌套旧检查点膨胀导致 500 的问题。
- 测试：单元 + 接口 + Playwright；数据库测试使用独立 `scenic_test` + 临时 schema；`TEST_DATABASE_URL` 可覆盖。

### 5.3 运行与时钟

- `Runtime` 结构（`apps/server/src/platform/service.ts`）：`id, mode, scenario, businessTime, speed, paused, revision, configVersion, simulation, anchorReal, anchorBusiness, botsEnabled, overrides, alertCycles`。
- 实时 vs 回放：实时跟随墙钟；回放按 `anchorBusiness + (Date.now() - anchorReal) * speed` 计算目标业务时间。
- `tick()`：每秒检查当前运行；最多推 60 业务秒，10 秒步长调用 `simulation.step()`。
- 演示播种：`createRun(mode, scenario?, time?)`，回放默认暂停；`POST /demo/clock` 设 paused/speed/time；向后跳会自动创建分支。
- 场景：weekday、weekend、crowd、maintenance、oa、closing，每个含固定业务时刻。

### 5.4 仿真与客流

- `simulation.step()`：用确定性哈希种子 + 业务日期/时间生成入园需求、车辆/大巴批次、停车占用、索道排队、卫生间释放、天气、区域人数、告警；最多 320 个"代表游客点"用于地图可视化（不参与人数守恒）。
- `visitor-flow.ts`：公式模型把实际入园人数累计到分钟桶，按路线、速度档位、游览阶段计算占用核，按最大余数法分配为整数区域人数。
- 入园量：`arrivalPlan()` 按工作日/周末 + 固定权重 + 确定性噪声生成；17:00 停止入园；离园按路线时长公式。
- 复现：快照读取时重新生成代表点位置与轨迹；同一运行、同一业务时刻可复现。
- 速度：只影响业务时间流逝，不改变公式中的需求总量、路线权重与游览时长；`demandScale` 影响模拟入园需求，`botMax` 影响模拟游客聊天频率，不等同客流倍速。

### 5.5 设备与告警

- `devices.ts`：89 个模拟遥感设备快照；状态按运行 ID + 设备 ID + 5 业务分钟时间片确定：8% 离线、10% 异常、82% 在线；离线读数为 null，其余来自统一仿真。
- `detectAlerts()`：按点位容量计算负载率，超过阈值生成告警；恢复阈值 0.8；同轮持续异常不重复发告警。
- `createAlert()`：任务类型含 help、crowd、parking、cable、restroom、inspection、maintenance；自动按类别写游客公告或内部公告。

### 5.6 任务、OA、订单、聊天

- 任务：领取（start）→ 完成（complete，result 必填，无待审批 OA）；改派由管理员操作。
- OA：申请（taskId + expectedVersion + type + reason + needs）→ 撤回（仅待审批）→ 管理员 decision（approved/rejected + opinion）。
- 订单：kind=entry/parking；日期/slot/lotId/people；取消/改期带版本号；改期失败回滚；满员冲突 `SLOT_FULL`。
- 聊天：rooms/messages 分页；撤回正文不返回；言论审核独立文本试测（`POST /admin/moderation/check` 接受 `{messageId,expectedVersion}` 或 `{text}`，异步检测）。
- 知识：管理员发布文章/规则/资讯；问答走 `services/qa.ts` 检索 + LLM 生成；RAG 与会话管理仍待补齐。

## 6. 关键业务流程

### 6.1 客流仿真闭环

1. 演示控制端调 `POST /demo/clock` 设置 paused/speed/time（或选场景 + 时间）。
2. 服务端 `tick()` 计算目标业务时间，按 10 秒步长推进 `simulation.step()`。
3. `visitor-flow.ts` 用确定性随机 + 公式计算分钟桶入园、路线占用、区域人数；按最大余数法取整。
4. `devices.ts` 89 个遥感设备按 5 业务分钟时间片产出状态。
5. `detectAlerts()` 按容量阈值生成告警，写公告 + 任务。
6. 模拟员工（默认开启，30—60 业务秒领取，2—5 业务分钟反馈）领取并完成任务。
7. 业务到期公告标 expired，WS 通知各端重读快照。

### 6.2 预约闭环

1. 游客手机端查询 `GET /booking/slots` 看当日余量。
2. `POST /booking/orders` 创建订单（含 entry/parking）；幂等键 + version。
3. 演示控制端 `POST /demo/orders/{id}/enter` 模拟入园 → 服务端 `interactive()` 累计在园人数与停车占用。
4. 游览结束按公式离园；订单状态机推进。
5. 游客或管理员可取消/改期（版本校验；满员冲突 `SLOT_FULL`）。

### 6.3 任务与 OA 闭环

1. 仿真或人工触发 → `createAlert()` → 任务 pending + 公告。
2. 模拟员工或人工 `POST /tasks/{id}/start` 领取 → assigned。
3. 需要资源时 `POST /oa-requests`（待审批期间阻止完成）。
4. 管理员 `POST /admin/oa-requests/{id}/decision`。
5. 申请人或他人 `POST /tasks/{id}/complete`（result 必填，无待审批 OA）。
6. 归档到 `tasks/<id>.records[]`，含 actor、kind、text、at。

### 6.4 聊天与言论审核

1. 游客 `POST /chat/messages` → 持久化；模拟游客由 bot 配置生成（`botMax=0—2`）。
2. 管理员可对单条消息发起 `POST /admin/moderation/check`（messageId 或 text）；返回异步任务。
3. `GET /admin/moderation` 读取检测结果；记录含模型、规则版本、决定、理由。
4. 失败返回 retry + error，自动重试 + WS 推送刷新；言论违规由管理员 `POST /admin/messages/{id}/remove` 撤回。

### 6.5 AI 文字问答

1. 手机端 `services/qa.ts` 调用后端 `/api/v1/qa/*`。
2. 后端 `services/qa.ts` 检索 `knowledge.ts` 源 + 上下文，拼装 prompt 调 DeepSeek。
3. 流式响应通过 SSE 推回客户端；中断时 `messages.status` 标 interrupted 并写 journal。
4. 服务重启恢复中断：`UPDATE messages SET status='interrupted'`，记录 `qa/recovered-interruption` 事件。

## 14. 风险与注意事项

1. **不要把原型能力当已上线**：旧 Mock 描述、SQLite 路径、5174 简化版均已废弃；演示数据不能等同于生产数据。
2. **错误码不能回退为样例成功**：401/403/409/410 等必须显式提示；前端不得静默吞错。
3. **AI 密钥不得进入 `VITE_*`**：DeepSeek 配置只在服务端 `.env.local`；前端只读 `configured` 布尔。
4. **微信与公网部署仍是欠项**：演示完成 ≠ 验收完成；真机/相机/域名/穿透待办。
5. **跨端一致性靠 WS 广播 + 重新拉快照**：所有客户端不得缓存业务态做"自我推算"。
6. **数据库写入走事务 advisory lock**：测试必须用独立 `scenic_test` + 临时 schema，避免污染本地演示库。
7. **检查点嵌套**：2026-09-13 已修复嵌套副本膨胀 500，但新增代码仍需注意仅保留各时刻的运行与业务记录。
8. **二维码稳定 ID**：扫码域名与景点 ID 不绑定 runId，方便公网部署后链路稳定。
