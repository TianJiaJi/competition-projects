# 前线处置终端接口文档 V1.0

2026-09-13。**设计契约，真实业务后端尚未实现。** 当前页面只调用本地异步服务，不调用以下 HTTP 路径。机器契约：[frontline-api-v1.0.json](../../../docs/openapi/frontline-api-v1.0.json)。业务需求见 [前线功能需求](前线处置终端功能需求-V1.0.md)、[管理员 OA 增补需求](../../../docs/管理员OA审批增补需求-V1.0.md)。

## 1. 公共约定

基地址 `/api/v1`。成功 `{data,meta:{requestId,runId?}}`；失败 `{error:{code,message,fieldErrors?:[{field,message}],details?},meta}`。所有时间为含时区 ISO 8601；前端统一按上海时区展示，日期筛选包含起止当天。全局鉴权接口不使用运行头，业务请求必须带 `X-Run-Id`，失效运行返回 410 `RUN_EXPIRED`，不得回落默认运行。

真实版本采用服务端签发的 HttpOnly Cookie 会话；对外部署 Secure、SameSite=Lax，写操作校验 Origin/CSRF。登录成功设置会话 Cookie，退出删除并在服务端失效。现有 `/auth/*` 路径复用员工鉴权，专项 Session 投影补充 `employee` 与 `capabilities`；后端实施时需兼容管理员既有会话字段或显式适配，不直接替换旧响应。当前示例中的账号是公开 Mock 账号，不是生产凭证。

`frontline:read` 可查看当前运行全园任务及 OA；`frontline:handle` 可领取任务、在自己任务下创建 OA/结案、撤回本人未决 OA；管理员审批必须额外具有 `oa:approve`，并具有读取能力。不能信任前端隐藏按钮或用户提交的员工 ID。`scope=mine` 使用会话身份，不接受任意 actor 参数代替。

任务专用路径 `/frontline/tasks` 复用现有 OpsAlert 的字段语义，增加负责人、版本和处置时间，**不改变既有 `/ops/alerts` 的结构或只读行为**。未来园方和管理员通过后端投影读取相同事件与 records，前线不直接写其他端数据。

## 3. 类型与读取

### 3.1 任务 Task

沿用 `OpsAlert`：`id/anchorId/regionId/category/severity/status/title/location/reason/metric/startedAt/records/previousAlertId?`。

增加 `runId`、`version`（正整数）、`assignee`（`{id,name}` 或 null）、`handlingStartedAt`（时间或 null）、`completedAt`（时间或 null）。`startedAt` 始终表示事件发生时间。待处理负责人和处置时间为 null；处理中必须有负责人和开始时间；完成必须有完成时间。姓名为展示快照，权限关联必须使用 ID。

类别：`crowd/parking/cable/restroom/equipment/help/cleaning/inspection`；严重程度：`critical/important/reminder`；状态：`pending/processing/resolved`。records 每项 `{at,kind,actor,text}`，kind 为 `created/started/completed`，保持旧 OpsHandlingRecord 兼容。服务端审计须另保存操作者 ID；前线身份由 `assignee.id` 和 OA actor ID 关联，不按姓名做权限判断。

`listFrontlineTasks` 参数：`scope=current|mine|history`（默认 current）、`status/category/keyword/from/to/page/pageSize`。current 含 pending 和 processing；mine 仅当前负责人，含 processing 和 resolved；history 含 resolved。keyword 匹配标题、原因、位置。日期在 history 按完成日期，其余按发生日期。起止反向返回 400。

当前和本人排序：严重程度 critical→important→reminder、发生时间倒序、ID 升序。历史按完成时间倒序、ID 升序。分页默认 1/20，pageSize 1—50；响应 data 为 `{items,total,page,pageSize}`。无数据返回空 items 和 total=0，不能使用当前页数量伪装总数。

### 3.2 OARequest

`id/runId/taskId/taskTitle/type/reason/needs/status/applicant/createdAt/updatedAt/version/decision/records` 均必需。taskTitle 保存创建时标题快照；applicant 为 `{id,name}`。type 为 `reinforcement/cordon/supplies/other`；status 为 `pending/approved/rejected/withdrawn`。

decision 未审批或撤回时为 null；批准/驳回为 `{actor:{id,name},at,opinion}`。records 每条为 `{kind,at,actor:{id,name},text}`，kind 为 `submitted/approved/rejected/withdrawn`，按时间先后返回。终态后不允许编辑、删除、重开或再次审批。

`listOARequests` 参数：`scope=all|mine`、`status/type/taskId/applicantId/keyword/from/to/page/pageSize`。默认 all；mine 强制会话身份，可与其他筛选求交集，不能扩大权限。日期按申请时间上海日期；关键词匹配任务标题、原因和需求。按 createdAt 倒序、ID 升序。分页响应与任务一致。待审批数量由 `scope=mine&status=pending&pageSize=1` 的 total 得到。

## 4. 写入与事务

所有业务写请求携带 `Idempotency-Key`（8—128 字符）和正文 `expectedVersion`。幂等域为运行、员工、键；同键同请求返回首次业务结果，不重复添加记录。不同路径/目标/正文复用键返回 409 `IDEMPOTENCY_CONFLICT`。只缓存成功提交；超时重试复用同键，修改内容使用新键。后端先鉴权/校验运行，再查幂等结果，再校验业务状态和版本。

| 操作 | 正文 | 成功 data 与行为 |
| --- | --- | --- |
| 开始 | `{expectedVersion}`，任务版本 | Task；pending→processing，绑定当前员工，记录 started |
| 完成 | `{expectedVersion,result}`，任务版本 | Task；仅负责人、processing 且无 pending OA，记录 completed |
| 创建 OA | `{expectedVersion,type,reason,needs}`，任务版本 | `{request,task}`；创建 pending OA，关联任务版本递增 |
| 撤回 | `{expectedVersion}`，申请版本 | `{request,task}`；本人 pending→withdrawn，申请与任务版本递增 |
| 审批 | `{expectedVersion,decision,opinion}`，申请版本 | `{request,task}`；管理员 pending→approved/rejected，申请与任务版本递增 |

result/reason/needs/opinion 去除首尾空白后均为 1—500 Unicode 字符。负责人、申请人和审批人由会话产生，客户端不得指定。开始和完成版本每次加一；OA 创建时版本为一，后续终态操作加一。OA 变更不向旧任务 records 写入新 kind，避免破坏大屏兼容性。

完成任务必须与“查询是否存在待审批 OA”处于同一事务/锁内。OA 创建、审批或撤回需同时更新关联任务版本。两个员工领取、撤回与审批竞争、结案与新建 OA 竞争时只能合法提交的一方成功，其余返回冲突，不覆盖最终状态。

OA 批准/驳回/撤回只解除该申请的结案阻止；其他待审批仍阻止。批准不代表落实，任务仍为 processing；完成任务不恢复设施、不更改客流、不自动推进检修计划。

## 5. 错误与本地适配差异

| HTTP | code | 前端处理 |
| --- | --- | --- |
| 400 | VALIDATION_ERROR | 显示字段错误，保留输入 |
| 401 | AUTH_REQUIRED / AUTH_INVALID | 重新登录或显示账号密码错误 |
| 403 | FORBIDDEN | 无操作权限，保留只读入口 |
| 404 | NOT_FOUND | 对象不存在，返回列表 |
| 409 | VERSION_CONFLICT | 重新加载最新对象，不静默覆盖 |
| 409 | TASK_STATE_CONFLICT / OA_STATE_CONFLICT | 状态已改变，刷新详情 |
| 409 | OA_PENDING | 保持处理中，提示待审批申请 |
| 409 | IDEMPOTENCY_CONFLICT | 不能将同键用于不同操作 |
| 410 | RUN_EXPIRED | 停止旧运行操作，不回落默认数据 |
| 503 | SERVICE_UNAVAILABLE | 保留草稿，稍后重试 |

本地专用错误为 `MOCK_STORAGE_FAILED/MOCK_STORAGE_CONFLICT/MOCK_STORAGE_CORRUPT`；不作为 HTTP 错误返回。当前 GateError.fieldErrors 使用字典，未来 HTTP 适配层需把数组转换为字段字典。

本地 `load()` 返回整个 Database，UI 在完整集合上筛选，没有真实 HTTP 分页；接入时需要改为查询参数和列表页状态，不可只筛选后端第一页。写服务返回保存后的完整 Database，真实适配层需将 Task 或 Receipt 合并到缓存并重新读取受影响列表。Mock 成功重放返回最新本地快照；真实 HTTP 必须存储并重放首次操作响应，之后另行刷新。

Mock 本端 runId 固定 `run_gate_mock_v1`，不提供运行选择。初始化/重置建立相对当前时间的样例。业务键的全文比较和可用时 Web Locks 仅用于同源浏览器冲突保护，不能替代后端事务。模拟会话用 sessionStorage，真实实现禁止以该数据作为可信身份。

OA 记录由前线独立种子与操作产生，和管理员、大屏暂不互通；HTTP 路径都是后续实现目标。全局旧 OpenAPI 不被覆盖，本文及专项 JSON 作为前线/OA 的新交接基线。
