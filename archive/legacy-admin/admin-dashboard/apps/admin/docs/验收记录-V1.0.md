## 6. 延期项与后续接入点

本期为**精简可演示版**：15 个页面全部实现，业务规则全部可复查；以下能力按约定延期，均已在服务层或组件层预留结构。

| 延期项 | 原因 | 后续接入点 |
| --- | --- | --- |
| `?preview=1` 开发预览入口与 8 类注入场景（加载/空/失败/写入失败/响应超时/会话过期/存储损坏/卫生间释放前后） | 本期确认的精简口径 | `src/services/store.ts` 的 `configureRuntime({ storage })` 与各服务的 `ApiResult` 分支即为注入点；接入后只需新增 `core/storage.ts` 的 preview 命名空间 |
| 多标签冲突检测与重载提示 | 同上 | `writeStore` 已集中收口，可在此比较 revision 并提示重新加载 |
| 第二 runId 夹具与运行切换 UI | 同上 | `BusinessStore.runs` 已按 runId 分区，未知 runId 已有 `RUN_EXPIRED` 语义 |
| 24 篇资讯 / 30 条订单全量种子 | 精简为“足以演示每条规则”的规模（22 篇内容、17 条订单含 3 个背景批次） | 种子集中在 `src/mock/global-seed.ts`、`src/mock/run-seed.ts`，可直接扩充 |
| 连续操作 30 分钟的性能观察 | 需要长时间人工运行，未纳入本次自动化 | 可用 Playwright 长时运行脚本补充 |
| 真实 HTTP/WebSocket、跨端联动、人脸识别、设备控制、部署 | 需求文档明确不属于本期 | `src/services/**` 为唯一适配层，替换实现即可，页面不拼接 URL |
