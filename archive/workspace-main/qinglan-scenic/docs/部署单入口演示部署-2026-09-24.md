# 单入口公网演示部署

更新：2026-09-24

## 拓扑与现状

内网 node1 使用 Docker Compose 运行六个前端、一个后端、PostgreSQL 17 和 Caddy 网关。PostgreSQL 使用 `pg-data` 持久卷，已从迁移前快照恢复，迁移版本为 2；七个业务镜像均为 `172b8a3`。SakuraFrp 客户端与网关共享容器网络命名空间，将网关的 TLS 端口 `127.0.0.1:31101` 送入 TCP 隧道。宿主机只映射 `127.0.0.1:8080`，未占用现有 Kubernetes Ingress 的宿主机 `31101` 端口。

现有下载系统仍在原 Kubernetes Ingress 上，宿主机 `http://127.0.0.1:31101/` 返回 200。**不得删除或停用该系统，也不得把 Compose 网关映射到宿主机 31101。**

SakuraFrp `scenic_ingress` 已连接，公网中继为 `frp-put.com:33613`。该节点拒绝明文 HTTP，因此内网网关对隧道启用 Caddy 内部 CA 签发的 TLS。CA 数据保存在 `caddy-internal-data` 卷，香港 Caddy 使用 [scenic-root.crt](../infra/edge/hongkong/scenic-root.crt) 验证回源证书，SNI 固定为 `m.starhusk.com`，原始 Host 仍转发给内网网关。已通过中继验证六个站点首页和 `/api/v1/health/ready` 均返回 200。

香港主 VPS 的公网地址为 `43.161.218.64`。已从 node1 经现有备用 VPS 中转，用登记的 `.pem` 密钥登录；备用 VPS 只承担运维 SSH 中转，其原有服务未改动。香港主机已安装 Ubuntu 仓库的 Docker 与 Compose，配置指定的 Docker Hub 镜像源，并在 `/opt/scenic-hk-edge` 启动 Caddy。用户已将六个 A 记录改到该公网 IP，Caddy 已签发六个有效 HTTPS 证书。

## 公网验收

- `m`、`ops`、`visitor`、`admin`、`gate`、`demo` 六个域名的首页、静态 JS/CSS 和 `/api/v1/health/ready` 均返回 200，TLS 证书验证通过；就绪接口报告 PostgreSQL、迁移版本 2、AI 已配置。
- 六域名的 `/api/v1/runtime` 返回相同运行 ID 和修订。WebSocket 能接收 pong 与后续修订更新。
- 使用游客账号创建并取消一笔测试预约；使用员工和管理员账号完成一条新注入任务的领取、OA 申请与审批、任务结案。测试预约已取消，测试任务已结案。
- AI 问答经公网 HTTPS 返回 `text/event-stream`，首包约 512 毫秒，收到多段 `delta` 及最终 `done`。
- 上线库的管理员账号为 `admin01`、`admin02`，密码 `123456` 均已验证；不存在 `admin03`。这些弱口令只适合受控演示，长期公网使用前应改密。

## 运维边界

现有下载系统仍在 Kubernetes Ingress 的宿主机 31101 端口上，返回 200；不要删除、停用或占用它。HTTPS 入口与内网网关都使用 Compose 自动重启。内部 CA 私钥位于 node1 的 `caddy-internal-data` 卷，香港 Caddy 仅持有根证书；若该卷丢失，须重新分发新的根证书。

本轮不部署数据库备库或长期异地备份。单机故障可能丢失部署后的新增数据。
