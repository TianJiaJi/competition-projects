# 统一数据与仿真修复

## 根因

- 后端直接使用手机版裁剪点位，缺少全部安全设施、游客终端；前端只能显示未知。
- 索道队列只保存人数，任何队列未清空都会延长整类游客的离园时间。位置又按离园时间计算，游客被反复拉向出口。入口/出口停留过长，原模型的五等分停留也没有对应实际景点。
- 回放按真实时间差追赶，后台运行和停机时间也会累计；游客大屏另用本机日期时钟，可能白天显示“闭园、0人”。
- 仿真逐步查库，所有 GET 又加入写事务队列。后台推进会阻塞页面读取；启动排查时本机后端没有监听，前端代理报错。
- 园方端携带本地完整样例及 `preview` 切换，游客端存在 sample 开关，手机版生成资源内含一整份旧运营快照。手机还残留本地入园模拟和业务缓存恢复。管理员、前线源码保留旧本地数据库实现。
- 园方大屏在所有卫生间关闭时访问不存在的“最繁忙卫生间”名称，Vue 渲染中断，导致头部已更新而区域与地图保留旧画面。已补齐无开放卫生间的空状态。
- 管理员强制刷新可能复用写入前已发出的读取，导致保存成功后找不到刚创建的记录。前线分开读取任务和 OA，并用 `Date.now()` 伪造数据版本。

## 修复边界

六个前端不再生成运营样例或在失败时回退至样例。测试专用数据放在 `tests/fixtures`、各应用的 `tests/fixtures` 和 `packages/client/testing`，不进入应用运行入口。静态地图、设施目录、道路和容量定义仍是正常业务配置。

后端仿真作为演示环境唯一客流与遥测来源保留；演示预约仅通过后端命令创建，可重复执行且不自动入园。没有删除已有真实订单或历史运行。

## 行为

- 安全设施从完整静态目录补齐；已有暂停运行的读接口同样提供安全设施状态。
- 索道业务队列不再拖延其他游客离园；三维游客沿后端轨迹插值并使用道路表面高度。后续“重构人流生成逻辑”任务在同一工作区进一步将空间分布升级为分钟入园桶、固定路线和分段时间的公式模型，整体验证以当前模型为准。
- 新建、切换、服务重启后的回放暂停；只推进选中运行，继续后才按倍速推进。后台每批最多推进一分钟业务时间，时钟切换保留余量。
- 游客与园方屏显示后端业务时间。停止入园但尚有人时标记清园中；清园完成后人数为零、区域关闭。
- GET 使用 PostgreSQL 一致性只读事务；前线任务与 OA 一次读取同一版本。总人数与区域合计不符或快照时间不同于运行时间时，后端拒绝输出不一致快照。
- 非法 JSON/数组/空值请求返回 400，超大请求返回 413。数据库连接异常返回 503。
- 手机配额读取期间显示加载，未知配额不冒充零；选择有效时段后才能提交，已结束时段由后端标记不可预约。

## 验证入口

`pnpm test`；`pnpm exec playwright test --config playwright.platform.config.ts`；工作区、后端、手机和前线类型检查；各端构建。

新增回归覆盖客群索道隔离、安全设施、午夜零值、回放重启/倍速、预约幂等补充、读取不被写事务阻塞、输入错误状态码、跨端总数与区域守恒，以及清园后的区域归零和禁用 preview。

园方与游客的旧 UI 用例已改为测试专用 HTTP 拦截，不再依赖生产页面的 sample/preview/alwaysOpen 开关。跨端一致性用例验证清园、重新开园时不刷新页面即可同步，并断言没有页面异常。
