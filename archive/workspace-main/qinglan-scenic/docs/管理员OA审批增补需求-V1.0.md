# 管理员 OA 审批增补需求 V1.0

2026-09-13。本文件为后续管理员开发任务书；本轮不修改管理员应用代码。前线功能及接口依据见 [前线接口文档](../apps/gate/docs/前线处置终端接口文档-V1.0.md)。

## 1. 入口和权限

在管理员导航中增加“OA 审批”，建议路由 `#/oa`；沿用现有后台视觉与列表/详情组件，不另建视觉语言。菜单是否显示由 `oa:approve` 能力控制；普通前线员工不得调用审批接口，后端必须检查该能力。

管理员原有告警页面继续只读。告警详情新增关联 OA 的只读入口，不增加开始/完成、指派、消除告警等操作。

## 2. 列表与详情

默认显示当前运行待审批申请。筛选包括状态、类型、申请人 ID、关联任务 ID、关键词和申请日期范围。状态为待审批/已批准/已驳回/已撤回；类型为增援/封锁现场/物资/其他。先完整筛选再分页，每页默认 20、最多 50 条；按申请时间倒序、相同时间按 ID 排序。

列表列：申请类型、关联任务、位置、申请人、申请时间、状态；位置由关联任务读取，不用申请正文推断。点击后打开详情：完整原因、需求、任务信息与负责人、申请记录和审批结果。长文本自然换行，不以省略号隐藏审批必需信息。

可从关联任务进入已有只读告警详情。不存在、已失效运行、无权限、读取失败都有可重试或返回入口，不展示空白详情。

## 3. 审批操作

只允许待审批申请点击批准或驳回。审批意见必填，去除首尾空白后 1—500 字；批准时说明安排，驳回时说明原因。显示决定与意见确认后提交；请求中禁用重复操作，成功后以服务端结果刷新列表和详情，失败保留意见。

身份由服务端会话确定，不接受前端提交审批人 ID。审批记录保存操作人 ID、姓名快照、时间、决定和意见。审批终态不可修改、重开或删除；前线申请人可撤回未决申请。撤回与审批竞争时，只允许第一个事务成功，另一方收到 `VERSION_CONFLICT` 或 `OA_STATE_CONFLICT` 并重新加载详情。

任务状态与 OA 状态分开：批准/驳回结束申请，但不自动完成事件。前线任务下所有待审批 OA 均结束后才允许提交完成结果；封锁、增援和物资批准均不自动控制设施或分派人员。本期无“已落实”状态。

## 4. 接口与一致性

使用 `GET /api/v1/oa-requests`、`GET /api/v1/oa-requests/{oaId}` 查询，`POST /api/v1/admin/oa-requests/{oaId}/decision` 审批。审批请求携带 `X-Run-Id`、`Idempotency-Key`，正文含申请 `expectedVersion`、`decision` 和 `opinion`。

审批与申请记录、关联任务版本更新必须同事务提交；成功返回最新申请和任务。读取可与前线共享契约，审批能力独立授权。接口字段、响应和错误以 [专项 OpenAPI](openapi/frontline-api-v1.0.json) 为准。

不在正式管理员页面调用前线开发环境的 `decideDemo` 或读取其 localStorage；真实跨端同步待统一后端实现。

## 5. 后续验收

- 普通员工审批返回 403；具备能力的管理员可读、批准和驳回。
- 空白/超长意见、重复点击、网络失败保留输入；同幂等键不产生重复记录。
- 两位管理员竞争、前线撤回竞争、旧版本提交不得覆盖已结束申请。
- 已审批与已撤回记录只读；审批不会改变现场监测、设施状态或自动结案。
- 审批成功后，前线读取到意见与审批记录；最后一条待审批结束后解除结案阻止。
- 后台既有告警页、设施页和权限行为不回归；验证加载、空数据、失效运行及跨页筛选。
