## 一、目标与已确认边界

用总量公式、时间分布、区域权重和少量队列变量，生成一个随真实上海时间变化的虚构自然景区。数据应表现出开园到达高峰、周末增量、午间热点、局部设施拥挤、晚间离园及夜间闭园。

最终以“数字能对应、忙闲变化可信、现场操作能联动”为目标，不建立逐人行为引擎，不模拟物理碰撞、逐人厕位行为、复杂排队调度或生产级基础设施。

### 1.1 前端需要的数据

| 类别 | 对外展示 | 不要求展示 |
|---|---|---|
| 客流 | 今日累计入园、实时在园、区域人数、忙闲等级 | 每位背景游客的精确位置和身体属性 |
| 预约 | 当日有效预约人数、核销人数、现场预约余量 | 复杂实名同行人和审批流程 |
| 停车 | 各场容量、占用、余位、忙闲等级 | 每个车位的车辆轨迹 |
| 卫生间 | 位置、开放状态、忙闲、男女坐蹲位、小便位、无障碍间的总数／占用／可用／排队 | 逐人行为、传感器接入、精确等待预测 |
| 索道 | 方向、开放状态、忙闲、排队人数、预计等待、在途及总容量 | 逐人轨迹、真实传感器、故障仿真 |
| 环境 | 天气、温湿度、风、AQI、负氧离子 | 与真实传感器一致的测量结果 |
| 预计 | 今日预计总量、未来一小时客流趋势 | 已经知道未来随机结果的“准确预测” |

卫生间分项与索道队列已按 §6.2、§6.3 恢复展示；演示预计等待不代表现场实测。关闭状态优先于忙闲状态，不能用“空闲”表示已经关闭的设施。

### 1.2 确认规则与校准参数

- **已确认规则**：上海实时时钟；10 秒步长；今天与昨天；工作日／周末；免费分时预约；环线与两条短线；三座停车场；索道正常运营；关键数字加忙闲等级；现场扫码真实联动。
- **初始校准参数**：区域权重、区域参考承载量、游览时长概率、服务能力、分流强度、环境振幅等。本文给出完整起始值，作为首次实现及数值校验的默认输入。
- 修改校准参数需更新 `config_version`，同一版本内不能因刷新而改变。初始值不是行业标准，也不声称已经通过完整联动仿真。
- 不增加节假日、调休、季节、天气影响客流、索道故障或工作人员夜间活动模型。

## 二、统一时间、随机数与数值约定

### 2.1 时间参数

| 参数 | 初始值／规则 | 类型 |
|---|---|---|
| `timezone` | `Asia/Shanghai` | 已确认 |
| `step_seconds` | 10 秒；一天 8,640 步 | 已确认 |
| `open_time` | 08:00 | 已确认 |
| `last_entry_time` | 17:00，不含此时刻 | 已确认 |
| `close_time` | 18:00 开始闭园 | 已确认 |
| `visitor_clear_target` | 约 19:00 | 已确认目标 |
| `parking_clear_target` | 约 19:30 | 已确认目标 |
| `preopening_arrival_start` | 07:30 | 已确认 |
| `full_route_cutoff` | 14:00 起不再选择完整长线 | 校准初值 |
| `medium_route_cutoff` | 15:30 起只选入口短线 | 校准初值 |
| `parking_open_time` | 07:00 | 校准初值 |
| `cable_up_hours` | 08:00—17:00 | 校准初值 |
| `cable_down_hours` | 08:00—18:30 | 校准初值 |
| `forecast_refresh` | 每分钟；输出未来 10、20、30、40、50、60 分钟 | 初始配置 |
| `history` | 今天与昨天；预约创建记录可追溯前一天 | 已确认 |

以服务器时间确定业务日期及步号：`step_index = floor(距上海当日零点的秒数 / 10)`。时间戳存储为带时区含义的标准时间；营业规则和日期分组使用上海日期，不使用 UTC 日期截断代替。

前端每轮接收 `business_time` 和版本号；浏览器时间仅用于动画插值，不独立决定开闭园、预约过期或状态推进。流量按区间 `[本步开始, 下步开始)` 归属，跨零点只切换当日累计，不清除真实存量。

### 2.2 随机与取整

统一定义 `U(key)` 为 `[0,1)` 内的确定性伪随机值，键包含 `model_version、config_version、业务日期、指标类别、时间块或记录编号`。相同键必须产生相同结果。

建议可复现定义：对 UTF-8 键取 SHA-256，以前 4 字节的大端无符号整数除以 `2^32` 得到 `U`。不依赖语言内置的随机哈希，也不在每次读取接口时重新抽样。

连续扰动按固定时间锚点生成，在相邻锚点间线性插值。客流锚点每 5 分钟一个，环境锚点每 30 分钟一个。插值后的扰动仍处于指定范围内。

人数分配使用最大余数法：先向下取整，再按小数部分从大到小补足，平局按固定 ID 排序。由此保证区域、时间桶和来源分配之和严格等于总人数。

运力等小数速率保留余量：例如 20 人/分钟等于每步 `10/3` 人，三步应分配为 3、3、4，而不是每步都向下取整为 3。容量信用最多保留一计算步的未用能力，不能把夜间空闲运力积攒到早晨。

### 2.3 两个运行空间

实时模式 `mode=realtime` 跟随上海时间；回放模式 `mode=replay` 使用独立 `run_id`、时钟、快照和现场订单。回放可选日期、倍速及跳时，不写入实时历史。

中途启动先恢复兼容快照，再补算至当前业务时间。没有快照时，从该日所需的种子数据生成今天状态；今天的提前预约可直接生成前一天的创建时间，无需重建整年历史。

若存在已保存的现场操作，则从包含这些操作的快照继续，或按时间和稳定顺序重放这些操作，不能用纯背景重算覆盖。时间没有向前推进时不重复执行同一已提交计算步。

## 四、到达、预约与入口公式

### 4.1 分时到达

`D = round(base_demand × [0.9 + 0.2 × U(date,demand)])`。

| 时段 | 权重 |
|---|---:|
| 08:00—09:00 | 22% |
| 09:00—10:00 | 20% |
| 10:00—11:00 | 13% |
| 11:00—12:00 | 8% |
| 12:00—13:00 | 5% |
| 13:00—14:00 | 13% |
| 14:00—15:00 | 9% |
| 15:00—16:00 | 6% |
| 16:00—17:00 | 4% |

先将小时权重转为每步基础权重，用对称短窗平滑小时边界；整体高峰偏移取 `20×U−10` 分钟，越出营业到达区间的权重回收至最近有效边界，再乘连续扰动 `1 + noise(t)`，其中 `noise(t)∈[-0.15,0.15]`。

从调整后的首小时权重中提取约 10% 分配到 07:30—08:00。最终在全部有效时间桶上归一化：

`a[t] = raw_weight[t] / Σ raw_weight[t]`

`到达计划人数[t] = AllocateInteger(D, a)[t]`

此处的到达计划先表示游客到达景区外围；停车、上下客和步行延迟决定实际到入口的时间。公布的高峰权重是基础形状，实际入园小时占比不要求与该表完全相同。

17:00 前无法完成入园的游客计为到达未入园；不得为了凑足 D 而突破闭园或容量规则。D 是需求基准，不是必须兑现的入园数。

### 4.2 预约记录和创建时间

`B = ceil(D / [(1−0.03)×(1−0.04)])`。

背景记录只需 `id、source、visit_date、slot、people、created_at、cancel_at、planned_arrival_at、status、checkin_at`。可一条记录表示一批人数，不要求一人一条账号。

先分配取消人数，再在剩余人数中分配爽约，状态互斥。因整数产生的实际到达量与 D 的尾差，通过不超过少量人数的类别余量分配修正，不能每天系统性少算取消及爽约。

提前预约约 70% 在前一天生成，创建时间初值覆盖 08:00—24:00，18:00—22:00 较集中；当天预约约 30%，需在计划到达前产生。取消发生在创建之后、实际核销之前；爽约记录没有实际到达时间。

小比例提前／迟到通过预约时段与实际到达时段错开表达。首末时段没有合法相邻时段时回归本时段，不要求每小时精确满足相同比例。背景不模拟改期。

### 4.3 预约容量与指标口径

背景时段配额按该时段计划生成的原始预约人数配置；现场配额独立：

`R[date,slot] = 20 + floor(21 × U(date,slot,interactive_quota))`

其取值含 20 和 40，每个日期时段固定。现场可约未来一天和当天未结束时段，17:00 后不能新建当天入园预约；核销仍按当日通行窗口校验。

`现场余量 = R − Σ(该时段有效现场订单人数)`。

有效预约含已核销订单，核销后不释放名额。取消可释放，改期需要原时段释放与新时段占用同时成功。17:00 时仍未核销的当天订单过期；已到但未核销与未到均记录原因，不把限流导致的未入园全部称为爽约。

建议展示两项独立指标：

- 今日有效预约人数：当天已创建且未取消未失效，包含已核销。
- 今日预约核销率：累计核销人数／当天已创建且未取消的预约人数；分母含最终未到失效，避免17:00一过分母缩小、核销率虚升。分母为0时显示“—”。

### 4.4 入口队列与全园限流

设 `Bpark` 为背景在园人数，`Ipark` 为现场在园人数，`C=10000`，`H=100`。

`背景可接待余量 = max(0, min(C−Bpark−Ipark, C−H−Bpark))`

两入口依队列需求分配同一份余量，不能各自使用一遍全园余量。分配采用比例分配和整数余量补足，任一入口未用完的通行能力可让另一入口使用剩余全园名额，但不增加另一入口自身运力。

`背景入园[g] = min(Q[g]+到达[g], 本步可用通行能力[g], 分配到的全园余量[g])`

现场核销在授权及订单校验后立即生效，仍受 C 限制；消耗对应入口本步能力，若整单造成短时超过背景步长配额，在后续背景能力中扣回，不延迟已经确认的核销提示。

入口间转移只作用于新到或明确转移出的背景需求。用 `等待分钟≈Q/每分钟运力` 估计，另一入口“等待＋4分钟步行”至少少 3 分钟时，将最多 30% 的候选需求转过去，并延迟 4 分钟到达。比较使用上一步状态，避免同一步反复互相转移。

`Q_next[g] = Q[g]+到达[g]+转入[g]−入园[g]−转出[g]`

17:00 不再核销，剩余队列及尚在前往入口的批次转入“到达未入园／返程”，不计入在园。若来自停车或大巴，要继续生成其返程车辆事件。

## 五、在园、区域与离园

### 5.1 只维护批次和时间分布

每个实际入园时间桶保留来源、人数、路线类别及离园计划。无需记录背景个体位置。现场订单可保留自己的模板时间轴，以便扫码后能看到独立的游览进度。

正常入园批次的游览时长起始分布如下，速度、观景、午间休息及常见索道等待已经包含在内：

| 路线类别 | 距离基线 | 时长及概率 | 选择比例初值 |
|---|---:|---|---:|
| 完整长线 | 6公里 | 180／240／300分钟，25%／50%／25% | 60% |
| 中线 | 4公里 | 120／165／210分钟，25%／50%／25% | 30% |
| 入口短线 | 1.6公里 | 35／50／65分钟，25%／50%／25% | 10% |

14:00后不再选择长线，剩余中线与短线按原比例归一化；15:30后全部选择短线。这里的路线类别包含步行及索道模板的组合，不再另加一次“索道运行＋步速＋休息”到总时长上。

为避免极少数计划超出清场目标，创建离园计划时只保留不晚于19:00的合法时间桶并归一化，不在19:00删除仍在园的人。当前边界下，14:00前长线最长5小时、15:30前中线最长3.5小时、17:00前短线最长65分钟，满足基础清场目标。

`计划离园[t] = Σ_s 入园人数[s] × 游览时长分布_s[t−s]`

将每个批次一次性整数分配到未来桶，不逐步重复取整。实际离园从计划桶兑现，不能超过该来源尚在园的人数。若存在尚未完成的必要环节，延期而不丢弃离园份额；清场目标是参数校准目标，不是强制清零指令。

定义平滑窗口 `G(t;a,b,c,d)`：a之前为0，a到b线性升至1，b到c保持1，c到d降到0，其后为0。日内修正初值：

`w_i = base_i × time_factor_i × guide_factor_i × local_noise_i`

局部扰动初值±5%，仍由日期种子和连续锚点生成。

`region_total[i] = region_background[i] + region_interactive[i]`

### 5.3 引导效果

园方引导只修改 `guide_factor` 的目标值；默认5分钟线性过渡，并对完整权重重新归一化。源区域减少的份额先通过通行区过渡，再分配到目的区域，避免两点之间的人数同时跳变。

只在新生成的背景分配中生效，不重写已经保存的历史人数。现场订单的暂停或路线切换单独处理，不被背景引导覆盖。

## 六、停车、厕所及索道

### 6.1 停车到达与返程

先从每日游客到达计划按40%／20%／40%拆分人数，再转换为小客车人数包、大巴人数包及其他来源；不能额外叠加一批大巴游客。

小客车首选P1／P2／P3的比例初值为60%／25%／15%。每场新到车辆先加入等候，按照余位和进场能力进入；满场时转移到有余位的其他停车场，全部满时继续场外等待，不模拟放弃游览。

`free[p] = max(0, capacity[p]−occupied[p])`

`entered[p] = min(可到场车辆[p], free[p], 本步进场能力[p])`

`occupied_next[p] = occupied[p] + entered[p] − exited[p]`

出场先释放车位，本步进场可使用已释放的空间；所有场共用车辆归属，转场者不能同时进入两个场。乘客只有在车辆进场并经过步行延迟后，才成为入口到达人数。

背景停车预约约70%，临停约30%。停车预约记录人数单位为辆，到场才占实体车位。现场停车名额保护不承诺满场时强制进入，满场应显示可替代停车场或等候状态。

返程按照同一车辆人数包的游览结束时间，加上对应停车场步行时间和5分钟上车时间生成出场计划。对原定入园但最终未入园的人数包，按实际返程决定出场，不让车辆永久占位。

大巴下客到场和接客到场是两个车次，共用6个泊位。登离泊位按3／5分钟释放，车辆驶离后不占小客车位。第二次到场不再产生入园游客。未完成接客的少量尾部需求保留至完成，不用19:30定时清除记录。

#### 6.2.1 前端归档演示算法

本轮只恢复前端样例数据，生产服务和传感器仍未实施。`packages/client/src/restroom-sample.ts` 用分钟释放桶计算聚合人数，不给每名游客或每个坑位建立对象；不会把这些附加统计重复加入全园人数。相同时间和区域数据生成相同结果，刷新不重新随机。

- 需求沿用下方覆盖表：`每分钟需求＝覆盖人数×0.25÷60×午间系数`。
- 本轮补充的可校准初值：女厕需求占 49%，男厕合计占 49%，无障碍需求占 2%；男厕再按坐蹲位与小便位容量比例分配。这些比例是本次补全的演示参数，不冒充历史记录中的已定值。

- 9:00、15:00 开始分批清洁；T1—T6 依次错开 10 分钟、持续 10 分钟。每个分项暂停约 10% 容量且至少 1 个，不提前清退正在使用者，释放后再停用。
- 页面忙闲取四个分项中最大的 `(使用中＋排队)÷总数`：小于 0.65 为空闲，小于 0.90 为适中，其余拥堵。关闭和维修优先显示不可用，可用数为 0。

#### 6.3.2 本轮前端演示计算

`packages/client/src/cable-sample.ts` 每 10 秒推进一次聚合队列，以 24 秒班次边界累计登乘；单次最多 8 人，8 分钟后从在途桶释放。上下行独立满足 `新队列＝旧队列＋到达−登乘`，`新在途＝旧在途＋登乘−到站`。

新增可校准需求初值：上行覆盖人数 `Z0＋0.35×Z8`，每人每小时需求系数 1.4；下行覆盖人数 `Z4＋0.35×Z3＋0.35×Z7`，需求系数 0.6。需求/分钟＝覆盖人数×需求系数÷60×时段因子。时段因子为 `0.6＋0.9×G`，上行 G(08:00,08:30,09:00,10:00)，下行 G(13:00,14:00,15:00,17:00)，G 为线性爬升、平台、线性下降的梯形函数。小数到达量累积后取整，不逐帧随机。

预计等待＝下一班剩余分钟＋`floor(队列人数/8)×0.4`，保留一位小数。等待小于 5 分钟为空闲，5—不足 10 分钟为适中，10 分钟及以上为拥堵；关闭和未知优先于忙闲。样例使用当前统一区域快照和确定的时间计算，不代表服务端已维护真实历史队列；真实接入缺失字段显示未知。

`alwaysOpen=1` 在实际营业时间外使用演示 12 时加当前分钟和秒数计算，页面时钟仍显示上海真实时间。原有后台规划的来源延迟模型保留在下节，未来服务端接入时可替换到达项，容量和守恒口径保持不变。

#### 6.3.3 后台数值规划中的来源延迟


上行需求由符合路线时间的实际入园人数延迟5分钟产生；上行初值30%／35%。下行需求从另10%的实际入园份额按90／120／150分钟延迟分配，上下行选择份额互斥。15:30后入园批次仅短游，不产生新增索道需求。

`up_demand[t] = eligible_entry[t−5min] × up_share`

`down_demand[t] = Σ eligible_entry[s] × down_share × climb_distribution[t−s]`

分配时即作人数守恒取整，不能重复从同一批人产生多个方向的需求。离园分布已包含常规索道使用，只作一次影响；持续超出常规等候时可推迟对应批次的离园份额，不能把仍在候乘或在途的人提前算作离园。

当上一轮内部等待估计 `W=Q/rate` 超过10分钟，上行新需求改走步道的比例为 `min(0.4, 0.02×(W−10))`。下行采用相同规则改步行返程，已在队列内的人不反复退队。改走步道的人仍在园，不作为新增人口。

`boarded = min(Q+accepted_demand, capacity_this_step)`

`Q_next = Q + accepted_demand − boarded`

在途量按登乘后8分钟到站释放，仅作为在园人数的子集；不能加在区域人数合计之外。人数已经在全园及区域中统计，索道负载只提供运营解释。

索道仅正常营业。关门前停止新增候乘需求，为已有队列留出消化时间。基准配置应验证其在营业结束前消化；若参数使队列尚未清空，不强行置零，保留“收尾中”并将其作为参数校准失败提示，不扩展故障剧情。

## 七、等级、预警、环境与预计

### 7.1 等级阈值

| 对象 | 指标 | 空闲 | 适中 | 拥堵 | 预警恢复阈值 |
|---|---|---|---|---|---|
| 全园 | 在园／10,000 | <0.60 | 0.60—<0.85 | ≥0.85 | <0.75 |
| 区域 | 人数／区域参考承载量 | <0.60 | 0.60—<0.85 | ≥0.85 | <0.75 |
| 厕所 | 需求／等效能力 | <0.65 | 0.65—<0.90 | ≥0.90 | <0.80 |
| 索道 | §6.3.2 预计等待 | <5分钟 | 5—<10分钟 | ≥10分钟 | <5分钟 |
| 停车 | 占用／有效容量 | <0.70 | 0.70—<0.90 | ≥0.90 | <0.80 |

索道预计等待同时用于游客端展示与等级换算；卫生间前端分项忙闲按 §6.2.1 的资源占用规则计算。所有等级均为仿真阈值，不标作行业安全标准。忙闲色条与全园硬限流是两件事：全园拥堵并不等于已经达到10,000人的硬上限。

每步先计算原始指标，再以60秒时间常数平滑：`smooth_next = smooth + α×(raw−smooth)`，`α=1−exp(−10/60)`。数值人数保持真实整数；平滑用于等级和图形，不改写人数账本。

连续12个10秒步超拥堵阈值形成运营预警；前线反馈开始处理及完成，人工完成后关闭本次事件，不改写实际负载。同轮持续异常不重复触发；连续12步低于恢复阈值视为本轮异常结束，之后再次达到触发条件才生成新事件。指标回落本身不自动结案。设施关闭显示真实关闭原因，不冒充“运营改善”。定期检修按周期创建独立待办，设施可用性独立于检修待办状态。

### 7.2 环境公式

环境独立计算，绝不修改入园需求、速度、路线或索道状态。以下是展示数据，非真实传感器或气象模型。

令h为上海时间的小数小时，日温度低值 `L=16+日偏差`，高值 `H=27+日偏差`，日偏差目标值为日期种子确定的±1.5℃。00:00—06:00用半余弦过渡从前一天偏差切到当天偏差，06:00后保持当天值；跨日扰动锚点使用同一个绝对时间键，避免午夜换日期时环境数值突然跳变。

- 06:00—14:00：`T0=L+(H−L)×[1−cos(π×(h−6)/8)]/2`。
- 其余时间将h转换到14—30小时区间：`T0=H−(H−L)×[1−cos(π×(h−14)/16)]/2`。
- `temperature = clamp(T0−1.5×rain + noise(±0.4), 10, 32)`，单位℃。
- `humidity = clamp(80−1.4×(temperature−16)+8×rain+noise(±3),45,98)`，单位%。
- `wind_speed = clamp(1.8+0.8×G(08:00,12:00,15:00,19:00)+noise(±0.5),0.2,6)`，单位m/s。
- `aqi = round(clamp(38+5×sin(2π×(h−8)/24)+noise(±4),10,80))`。
- `negative_ions = round(clamp(2600+8×(humidity−70)+200×rain+noise(±100),1000,5000))`，单位个/cm³。

天气日类型按日期种子生成：晴40%、多云40%、小雨20%。小雨日用 `rain=G(11:00,12:00,13:00,14:00)` 平滑表示雨段，其余日期rain=0；只用于环境字段，前端天气名称随雨段变化。风向从8个方向按日期种子选定，日内保持稳定，不增加风场模型。

### 7.3 预计数据与实际隔离

实际历史按已发生事件和快照生成。预测独立字段保存，不写回背景模型历史，也不调用生成器未来的随机序列。

今日预计先使用工作日／周末基础曲线。令 `F(t)` 为无随机基准到达曲线截至当前的累计比例，`O(t)` 为已经观察到的外围到达人数：

- F<0.1时，不用少量早场样本放大全天，修正系数k取1。
- F≥0.1时：`k=clamp(O/(base_demand×F),0.8,1.2)`。
- 当天需求估计为 `0.7×base_demand+0.3×base_demand×k`，再结合已创建、未取消且计划到达时间在未来的预约进行剩余需求修正；不使用尚未发生的取消／爽约抽签结果。

剩余需求用下列轻量公式合并，不重复相加两套预计：

- `R_known = 已创建、未取消且尚未到达的当日预约人数 × 0.96`，包括可能晚到的有效预约；已到外围、停车或入口队列的人不再列入。
- `R_model = 当天需求估计 × (1−F(t))`。
- `R_uncreated = max(0, R_model−R_known)`；`R_remaining = R_known+R_uncreated`。

这是用已知预约给剩余需求提供下限的简化预测，不是精确预约转化模型。已知需求按预计到达时间分配，已超过计划时间的按剩余开放时间分配；未创建部分按剩余基准曲线分配。当前外围、停车和入口队列保留在预测起始状态中，不重复生成。

今日预计入园人数为“已实际核销＋剩余时段可接待需求估计”，需考虑入口运力和全园限流，不保证等于D。17:00后停止预测新增入园，今日预计收敛到实际核销累计。

未来一小时复制当前必要的聚合状态，按平均到达、离园计划、当前引导及限流规则推进360步；不带未来随机扰动，不凭空预测新的后台操作。输出每10分钟一次的全园与区域预计人数，区域预计合计与预计在园一致。

## 八、更新顺序、持久化与现场联动

### 8.1 每步计算顺序

1. 固定 `run_id、business_time、step_index`，读取已生效配置和现场事件；处理本步预约创建、取消及过期。
2. 兑现到期的离园、车辆出场、泊位释放、索道到站及转移到达，释放相应容量。
3. 产生本步外围到达需求，分配交通方式，处理停车／上下客；将乘客投入未来的入口到达桶。
4. 更新入口队列与转移，读取一次全园可接待余量，分配两入口核销，生成实际入园记录与离园计划。
5. 更新索道需求和登乘；必要的超时延迟反馈到相关离园份额，保持候乘者不被提前离园。
6. 汇总两种来源在园人数；分配区域，再计算厕所、停车和索道负载、等级及持续预警。
7. 计算环境，保存本步状态和计数器，递增revision，推送快照；每分钟生成一次独立预测。

同一步产生且需零延迟执行的事件只执行一次，其余进入明确的未来桶。阶段之间使用同一运行状态，不能让多个前端各自推进。每步校验硬约束，发现负数或容量超限时报告计算异常，不通过静默截断掩盖原因。

### 8.2 现场扫码

入园记录以请求编号和订单状态防重复。现场核销在服务端确认后立即增加 `checked_in_today` 和 `in_park_interactive`，将该订单人数放入入口区域并推送；10秒背景步长不能成为核销提示的等待时间。

背景只更新 `background` 来源；现场批次保存 `order_id、people、entry_at、route_id、timeline、paused、exit_at`。暂停和换线仅调整该批次的模板时间轴，不重复入园，离园后扣减一次。

暂停不能绕过闭园规则：进入闭园返程阶段后恢复返程时间轴，不再无限期停留。正常实时流程遵守开放时间；夜间想演示入园，应使用独立回放模式。

全园限流对现场同样生效。保留100人空间是提高现场成功率的背景保护，不是无条件突破容量的凭证。停车预约和停车核销分别处理，不自动把车辆进场当作乘客入园。

### 8.3 存储与前端接口

继续使用单个Node.js服务、SQLite、WebSocket。SQLite保存参数版本、简化订单、现场操作、最新完整聚合快照及分钟历史；每步在内存推进，关键操作立即保存，常规快照每分钟保存。重启允许补算最近未保存的背景步，不丢弃已确认现场操作。

最小只读输出分为：公共景区快照、园方运营快照、今天／昨天历史、独立预测。游客接口不返回联系人、订单明细、内部队列或工作人员记录。现场命令包括预约、取消、改期、核销、路线控制、离园和允许的引导操作。

快照携带 `mode、run_id、business_time、revision、generated_at`。客户端忽略旧版本；断线重连拉取完整快照和必要近期记录，不实现复杂增量重放。更换run_id时清除旧运行缓存。

数据已补算不等于前端可查看未来实际：实时历史查询只能到当前上海时间。昨天可展示完整日线，今天未发生部分为空或作为独立预测展示。

## 九、四组可复核算例

以下是固定输入下的算例，用于检查公式和单位，不是声称完整模型已经校准通过。为便于复核，示例关闭随机扰动，除特别说明外使用本文件初值。

### 9.1 工作日预约与开园

取D=10,000：

- `B=ceil(10000/(0.97×0.96))=10,739`人原始预约。
- 取消人数取322，余10,417；爽约取417，预计到达10,000。
- 首小时基础需求2,200人，其中220人提前到07:30—08:00，首小时营业后剩1,980人。

取开园前两入口分别已有176、44人等待。08:00第一个10秒桶实际到入口6人，分配主入口5、辅助1人：

| 项目 | 主入口 | 辅助入口 | 合计 |
|---|---:|---:|---:|
| 原等候 | 176 | 44 | 220 |
| 新到 | 5 | 1 | 6 |
| 本步核销 | 10 | 5 | 15 |
| 剩余等候 | 171 | 40 | 211 |

在没有原在园游客时，在园增加15人。`220+6=15+211`，门外等候与园内人数没有重复。例子中的门口到达是停车和步行延迟之后的输入，不把外围到达直接当成已经入园。

上午在园峰值需由全部入园和离园分布算出，不写死在11:30。此前用独立均值模型得到工作日约5,190人、周末约9,342人的峰值，仅作量级参考。

次日预约约70%已在前一天生成；公开夜间大屏仍可保持闭园静态，不要求增加维护、巡检或人员活动。

### 9.4 现场预约与核销

某时段现场预留32人，已有有效预约12人，因此余量20。新建3人订单：

1. 预约成功：有效预约增至15，余量17；在园不变。
2. 核销前背景在园8,000、其他现场在园4，总在园8,004。
3. 核销成功：累计入园增加3，现场在园增至7，总在园8,007；入口区域增加3。
4. 重复扫描同一凭证：所有人数不变，返回已核销结果。
5. 下一背景步入园12、离园5：背景变为8,007，现场仍为7，总在园8,014，不能回到8,007或额外再加3。
6. 这笔订单完成游览离园：只扣该现场批次3人，现场剩4；累计入园不减少。

现场订单暂停或换路线只改其区域归属和离园计划，不能重新占一次入园名额。核销请求结果不确定时查询原请求，不能换新请求重复记账。

## 十、验收、校准与范围控制

### 10.1 必须成立的关系

- `全园在园 = 背景在园 + 现场在园 = 所有互斥区域人数之和`。
- 若当日初始存量非零：`当前在园 = 当日初始在园 + 今日入园 − 今日离园`；不得忽略跨日存量。
- `车位容量 = 占用 + 空闲`，不可用车位以后如增加字段需单独列出，不重复扣减。
- 入口等候和场外移动不算在园；厕所及索道为在园的附加统计，不再加一次。
- 取消、爽约、核销、到达未入园的统计互斥且原因明确。
- 所有分配权重归一化，所有人数／车辆非负，硬容量不被突破。
- 同一随机种子与配置重复运行一致；刷新和新增浏览器连接不影响结果。
- 背景更新不覆盖现场操作，重试不重复核销，实际历史不混入预测或回放。

### 10.2 校准顺序与场景

1. 先关闭随机性，验证普通工作日与周末的总量、入口队列、在园曲线和晚间清空。
2. 再加入固定日期扰动，验证高峰没有因边界裁剪而丢失人数，周末整体高于工作日。
3. 校准区域权重及厕所能力，使平日大部分设施空闲或适中、周末午间只有少数位置拥堵；不追求精确等待时间。
4. 校准索道需求与运力，达到平日较顺畅、周末高峰可见拥堵，并在营业结束前消化正常队列。
5. 验证停车与乘客时序、晚到短游、全园限流、现场多人订单和重复扫码。
6. 验证中途启动、断线重连、跨日、回放隔离和参数版本切换。

校准每轮只调整一种因素，并记录参数、观察到的偏差和调整原因。既定业务规则不因调参改变。本文所列等效能力、权重和分布是可运行的起始设定，不是已经完成全套联动仿真的结论。

### 10.3 文档和实现验收边界

本文交付时核查参数单位、表格合计、四组算例及引用完整性。后续实现需要用全天数据验证跨步约束、忙闲形状和恢复行为，不能把文档算例通过等同于程序已通过全天验证。

前端关键操作正常网络下3秒内可见；背景每10秒一致更新；同一时刻各端数字一致；实际演示设备持续运行30分钟无明显界面故障。

不恢复逐人仿真、逐厕位传感器、索道故障、天气驱动游客行为、年度季节模型、复杂并发压测或生产级集群基础设施。
