## 1. 交付目标与依据

### 1.1 本次开发完成后应达到的效果

协作者在同一仓库独立分支内完成可以独立启动、操作和刷新复查的业务后台。内容编辑、订单取消与改期、配额调整、设施状态、检修计划、账号和聊天管理均有可核查的本地数据结果。用户能够按任意常见顺序操作，不依赖固定点击脚本。

技术采用 Vue 3、TypeScript、Vite、pnpm workspace。沿用青岚山境品牌样式，自建并复用后台组件，不引入 Element Plus、Ant Design Vue 等整套后台 UI 库。允许使用现有图标库及专门的 Markdown 解析工具；日期时间可以用封装后的原生控件，不要求自研日历引擎。

**本期开发验收为同一浏览器内的完整 Mock 原型。** 真实 API、数据库、跨设备和其他终端同步、WebSocket、人脸识别、前线终端、设备控制及部署均不属于本期。不得用无数据变更的“保存成功”交付，也不得声称样例操作已同步到手机或大屏。

### 2.2 视觉与尺寸（2026-09-13 归档修订）

本期仅面向 PC 宽屏，手机与窄屏适配不属于交付要求。主验收为 1440×900 CSS 视口，同时检查 1920×1080 和 1366×768。唱片导航预留 332px，顶部最小高度 56px，内容外边距 24px。多数管理列表使用固定标题／筛选／分页与内部滚动阅读区；表格过宽时在容器内横向滚动。抽屉和确认窗复用公共玻璃材质，内容滚动且操作可见。

工作台、景区资料及服务状态采用有主次的独立概览布局，继承宋体标题与公共玻璃容器。正文 18px、辅助信息 16px、区域标题 24px、主标题 32—36px，数字等宽。服务状态不显示描述性小字。静态等高线背景、轻微模糊与玻璃高光保持一致，不引入持续三维渲染。

外观支持跟随系统／浅色／深色；偏好使用 `qinglan.admin.appearance` 独立保存，系统变化和跨标签切换可同步，不重置业务数据、草稿或阅读位置。深色状态颜色区分健康、异常及未知。景区资料与服务状态在 650px 以下用同一导航分组的选择器替代固定侧栏；其余页面本期以桌面后台尺寸为验收基线。

表格、分页、表单、状态、确认、抽屉和异步反馈使用统一应用封装。键盘可操作，焦点可见；弹窗关闭后回到触发按钮。图标和颜色同时配文字，不只依赖颜色。

### 2.3 列表、表单及反馈约定

- 普通列表默认 20 条／页，可选 20、50；分页发生在全部结果完成筛选之后。提交搜索或重置筛选回到第一页，搜索去除首尾空白、英文不区分大小写。筛选有明确“查询”“重置”按钮，返回列表时保留本次页面筛选与阅读位置；窄容器收进筛选浮层，取消不应用草稿。预约配额的日期／类型／停车场切换会自动查询，只有最新响应可更新结果。
- 默认按更新时间降序、相同时间按稳定 ID 排序；时段按开始时间升序、设施按共享配置顺序、告警见 ADM-11、消息见 ADM-13。删除最后一页最后一条后回到最近有效页。
- 所有页面覆盖加载、空数据、失败及重试；表单增加校验失败、提交中、成功。失败保留输入，不关闭表单、不更新已保存数据。读取失败不当作空列表，写入失败不显示成功。
- 必填字符串 trim 后不得为空；输入控件注明单位。保存时在服务层再次校验，不能只依赖禁用按钮。字段错误紧邻字段显示，通用错误显示在表单内。
- 未保存关闭抽屉、切换路由、退出时提示放弃修改；浏览器刷新使用可用的原生离开提示，不要求浏览器显示自定义长文案。
- 删除、取消订单、禁用账号、停用设施、撤回消息、恢复样例均确认具体对象及影响；改期确认新旧时段；发布公告确认范围和有效时间。提交期间禁用同一操作，成功后本页列表、详情、工作台等相关查询结果一致更新。
- 只读详情不出现保存按钮。禁用动作标注原因，例如“该订单已经入园，不能取消”，不靠降低透明度表达业务原因。

**本期内容编辑默认限制：** 景区／景点名称 1—60 字，文章／公告标题 1—100 字，简介／摘要 1—300 字，地址与营业说明 1—200 字，Markdown 正文 1—20,000 字，公告正文 1—2,000 字，操作原因 1—200 字，举报处理说明 1—300 字。字符按 Unicode 码点计数。已有接口更明确的限制优先；这些前端限制中未写入旧契约的项目列入 D-06。

## 3. 逐页需求

以下每页同时适用第 2 章公共规则；“接口”均指未来对接设计，本期由 Mock 服务实现相同能力。

### ADM-01 员工登录

**字段与操作：** 账号 `username`、密码 `password`，均必填；账号最长 64 字、密码最长 128 字。提供显示／隐藏密码、登录。演示账号固定 `admin_demo`，密码 `AdminDemo123!`，在登录页以“本地演示账号”可展开说明并写入后台 README；仅用于公开样例，不能作为生产凭证。

**交互与校验：** 错误账号或密码统一提示；登录中防重复提交。模拟会话有效期为 12 个真实小时，保存在本后台 sessionStorage 命名空间，不保存密码；同一标签刷新保留会话，关闭标签后重新登录。未登录、过期、游客身份访问均不能进入业务页。过期保留业务数据，返回登录并提示原因。

**依赖与验收：** 预置员工、模拟会话；对应 `staffLogin/getMe/logout`。验证错误登录、正确登录、合法深链、退出、过期及员工权限校验。Mock 身份判断不被描述为真实服务端鉴权。

### ADM-02 工作台

**字段：** 当日有效入园预约人数、当日有效停车预约辆数、未完成告警数、待处理举报数。前两项按业务日期、`reservationStatus=confirmed` 汇总现场和背景数据，含已入园／已进场，分别使用人数和辆数；页面不展示来源解释，点击后进入相同日期和状态的订单视图。告警为当前运行 pending 与 processing 总和；举报为 pending 总和，不受其他页面筛选影响。

**交互：** 指标跳转对应页面并带筛选；告警占据主阅读区，按紧急程度优先展示 5 条未完成告警；预约概况及待处理举报位于辅助区。举报展示首条摘要与总数，独立读取及重试。没有额外编辑按钮，没有营收图表或第二份随机指标。默认数据缺失则显示未知与读取失败说明，不显示假零。

**依赖与验收：** 从统一订单、告警、举报集合计算。取消当天 3 人订单后人数指标减 3；改到次日同样减 3；生成检修告警后未完成告警加 1；处理举报后待处理数减 1。页面切换和刷新仍一致。

### ADM-03 景区资料

| 字段 | 编辑与校验 |
| --- | --- |
| `name`、`summary` | 景区名称、简介，必填，默认青岚山境现有文案 |
| `address`、`servicePhone` | 地址及演示服务电话必填；电话 7—20 位，允许数字、`+`、空格、连字符 |
| `coverUrl` | 从随包素材清单选择，必填 |
| `openingText` | 营业说明必填；属于展示文案，编辑不改变预约或设施营业规则 |

提供编辑、预览、保存和取消修改。预览显示当前草稿，保存后成为本后台统一景区文案。读取与保存对应 `getScenic/saveScenic`；图片由素材清单提供。

**验收：** 改名并保存后重新进入、刷新可读；草稿取消不改变已保存资料；错误电话与空名称被阻止；封面在原型离线静态资源可用时可显示。跨端标题更新不属于本期。

### ADM-04 资讯与指南

**列表：** 标题、栏目 `news/guide`、发布状态 `published`、更新时间；按关键词、栏目、发布状态筛选。关键词匹配标题与摘要。操作为新增、编辑、预览、发布／下架、删除。

**编辑：** 栏目、标题 `title`、摘要 `summary`、正文 `body`、封面 `coverUrl` 均必填。新增默认未发布，保存草稿与发布操作明确分开；编辑已发布文章保存后更新已发布内容，不增加审批或版本流程。新增成功生成稳定 ID，保留创建时间，更新时只改更新时间及修改序号。

Markdown 提供标题、加粗、列表、链接、图片插入按钮和编辑／预览切换。只允许安全的普通链接及素材清单图片引用；原始 HTML 转义或忽略，拒绝可执行 URL。图片不上传，正文图片与封面均来自本地资源清单。

**依赖与验收：** 对应 `adminListArticles/createArticle/adminGetArticle/saveArticle/deleteArticle`。完成新增→修改→发布→下架→删除；每一步可重新查询。栏目筛选需完整结果后再分页，不能只筛当前 20 条。验证 Markdown 安全预览、删除取消、保存失败保留草稿。

### ADM-05 景点介绍

**列表：** 仅共享 `kind=attraction` 点位，展示 ID、名称、区域、简介、更新时间；关键词匹配名称和简介，支持区域筛选。

**编辑：** `name/summary/body` 必填；`imageUrls` 为随包图片多选，0—6 张且去重，可调整顺序；`sourceIds` 从已有知识来源多选，可为空。只读显示点位 ID、区域、节点及原始配置名称。名称变化保存为全局内容覆盖，设施列表使用该覆盖显示名；不得修改共享常量、ID、区域或节点，也不增加点位。

**依赖与验收：** `listPois/getPoi/savePoiContent`、知识来源、素材清单。修改听溪台文案和名称后，景点内容及后台设施显示一致；路网和旧订单引用不变；未知来源 ID 被拒绝；刷新保留修改。状态编辑通过设施页处理。

### ADM-06 公告管理

**列表与筛选：** 标题、范围 `public/internal`、是否发布、实际生效状态、开始／结束时间、更新时间；按关键词、范围、发布状态、生效状态查询，关键词匹配标题及正文。

**表单：** `title/body/audience/startsAt/endsAt` 必填，默认公开且未发布。正文为纯文本；开始、结束为上海业务时间，开始必须严格早于结束，允许创建过去区间的样例。

**动作与规则：** 新增、编辑、发布、下架、删除。实际生效由业务时间计算：未发布为“未发布”；已发布且当前时间早于开始为“待生效”；`startsAt <= 当前时间 < endsAt` 为“生效中”；达到结束时间为“已过期”。发布过期公告仍显示已过期，不提示正在展示。内部公告只在工作人员视图可见；本期预览明确标注目标范围。

**依赖与验收：** `adminListNotices/createNotice/saveNotice/deleteNotice`。固定 14:30 下验证 14:00—15:00 生效、15:00—16:00 待生效、13:00—14:30 过期；下架后即未发布；公开和内部不混淆。操作不自动生成告警。

### ADM-07 订单管理

**列表字段：** 订单编号、类型、预约日期和时段、现场／背景来源、联系人、人数／辆数、预约状态、履约状态、创建时间。停车增加车牌和预约停车场，入园增加人数。背景记录展示“背景模拟批次”，缺少联系人显示“不适用”，不合成真人信息。

**筛选：** 类型、日期、来源（现场／背景／全部）、预约状态、类型对应履约状态、关键词。默认当天、入园、现场、全部状态。关键词匹配订单 ID、已有联系人姓名／电话及停车车牌。工作台跳转可覆盖默认来源为全部。

**详情：** 包含原列表字段、更新时间、入园／离园或进场／离场时间、失效原因及本地取消／改期记录。车牌、联系人、人数与预约类型在此只读，不展示入园二维码或人脸资料。显示预约停车场与实际停车场的区别。

| 状态维度 | 值与显示 |
| --- | --- |
| `reservationStatus` | `confirmed` 有效、`cancelled` 已取消、`expired` 已失效 |
| `visitStatus` | `not_entered` 未入园、`in_park` 在园、`exited` 已离园 |

**依赖与验收：** `adminListOrders/adminGetOrder/adminCancelOrder/adminRescheduleOrder/adminListSlots`。验证成功取消、跨日改期、换场、目标满额、重复提交、原订单已失效、已在园／已进场不可操作。任何失败必须保留原订单与原配额。

## 4. 关联业务规则与算例

### 4.1 订单、时段与原子保存

业务时钟固定为 `2026-09-12T14:30:00+08:00`。入园和停车档为 08:00—17:00 每小时一档，支持当天未结束档及次日档；当日入园未消费订单在 17:00 失效。停车订单有效到档结束后 30 分钟，右边界不含；取消可以在到场窗口前进行，进入等候状态后的取消和改期仍必须在有效窗口内。查询与提交都按原订单状态、日期及窗口判断，不能只看目标时段。已过期样例保留用于只读查询，不实现全天自动仿真。

取消前提为 interactive、confirmed、入园 not_entered 或停车 not_arrived/waiting 且仍有效。改期使用相同资格；目标类型一致、当天未结束或次日、目标停车场开放、目标配额足够。同档同场视为没有变更，不重复消耗名额。停车 waiting 换场在本期按普通改期迁移配额，不接入旧 gate 转场协议。

配额的 `interactiveBooked` 包含该档尚有效未消费和已经消费的现场配额，不能只数尚未入园订单。取消／失效的未消费订单释放配额；消费后不因离园／离场释放。背景订单不占现场配额。初始化的已占数必须能由完整样例现场订单解释；分页只是显示方式，不改变集合规模。

例：A 档配额 32、已占 12，含待改期的 3 人订单；B 档配额 30、已占 8。改期成功后 A 已占 9／余量 23，B 已占 11／余量 19，订单时段变为 B，实际在园人数不变。B 仅余 2 时整体失败，A、B、订单及持久化结果全部保持原值。取消这份订单只释放其当前归属档的 3 个名额一次。

实现采用“校验最新存储 → 在草稿状态应用全部变更 → 一次持久化 → 发布页面状态”。本地存储失败视为整次失败，不能先改订单再保存配额。为取消、改期等动作保留请求标识并去重；超时后的重试使用同一动作标识或查询原结果，不假定失败就可重复执行。

### 4.2 设施停用与通路保护

停用改变可用性和新业务资格，不改变物理容量、现有订单和占用。停车详情分别显示“物理余位”和“当前可接收新预约／使用”，索道保留在途和排队，卫生间按 §4.3 计算可用量。所有已有订单仍可进入详情由工作人员按资格取消／改期，没有批量自动处理。

本期使用已有共享路网做可达性校验，不硬编码“主路不能关闭”：删除 proposed closed 道路；停用索道移除相关 cable 路段；景点关闭遵循现有景点节点通行限制；纯服务设施如 AED、卫生间、商业点和终端停用不自动封掉接入步道。道路保留方向；出口要求以步行通路为准，不能只依赖索道撤离。

当前出口目标明确为 `gate-out`，`entry` 是入园服务点，不自动充当备用出口。关闭入园服务只停止新使用，不删除入口广场路网节点；`gate-out` 是唯一配置出口，停用时应被拒绝。以所有开放景点节点、每个仍开放区域的共享代表通行节点，以及仍有样例占用的可定位节点为检查起点，至少有通向有效出口的步行路线。后台集中配置的区域代表节点为：Z0→entry、Z1→r1、Z2→r2、Z3→r3、Z4→r4、Z5→r6、Z6→r7、Z7→r5；Z8 检查 entry 与 r1…r7 全部主通行节点。它们是现有路网节点，不把区域中心坐标转换为虚构节点。

关闭前比较现状与候选状态：现状已经不可达的节点单独展示已有问题，候选造成新的不可达则拒绝；出口不可用始终拒绝。拒绝结果列出受影响节点／区域名称，页面保留草稿供调整。可达性检查只是 Mock 业务规则，不声称完成真实消防或疏散验证。

索道两站状态更新、道路状态更新及其通路校验均在一次状态变更中处理，失败不只改变一半。设施开放状态与所属区域状态分别显示；区域关闭时单独恢复设施不越过区域限制。后台不新增区域状态编辑器。

### 4.3 卫生间分项暂停

共享分项键为 `female/male/maleUrinals/accessible`。大卫生间 t1/t4/t5 分别 24/8/12/2 个，总计 46；小卫生间 t2/t3/t6 分别 16/6/8/2 个，总计 32。最终引用 [共享配置](../packages/scenic/src/restrooms.ts)，不将小便位写成坐蹲位，不重复计入无障碍间。

每分项维护总数 N、使用中 O、排队 Q、基础暂停 B、人工申请暂停 R。N 为预置物理容量，O/Q 为只读样例；B 为未受此次人工调整影响的样例暂停基线，必须满足 `0 <= B <= N-O`。人工申请为该分项希望达到的暂停总数，不与基础暂停简单相加。

- 整座开放：实际暂停 `S=max(B,min(R,N-O))`，等待释放 `W=max(0,R-S)`，可用 `A=N-O-S`。
- 整座关闭／维护：该状态下有效申请为 N，实际暂停 `S=N-O`，等待释放 `W=O`，可用 A 为 0；原人工申请 R 保留，重新开放时恢复按 R 计算。
- 不改变 O、Q，不提前清退使用者。`N=O+A+S`，四分项相加得到整座数字；申请、实际、等待是不同字段。
- 原型不模拟占用释放，界面说明“等待后续使用数据更新后生效”；开发预览可提供释放前后两份确定快照用于验证，不在业务页增加“清空人数”按钮。
- 原有 Q>0 时 A 必须为 0。样例基线需满足 Q>0 时 `O+B=N`，因此恢复人工暂停不会伪造空位或清空队列。释放后的开发快照应同时提供一致的 O、Q、B；如果读取的数据违反此关系，显示数据异常并禁止分项保存，不新增逐人排队或自动入厕算法。

算例：女厕 N=24、O=20、B=0、Q=0，申请 R=10，实际暂停 4、等待释放 6、可用 0，O 仍为 20。开发预览使用 O=12 的释放后样例时，实际暂停 10、等待 0、可用 2。申请 25、负数和小数均拒绝；整座维护后实际暂停 12、等待 12、可用 0。

### 4.4 检修计划与只读告警

计划存储为全局配置，本期产生的告警与生成记录按 runId 隔离。到期判断为 enabled 且 nextDueDate 不晚于固定业务日期。生成去重键为 `(runId, planId, nextDueDate)`，计划与生成记录、告警在同一次持久化中保存；刷新时发现去重键存在则不再生成。

本期不自动补齐过去多个周期、不自动推进下次检修日期。周期用于计划展示及人工安排参考，前线完成后的排下期行为留待后续联调；用户可手工修改下次日期。修改为另一到期日是另一期，可产生新事件，保存前提示将新增记录；改回已生成日期不重复生成。停用计划、改成未来日期不删除已生成事件。

新检修告警级别为 reminder、类别 inspection、状态 pending；设施位置来自共享数据，标题为“{设施名}定期检修”，依据显示周期、到期日及计划说明。首次生成记录的 actor 为“检修计划”，业务发生时间使用固定业务时间；历史标题与说明保留生成时快照，不随计划后来改名重写。

负载回落不自动结案，完成反馈不把设施自动改为正常。当前后台只能查看种子处置记录和新增 pending 检修；“开始／完成后跨端更新”明确属于前线端与后端后续工作。

## 5. Mock 数据、持久化与预览

### 5.1 数据组织

后台业务类型、Mock 种子、存储适配、业务服务、页面分开。页面只能调用异步业务服务，不直接读写 localStorage。共享点位、容量、路网只读引用；景区／景点编辑使用内容覆盖层，不修改共享常量。禁止从 `apps/ops` 直接 import 业务模块形成跨应用依赖；告警按共享类型建立后台种子，可参照现有园方样例内容。

| 分区 | 内容 |
| --- | --- |
| 全局 | 预置用户、景区文案、文章、景点内容覆盖、知识与来源、检修计划 |
| 当前运行 | 订单、配额、公告、设施动态与暂停、告警、消息、举报、禁言、检修生成去重记录、操作结果 |
| UI 临时状态 | 当前页、筛选、抽屉、未保存草稿，不作为已保存业务数据 |
| 会话 | 员工模拟会话、真实到期时间，单独 sessionStorage 保存 |

业务时间统一固定，默认样例 runId 为 `run_admin_mock_20260912`，revision 为本地递增整数。同一业务时刻多次保存通过 revision 和真实记录时间区分，不能依赖 updatedAt 必然递增。全局内容保存也更新本地 revision。

服务边界保留显式运行上下文；有合法样例 runId 的 URL 可以打开对应样例，未知或已失效的运行显示不可用，不悄悄回到默认运行。本期只提供默认样例和测试所需的独立第二运行夹具，不做切换列表、回放或重置演示接口。

### 5.2 本地保存和恢复

业务存储键固定 `qinglan.admin.mock.v1`，存储版本、完整全局数据和按 runId 分区数据；会话使用 `qinglan.admin.mock.session.v1`。不使用 `localStorage.clear()`。恢复样例仅清理并重新建立本期后台业务状态及业务界面缓存，保持当前有效员工会话，不触碰游客／园方数据。

业务写入成功后再更新页面内存；若存储容量不足、禁用或序列化失败，显示“本地保存失败”，保留旧数据与草稿，不切换成仅内存成功。首次无法持久化时允许只读查看初始样例，并提示不能保存。存储内容损坏或版本不兼容时提示恢复入口，不静默覆盖已有内容。

刷新、路由切换、退出再登录必须保留已保存业务。多标签同步不作为本期功能；检测到其他标签的后台存储改变时，本标签提示重新加载并暂禁写入，保留当前草稿，不用旧整份快照静默覆盖另一标签。无需实现多人并发合并。

### 5.3 样例覆盖与素材

样例覆盖全部共享设施及道路；索道合并为一个业务对象。景点正文与知识引用使用已有青岚山境名称，补充内容标为演示说明，不使用旧接口里的“云岚文化景区”“古建展馆”作为当前实际点位。

后台维护小型随包素材清单：资源 ID、展示名、本地 URL、替代文字。素材来自仓库已有资源（例如游客端 `public/images/qinglv-landscape.png` 的副本）或协作者新增的本地静态 SVG；需注明来源，不依赖未提供的 `/assets/scenic/*.webp` 示例路径。图片可重复使用并标注示意图，不要求本期另行生成或采购图片。

### 5.4 开发预览入口

采用 `?preview=1#/...` 开启独立预览控制，正常 URL 不显示。预览存储使用独立 `qinglan.admin.mock.preview.v1` 命名空间，不能污染正常业务样例。提供加载、空数据、读取失败、写入失败、写入后响应超时、会话过期、存储损坏、卫生间释放前后等确定情形；场景标注仅供开发验收。

默认业务服务可以有短暂固定异步延迟，但不需要真实请求。提交成功后响应超时场景必须能查询已保存结果或以同一动作标识重试，不能重复扣配额。关闭预览恢复正常存储，不构成产品演示控制台。
