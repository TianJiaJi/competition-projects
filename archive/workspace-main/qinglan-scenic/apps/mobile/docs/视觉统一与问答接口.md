# 小程序视觉统一与问答接口

游客端采用浅青绿、静态等高线与浅色玻璃容器。长文和表单使用高不透明度底色；底栏背景覆盖左右边缘和底部安全区。地图与景观插画保持独立底图。

等高线复用共享地形，运行 `node apps/mobile/scripts/generate-contour.mjs` 生成 PNG 和内嵌纹理 CSS。CSS 内嵌图片是为了避免微信 WXSS 无法引用本地背景图片；不依赖 WebGL 或网页 SVG 组件。完整素材生成也会调用此脚本。

## 前后端边界

- 页面：输入、类别切换、消息展示、来源展开、滚动、键盘和临时连接状态。
- 网络适配：会话凭证、HTTP 和 H5 / 微信 SSE 传输。
- 后端路由：认证后的接口分发、HTTP 状态和 SSE 连接管理。
- 后端问答服务：推荐问题、景点上下文、校验、会话、重试关系、知识检索、模型调用与回答终态。
- 后端景区状态服务：运行内的点位开放、忙闲和道路关闭状态，持久化到 SQLite。

共享请求、工作台、消息、状态与流事件类型位于 `packages/contracts/src/mobile-qa.ts`。前端不上传问答快照、不解析重试原问题、不改写服务端消息终态。断线后重新读取历史；服务端发现连接断开会取消生成并保存部分回答，异常退出后启动恢复中断状态。

## 接口（前缀 `/api/v1`）

除原有公开资料详情接口外，以下接口使用现有 Bearer 凭证和 `X-Run-Id`。

| 方法与路径 | 请求 | 返回 |
| --- | --- | --- |
| GET `/qa/workbench?poiId=lake` | 景点 ID 可省略 | `context` 与包含推荐问题的 `categories` |
| POST `/qa/conversations` | `{poiId?}`，需 `Idempotency-Key` | 会话 ID、景点 ID、创建时间 |
| GET `/qa/conversations` | 无 | 当前身份与运行内的会话列表 |
| GET `/qa/conversations/:id/messages` | 无 | 服务端权威消息历史 |
| POST `/qa/conversations/:id/messages` | `{text}` 或 `{retryOf}`，需 `Idempotency-Key` | `start`、`delta`、`sources`、`done/error` SSE |
| POST `/qa/conversations/:id/messages/:messageId/stop` | 空对象 | 停止并持久化后的消息；重复调用返回当前消息 |
| GET `/scenic/state` | 无 | `points`、`closedEdgeIds`、`updatedAt` |
| POST `/debug/scenic/state` | `{kind:"point",id,availability?,load?}` 或 `{kind:"edge",id,closed}` | 修改后的状态 |

重试兼容旧请求附带的 `text`，实际原问题由后端依据消息关联获取。客户端 `snapshot` 不参与问答或幂等内容。终态包括 `completed`、`failed`、`interrupted`、`stopped`；主动停止与网络中断分开呈现。部分文字在生成过程中持久化，进程强制终止后可以恢复。

状态修改接口仅作用于调用者的运行，不控制真实设备，也不修改其他身份的运行。没有新增跨身份共享或后台管理权限。非法点位、状态枚举和道路 ID 被拒绝。

## 数据迁移与刷新

新增 `scenic_states` 表，首次访问按共享景区资料初始化，不导入设备端旧关闭状态。现有预约、收藏和聊天仍保存于当前设备。导览、详情、收藏和路线页显示时刷新状态，选用路线、开始游览及停车预约前再次刷新。导览前台每 15 秒刷新，更新失败时显示错误并暂停游览，状态标签显示待更新。

独立控制页通过接口修改当前运行的设施与道路状态。重置保留原来的设备记录清理行为，并建立新的问答运行和初始景区状态。游客页面清理项目展示用语，控制页保留必要调试说明。

## 验证

- `pnpm --filter @scenic/server typecheck`、`pnpm typecheck:mobile`（全仓检查为 `pnpm typecheck`）
- `pnpm build:mobile`：H5 与微信产物。
- `pnpm exec vitest run tests/unit/mobile-server.test.ts tests/unit/mobile-domain.test.ts tests/unit/mobile-sse.test.ts`
- `pnpm test:mobile`：独立前端端口 15176、后端端口 18787 与临时数据库，避免复用其他项目的预览。

浏览器覆盖预约、聊天室、路线、收藏，320 / 360 / 390 / 430 / 1024px 布局，工作台推荐、连续问答、来源、历史和新对话。后端使用明确的测试模型验证停止、重试、伪造快照无效、运行隔离及强制重启恢复。截图保存于 `.local/mobile-visual/`。

微信构建通过不等于真机验收：原生键盘、安全区及模糊效果仍需在微信开发者工具和真机检查。真实模型调用用 `RUN_LIVE_QA=1 pnpm test:mobile` 显式启用；普通回归不调用真实模型。

本轮结果：19 项相关单元测试、8 项浏览器测试通过，真实模型测试按默认设置跳过。前后端独立类型检查通过；最后一次全仓检查遇到同时新增的 `apps/gate` 缺少 Vue 依赖及组件声明，未修改该模块。
