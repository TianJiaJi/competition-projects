# 新版路演与实操展示安排

版本：2026-10-09 · 连续画布迭代。当前确定 01—03；04 由负责人继续设计，不在软件流程中强制执行。此前 55 分钟安排保存在 [历史路演稿](./历史方案/路演安排-v1.md)，其中 SQL 不执行、仅单工单的叙述已作废；工作流节点画布继续保留。

## 1. 开场与角色

开场：“这是一个通用应用搭建工作台。今天以学校为样例，从空间素材开始，由四位负责人接续完成需求描述、方案调整、应用组装和验收交接。”

| 操作员 | 固定职责 | 交接对象 |
| --- | --- | --- |
| 1 号 | 总体需求与空间方案；介绍地图、空间映射、浏览方式 | 给 2 号空间产物 |
| 2 号 | 五端职责、页面模板、组件和导航；整理数据需求 | 给 3 号页面与数据需求清单 |
| 3 号 | SQL 与服务层；初始化数据库、联通页面、解释执行结果 | 交付真实五端成果 |
| 4 号 | 本轮流程待定义 | 保留讨论空间，不补造方案 |

四人串行使用同一主机。总展示目标仍为 55 分钟加 5 分钟机动；04 未确认前不把旧分钟表当作新的锁定安排。两轮完整真人排练需在 04 脚本确定后计时完成。

## 2. 01 空间构建固定脚本

1. 在地图、坐标和参考模板节点选择文件；找文件不便时使用“载入准备好的素材”。无需打开侧栏。
2. 在需求卡片描述：“需要完整学校空间，能看区域和建筑，支持浏览及详情。”提交后观察轮廓、SVG、空间映射、沙盘方案依次推进。
3. 在调整卡片填写：“突出教学区，统一重点标识，使用学习视角，提供教学设施聚焦。”提交调整，在原卡片审阅差异，再确认组装。
4. 自动链到绿色“验收沙盘成果”停下，打开独立窗口演示缩放、旋转和设施详情。
5. 回到验收节点填写观察，点击“验收通过”。交接话术：“空间结构、楼宇与设施编号、沙盘组件交给界面负责人。”

## 3. 02 界面搭建固定脚本

1. 导入页面模板和公共组件；接收空间验收后，描述公共、监控、手机、后勤、管理五端的角色与功能。
2. 观察职责拆解、组件匹配、导航布局；按节点摘要讲解所用组件及其输入输出。
3. 调整：“手机提交和看本人记录，后勤处理，管理维护；调整导航和首屏重点。”提交后审阅差异，确认组装。
4. 自动链完成页面装配和数据需求清单，停在绿色验收卡片。打开五端成果，检查导航、列表、详情与表单。
5. 填写观察并通过。交接：“页面需要的字段、关联、查询和业务操作已经列清，交给 SQL 与服务负责人。”

## 4. 03 数据、服务与总装固定脚本

1. 导入 SQL 和服务模板，接收前端的数据需求，描述楼宇、设施、报修、预约、巡检及后台维护关系。
2. 沿白色节点讲解实体、表结构和查询，再解释服务四步：参数校验 → 角色/状态/归属规则 → SQL 参数绑定 → 返回结构。
3. 调整：“分开提交人与处理人；关联字段结构化；领取和完成校验条件，返回页面可用的数据。”提交并审阅后确认组装。
4. 数据库初始化后进入总装：汇集产物、核对清单、连接沙盘页面、对应字段接口、绑定按钮操作、配置跨端协作、检查服务连接。
5. 绿色验收节点打开成果：手机报修 → 后勤领取 → 空结果提交观察拦截 → 填结果完成 → 手机查看处理结果。领取后仍保留原提交人归属。
6. 需要时补充预约与取消、管理新增公告、巡检完成。回工作台填写观察并通过，再交给第四位负责人。
7. 第四人测试链和最后交付目前显示待定义。不得把开发检查结果当成第四人已完成测试或真人排练。

## 5. 窗口、恢复与记录

使用工作台给出的链接打开成果，保持 localhost 和端口一致。普通查看只聚焦现有窗口；链接可复制。登录页预填账号，操作者自行点击。窗口状态在目标页面就绪后更新；人工验收仍须回节点填写观察并确认。

刷新和重启恢复当前轮。需要从头排练时点击“开始新流程”，上一轮演示库将删除，先导出需要留存的记录。输入变化使下游失效，应重新确认和检查；不要用预制完成态覆盖实际失败。

人工观察只写亲眼看到的结果。开发自动化填入的记录不能当作投影、设备或真人排练证据。设备表和两轮 55 分钟记录见 [运行与排练记录](./校园演示运行与排练记录.md)。
