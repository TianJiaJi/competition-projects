# 校园演示运行与排练记录

版本：2026-10-09。本文覆盖软件运行和记录方法，设备信息及真人排练记录留空待实测。

## 1. 赛前准备与现场启动

在 `zhixing-campus` 目录执行。沿用项目声明的 Node.js / pnpm 环境；建议 Node.js 24、pnpm 10.17.1。首次安装和浏览器准备必须在赛前完成。

```sh
pnpm install
pnpm typecheck
pnpm test
pnpm test:demo
pnpm build
pnpm test:demo:static
```

开发时用 `pnpm demo:start` 同时启动 5500、5503、5506；只调工作台可用 `pnpm dev:demo`。现有 `pnpm dev` 仍为原五端入口。现场使用：

```sh
pnpm demo:build
pnpm demo:serve
```

构建应在赛前完成，现场只运行最后一条。静态服务器只绑定 localhost，端口占用时失败，不自动换端口。Ctrl+C 关闭本次启动的服务，不占用其他项目端口。统一使用 `http://localhost:5506/`，从节点打开成果标签页；允许工作台弹出窗口，勿使用 `127.0.0.1` 混合访问。

M01 PNG、M02 SVG、M03 配置由 `pnpm demo:assets` 按现有模型布局重新生成；该命令需要已安装的 Chrome，仅在修改模型布局后运行。正式播放无需生成素材、下载字体或执行 shell。

## 2. 正式流程操作

1. 工作台全图说明四条链；阶段按钮聚焦分组，“定位下一步”只定位。点击节点后使用右侧临时抽屉，Esc 关闭，代码可放大。
2. 载入校园图片、SVG、设施配置、参考标准，查看 M05 后打开校园沙盘。等待模型就绪，再点击页面顶部“定位明理楼投影设备 · F4”。
3. 载入需求与 SQL 模板；检查 S03，观察 T1→F404 被拦截；载入 S04，再次检查；加载 SQL 与配套结果。SQL 未执行。
4. 打开通用模板，使用预填 `staff01 / 123456` 点击登录。身份显示“后勤人员”。返回工作台载入公共组件、校园配置、适配，点击“应用校园成果”。同轮身份保留，页面实际就绪后节点通过。
5. 校园后勤保留全部导航，工单仅 T1；巡检等无关模块为空。按 F4 筛选并打开详情，保持待处理。勿在此时领取。
6. 载入测试需求、测试模板，准备检查脚本，运行真实检查。十项检查使用隔离副本；D02 的“断言通过”表示 F404 被正确拒绝。现场 T1 不变。
7. 在人工验收节点，对 H01—H03 按实际观察填写证据和判定。最终在后勤领取 T1、空结果提交一次、填写固定结果并完成，再核对历史记录、返回沙盘，登记 H04/H05。
8. 在交付节点确认并下载 JSON。固定处理结果为：**已重新连接投影信号线并校准色彩，试播画面正常。**

## 3. 报告与恢复

- 报告区分预制材料、实际函数检查和人工证据。人工通过或失败均必须填写说明。普通查看成果只聚焦已有标签页，不重载工单。
- 当前阶段重置会使依赖它的下游结果失效；SQL 重置后重新从 F404 开始。失败历史保留。
- “重置后勤验收”恢复 T1 待处理、清空人工记录，保留本轮身份。自动检查报告不代替人工重新操作。
- 整场复位生成新 run，当前报告暂存于当前工作台页面，可先下载。已打开的成果页恢复沙盘初始视图及通用模板；后勤重新登录，并等待页面复位确认。未打开页面按首次打开处理。
- 工作台刷新会丢失内存报告、生成新轮次并要求整场复位。刷新前先下载报告；关闭旧成果标签页，之后从工作台重新打开。
- 成果页刷新恢复 URL 对应的初始业务状态；同轮身份保留，页面显示刷新提示，工作台要求重新登记相关人工证据。关闭重开后需重新登录。
- “恢复与直达”中的排练菜单只预载前序材料，显示“预载 · 未执行”，不补造检查通过；正式最终交付仍要求真实页面和校验通过。
- 页面打开失败时允许弹窗后重试；20 秒没有就绪会显示超时，允许重新加载。手动复制 URL 缺少 opener 关系，不能替代工作台的应用确认。
- 若仍失败，打开“预制完成态”说明成果。该视图显著标记为预制，真实失败和未验收状态保留。
