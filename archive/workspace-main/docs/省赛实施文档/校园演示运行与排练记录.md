# 工作台运行与真人排练记录

版本：2026-10-12 · 固定画布与素材清单迭代。学校为演示样例，工作台保留 AI 工作流节点画布。本页设备信息与真人排练记录必须现场填写。

## 1. 准备和启动

**先进入 `zhixing-campus` 目录**，使用 Node.js 24（含 `node:sqlite`）及 pnpm 10.17.1。依赖和浏览器须在赛前安装；本轮没有新增第三方数据库依赖。

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm test:service
pnpm demo:build
```

开发：`pnpm dev:demo` 或 `pnpm demo:start`。正式离线静态版：`pnpm demo:serve`。两者均启动五个成果端、工作台及本机数据服务。

| 端口 | 用途 |
| --- | --- |
| 5500 | 公共端；01 阶段只有沙盘 |
| 5501 | 运行监控 |
| 5502 | 手机 H5 |
| 5503 | 后勤 |
| 5504 | 管理后台 |
| 5506 | 应用搭建工作台 |
| 5507 | 本机 HTTP 服务与 SQLite |

5505 组件预览不计入成果，也不由统一演示启动器启动。所有演示 URL 使用 `localhost`。启动器先核验所有端口，冲突明确失败；不要同时运行原 `pnpm dev` 和演示启动。任一子服务异常退出会清理本次启动的其他进程；Ctrl+C 一并停止。

正式版本全部资源来自本地，绑定 localhost。断外网保留本机回环网络；不要把浏览器设为连 localhost 都禁止的离线模式。工作台打开成果使用独立命名窗口，需允许本机弹窗。浏览器可能按用户偏好将新窗口显示为标签页，但成果始终有独立 URL，不在工作台浮层里渲染。

## 2. 固定操作

1. 打开 `http://localhost:5506/`。首次建立轮次，之后刷新自动恢复；只有需要重做整场时才点击“开始新流程”。
2. 首次进入显示全图，使用底部导航或“定位节点”查看局部；拖动卡身或空白平移，Ctrl/⌘＋滚轮缩放。镜头完全手动，流程不会自动移镜；刷新恢复位置。“定位当前”优先找失败事项，再找人工停点、运行节点。
3. 从工作台“下载素材”取得 ZIP，或使用 `packages/demo/assets/material-pack/` 本地文件夹。点击整块导入区选择多文件或多文件拖入，可追加、去重、逐项移除；“载入参考素材”替换为该节点完整清单。至少一份登记成功即完成，取消选择不改变状态。需求直接在卡片输入并提交，自动步骤按依赖推进。
4. 在调整卡片输入一次修改，提交后原卡片查看差异，再点“确认组装”。观察输出摘要，无需逐个点自动节点。
5. 中性为未运行，蓝色为运行/等待验收，绿色为已完成；等待验收没有处理动画。验收卡常显端名链接：01 打开沙盘，02/03 各提供五个端。预览使用独立窗口，回节点填写观察后通过或退回。通过才交接；每阶段预览均可独立回看。
6. 后勤、管理、手机分别预填 `staff01`、`admin01`、`user01`，密码均为 `123456`，操作者点击登录。角色显示匿名名称。
7. 在手机提交报修，后勤领取，空结果提交观察拦截，填结果完成；手机显示处理结果。其他端约 2 秒自动刷新，也可手动刷新。
8. “本轮报告”执行独立副本检查；D02 分开标注输入拒绝与断言通过。人工观察通过/失败均填写说明。导出 JSON 留存本轮过程、素材版本、输入、真实执行和失败历史。

## 3. 恢复行为

| 操作/现象 | 行为与处理 |
| --- | --- |
| 工作台刷新 | 恢复 run、镜头、文件清单、输入、节点进度和历史；自动链继续，不删库；未确认提交等待手动重试 |
| 成果刷新 | 02 重建该端样例，03 从 SQLite 恢复业务；同轮身份保留 |
| 服务重启 | 恢复当前轮、节点与数据库；自动链继续，实际失败节点需点重试 |
| 普通“打开成果” | 聚焦同轮同阶段现有窗口，不刷新工单 |
| 关闭后重开 | 03 保留业务，关闭标签页后的身份需重新登录 |
| 上游输入、素材或调整变化 | 相关下游确认、验收与检查失效，历史保留；重新推进 |
| 验收退回 | 观察与原因留痕，回本段调整；重新提交、确认和验收 |
| 从旧轮次升级 | 保留已发布产物，待人工验收；不补造细节点执行记录 |
| 重新确认 03 | 幂等建表与查询，已存在的业务记录不隐式清空 |
| 开始新流程 | 归档旧过程 JSON，删除旧轮专属 SQLite，新 run、新身份；旧链接失效 |
| 阶段/样例/版本错误 | 明确报错，从工作台打开有效链接 |
| 就绪等待超时 | 检查窗口是否停在登录、模型加载或错误页；完成后点“重试” |
| 服务请求失败 | 明确显示错误/过期数据；不会用本地样例冒充服务成功 |

持久目录是 `zhixing-campus/.local/builder/`。`current.json` 保存轮次和过程，`run-<run>.sqlite` 保存当前业务，`history/` 保存过去的过程 JSON（不含会话令牌）。有需要先导出报告再开始新流程。

`DEMO_DATA_DIR` 可为开发/测试指定独立目录。`DEMO_NODE_DELAY_MS` 仅供测试加速，正式演示不要设置，默认每个处理节点约 1500 毫秒。浏览器验收使用 `.local/builder-e2e`，服务测试使用临时目录或内存库；不复用现场业务库执行检查。`DEMO_REUSE=1` 只应指向专用测试服务，不要对正在排练的轮次运行自动化。
