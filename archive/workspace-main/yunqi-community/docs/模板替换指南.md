# 模板替换指南

## 从现有项目开始

复制整个目录，排除 node_modules、dist、.local、test-results 和 playwright-report。项目无需父目录或兄弟目录。进入复制后的目录运行 `pnpm install --frozen-lockfile`。

### 1. 品牌和配色

编辑 `scenario/config.ts` 的 name、english、tagline、description 与 theme。主题覆盖玻璃、图表、背景、正文和控件，状态颜色保持独立语义。手机品牌还需同步 `apps/mobile/src/manifest.json` 的 name、description、h5.title，以及 pages.json 的页面背景色；运行 `pnpm assets:mobile` 更新 Lucide 图标。加载屏使用同一场景名称。

### 2. 导航和页面组织

`scenario.navigation` 决定后台唱片架分组与页面顺序。`packages/experience/src/App.vue` 内的 nav 决定公共、监控和工作人员导航。新增页面直接写 Vue 组件并挂到入口的页面分支，无页面配置 DSL。

手机页面清单为 `apps/mobile/src/pages.json`；各路由页调用 `ServicePage.vue` 的对应业务部分。复杂的新页面应拆为独立 Vue 页面，继续使用平台导航层。校园不注册访客页。

### 3. 指标与数据

`scenario.metricLabels` 管理四项主指标名称。`seed` 提供设施、工单、巡检、人员、楼宇、预约、访客、公告、安防和停车的固定数据。`usage` 提供趋势图；`questions` 提供助手的固定问答。

`packages/domain/src/index.ts` 的 metrics 负责主指标计算；更换业务口径就在此处修改，不要只改标签而沿用错误数值。公共概览、后台和运行大屏从同一份各端状态计算：在用空间/入住户数取楼宇汇总，停车余位取总量减使用量，工单取未完成数量，设施在线率取正常设施占比。师生与住户列表是少量服务档案，不等同于楼宇容量统计。

Mock 服务是同步内存操作，创建、领取、完成和编辑会更新当前端数据；刷新重新建立固定状态。没有随机定时波动，不使用 localStorage，不同步其他标签。刷新恢复也包含登录身份。需要真实接口时再替换 domain 调用边界，本轮不设计接口协议。

### 4. 页面与交互复用

- `packages/ui` 保留玻璃、唱片架、滚动条、等高线、水墨进度和图表组件。
- `packages/experience/src/components` 提供数据列表、筛选、分页、表单、抽屉和模型浏览包装。
- 抽屉保留 Escape 关闭、Tab 焦点限制与返回触发器；唱片架仍支持指针、滚轮吸附、键盘和减少动态效果。
- 手机用 uni 原生控件及原 Lucide 图标方案；H5 表单可访问名称在平台层传递到实际输入框，不把 DOM 逻辑放入业务规则。

### 5. 社区沙盘

统一入口为 `packages/experience/src/components/ModelBrowser.vue`，公共大屏、管理大屏与组件预览共用 `@scene/ui/community` 的 `CommunityMap`。

社区模型位于 `@scene/model/community`，布局与设施锚点统一维护在 `packages/model/src/community/layout.ts`，三维模型和底部画卷共用这份数据。模型配色来自 `scenario.theme`。

修改位置、建筑数量或业务归属时，同步检查布局单元测试。组件保留旋转、缩放、复位、加载进度和可选开场；空间锚点已与既有业务记录关联，本轮未启用点击详情或实时业务联动。

详见[云栖雅苑沙盘布局与组件](云栖雅苑沙盘布局与组件.md)。

### 6. 独立运行

修改 ports 为一组空闲端口，避免多个副本冲突；原项目端口配置不受影响。执行 `pnpm typecheck`、`pnpm test`、`pnpm build`，再在浏览器验证品牌、导航、指标及主要操作。
