# 工作流机制与样例

工作台采用常展开 HTML 节点与 SVG 连线，无分区框、节点侧栏或拓扑编辑。`src/builder` 是通用类型、客户端和桥接；`src/samples/school/workflow.ts` 定义学校的全部输入、人工、处理、执行、验收及占位节点。通用工作台不导入校园实体或业务检查。

## 实现边界（开发说明）

LLM 摘要、差异和装配产物是固定材料，文件只记录元信息，不解析/校验内容，不现场编译或生成源码。没有组件拼装器。SQL、SQLite、HTTP 与业务操作实际执行。演示前端不显示这些性质标签，内部节点类型和 JSON 执行证据保留区分。

## 节点执行与持久化

`server/workflow.mjs` 是并行 DAG 推进器：依赖齐备的自动节点一起运行，汇合等待全部输入；失败阻断依赖分支，其他分支可以完成。普通节点 25 秒，复杂节点 50 秒，当前关键路径约 525 秒；`DEMO_NODE_DELAY_MS` 仅为开发测试缩短等待。处理阶段文案由样例提供，开始时间与时长随节点持久化，刷新/重启继续；初始化幂等，实际执行串行。异步结果校验 run 与节点记录代次，避免无关素材导入改变全局 revision 后丢失正在处理的结果。

状态包含 blocked/ready/running/waiting/complete/failed/invalidated。素材导入、需求、调整原文、确认、验收、错误和重试全部留痕。通过/退回必须填写观察；通过才交接，退回至本段调整。失效按依赖传播，检查按 revision 判断有效性，历史保留。

`.local/builder/current.json` 独立于业务库保存 run 与节点；`run-<run>.sqlite` 保存业务。“开始新流程”仅删除上一轮专属库，历史 JSON 不含 session tokens。无节点记录的旧轮次继承已发布产物并等待人工验收；有节点记录的图升级比较持久化依赖签名，失效相关子图，保留输入、素材、历史和业务库，不补造执行日志。失效传播通过遍历依赖完成，与数组顺序无关。

## HTTP 接口

- `GET /api/workbench`：definition（含 workflow/modules）及 state（含 nodes、sequence、graph）；不返回身份令牌。
- `POST /api/new {run}`：归档上一轮过程，建立新轮次。
- `POST /api/runs/:run/node {node, action, revision?, ...payload}`：import(files[] 元信息；兼容 file)、submit(text)、confirm、accept(passed/detail)、retry。
- 旧 `/stage` 不允许绕过节点、材料和人工验收门槛，返回 409。
- `/context`：校验 run/caseId/version/stage/terminal，只返回请求阶段；阶段必须有有效产物。
- `/session`：POST 登录、GET 校验、DELETE 退出；身份按 run/application 保存于 sessionStorage。
- `/records`：共享数据读取与角色业务操作；初始化完成后允许组装连接检查的只读请求，写入仍要求成果生成和有效身份。
- `/checks`、`/manual`、`/report`：独立内存数据库检查、人工证据、JSON（含内部执行方式和 SQL/HTTP 证据）。

## 预览与桥接

01 纯沙盘、02 五端独立样例、03 共享服务，均保留本轮最新有效成果，不保存修改历史快照。按 run/stage/terminal 复用独立命名窗口，普通查看不导航、不重置工单；关闭重开重新加载。取消旧阶段跳最新阶段。

## 画布与客户端约定

节点的 module/布局位置、所属角色 stage、deps 执行依赖分别表达。outputName/inputs 提供产物和具名连线，task 是未开始时的任务，summary 是完成输出，phases/durationMs 提供逐步展示。所有学校文案及位置提示来自样例；前端不读取学校实体。

模块与卡片均使用固定网格。卡片按种类固定高度，长清单、过程、差异及代码只在内部滚动；内容、状态、日志更新不改变节点坐标、尺寸、连线锚点或镜头。空间、前端、服务从左/上/右向中央分批交接，跨模块连线绕开无关模块，主要交接名称常显，其余名称在悬停相关节点时显示。人工节点保留负责人窄色条，自动处理/执行节点使用独立灰白色条和灰色图标；连线保留角色色。中性底表示未运行/失效，蓝底表示运行/待验收，绿底表示完成，红边表示节点或提交失败。待验收不播放处理动画。

5506 使用校园公共包 `@scene/ui/liquid-glass` 和 `@scene/ui/contour`，保留原有蓝灰底与四角色色；不修改青岚项目或成果端主题。工作台只保留标题、必要操作和当前待处理事项。版本及轮次放在报告，五端成果的阶段横条移除，刷新与聚焦在业务工具区。

首次进入和开始新流程显示全图；每个 run 的镜头存于 `assembly.camera.<run>`，刷新恢复。没有自动跟随。只有定位当前、节点选择、模块导航、全图与缩放/拖动改变视野。定位先找全图失败（含客户端失败提交），再按路演顺序找可操作人工节点，最后找运行节点；没有目标时禁用。卡身、标题、正文、代码和空白均拖动，不选字；输入、按钮、链接、导入区域、展开控件和滚动条保留原行为。普通卡身滚轮平移，实际有溢出的内滚动区处理滚动，Ctrl/⌘＋滚轮缩放。画布使用 `overflow:clip`，避免控件聚焦隐式滚动。

素材由 `src/samples/school/materials.ts` 清单统一提供，详见 [素材使用说明](./MATERIALS.md)。`files[]` 保存规范化元信息；id 从 name/size/type/lastModified 计算，不采用客户端提供的标识或正文。旧单文件平滑迁移为列表，并保留 `file` 首项兼容字段；不会改写既有状态或补造执行记录。新请求 `mode: append|replace|remove|reference`，默认 append；旧 `file` 请求保持 replace 行为。参考模式从服务端清单取完整列表；移除用 fileId。清单集合不变时不推进、不失效；移除最后一份恢复待输入，保留输入、历史和数据库。取消文件选择不发请求。每份物理文件由清单白名单提供下载，不开放任意路径。

工作台写操作排队；每次出队采用最新修订，冲突保留失败并等待显式重试。导入反馈立即进入卡片，不随 GET 成功清除。提交失败和未确认的客户端请求保存在 `assembly.feedback.<run>`，刷新后显示错误并等待显式重试，不自动重放。state.sequence 每次保存递增，客户端同时使用请求代次与快照序号拒绝旧轮询，不能把 sequence 与业务失效 revision 混用。

验证文件选择时分别记录：浏览器选择器事件回调、Mac 原生 Open、Windows 原生选择器；不能把 setInputFiles 当作操作系统对话框通过。2026-10-09 已验证 Codex 内置浏览器选择器回调，以及 macOS Chrome 原生“打开”窗口选择 M01.png 后显示文件名和“已导入”；Windows 原生选择器仍待实机验证。本轮不修改路演安排文档。
