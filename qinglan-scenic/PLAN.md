# 沙盘游线人流与细粒度热力图计划

## Context

当前沙盘已有两条未完全衔接的客流链路：

- 服务端 `apps/server/src/platform/visitor-flow.ts` 会根据路线、入园时间、速度档位与游览阶段，生成最多 320 个可复现的 `VisitorFlowPoint`。每个点带有聚合人数 `people`、当前坐标、朝向、速度及未来 60 秒的游线轨迹。
- 前端 `packages/scenic/src/scene.ts` 已把这些代表人群绘制为实例化人形，并利用轨迹在下一次快照到来前沿游线平滑移动。
- 但 `packages/scenic/src/heat.ts` 当前只读取 `snapshot.regions` 的 9 个区域等级，在各区域中心按半径做高斯扩散；它不读取 `visitorFlow` 坐标或人数。这是热力图呈现为大块区域、不能反映人流沿游线位置变化的直接原因。

本次目标是将人流生成和热力渲染衔接：代表人群随游线连续改变坐标，热力图依据其坐标与聚合人数渲染为沿道路分布的细粒度图像，同时保持现有运行快照、可复现模拟、区域统计与多端读取机制兼容。

## 最新视觉修正（取代下文早期的窄带、高分辨率方案）

- 用户最终要求是全沙盘连续热力着色：无人处为空闲绿；有人处依据当前坐标和人数形成更细的连续色彩变化，不产生透明底上的孤立色斑。
- 删除为覆盖路网而制造匿名游客和最低人数的逻辑。使用现有代表群；没有人就是零密度。
- 保持 128×128、150ms 刷新上限。人数先双线性投到网格，再做两次方向高斯模糊；使用固定密度色标，不按每帧最高值拉满颜色。
- 整张纹理不透明，投影到现有沙盘热力材质；关闭/维护灰色仍优先。只有旧快照缺失 visitorFlow 字段才回退区域等级，明确空数组不会制造热度。
- 地理权重、关闭遮罩、配色缓存；慢设备沿用场景质量等级降低热力更新频率。
- 已核验空园、早晨、午间、闭园前与30倍速的游客端截图，以及运营端午间截图。验证暂停停止上传、播放继续更新。截图位于 `.local/qa/formula-flow-*.png`、`.local/qa/heat-ops-noon.png`。
- 本机单独测量 128×128 / 320 点平均热力重绘约 2.7ms；这是 CPU 算法测量，不等同于终端整体帧率。

## Approach（早期规划，冲突项以上述修正为准）

已确认的产品决策：热力只反映游客**当前位置**，不保留经过轨迹；游客端与园方运营端两个沙盘同步修改；沙盘改为**仅热力显示**，不再渲染可见人形；热力直接使用现有最多 320 个、带 `people` 权重的代表人群，不额外生成高密匿名点；步道呈窄而连续的热带，入口、广场和景点停留位置可形成较宽斑块；优先保障大屏端的纹理精度与动画流畅度。

推荐继续使用现有“统计客流 + 有权重代表人群”的模型，而不是为每位真实游客持久化独立实体：

1. 保留 `visitorDistribution()` 的人数守恒、路线选择、速度档位、确定性抽样和 `people` 权重；检查代表点在服务端快照与前端插值间的连续性，并补齐实际需要的轨迹/刷新数据。
2. 将热力投影的数据源从“区域中心 + `LoadLevel`”改为“`visitorFlow` 代表人群位置 + `people` 权重”。每个代表点只影响其当前位置周边的有限核半径；步道采用窄核，入口、广场和接近景点/停留位置的点使用较宽核，使热点沿步道、入口和停留区出现，而非覆盖整个区域。热力强度按所有代表点的 `people` 加权后做稳定归一化，避免代表点数量而非人数决定颜色。
3. 保留现有 Three.js `DataTexture` 与材质 shader 投影结构，在 CPU 端按更细网格栅格化人群贡献，再由 shader 映射到沙盘地形、道路与可受热力影响的表面。区域等级仍用于标签、图例和无 `visitorFlow` 时的兼容降级，不再作为正常热力的主数据源。
4. 移除场景中的可见人形实例网格；提取原人形动画的轨迹插值为统一的当前位置数组，让热力图使用同一时间基准和插值位置，在两次快照之间持续更新。暂停时冻结位置，倍速时沿相同游线按 `visitorFlowClock` 推进，不产生人形与热力错位。
5. 将纹理尺寸、核半径、强度归一化、刷新上限和降级策略集中为明确配置，并通过单元与浏览器回归验证密度、连续性与性能。

## Verification

- 对固定的业务时间、入园记录与种子，`visitorFlow` 的 ID、`people`、坐标和轨迹可重复生成，所有 `people` 之和与对应区域/在园统计口径一致。
- 代表人群在静止、正常播放、暂停和倍速播放时都只沿已定义游线移动；每个快照边界前后坐标连续，无跳跃到建筑中心或区域中心的现象。沙盘不再绘制代表人形。
- 热力热点跟随代表人群当前位置，集中于道路、入口与游览停留点；同一人群移动后旧位置在下一次纹理刷新时立即消失，不保留历史尾迹，不遗留大面积色块。
- 高权重人群比低权重人群贡献更大，但不会使少数点产生硬边、饱和方块或覆盖全图；在相同总人数下，代表点拆分方式不应改变总体热力口径。
- 热力图在关闭/维护区域按现有遮罩规则表现正确，缺失人流坐标时使用明确后备表现。
- 在游客端和园方运营端沙盘实测连续播放、暂停、倍速、切换人流视图和旋转缩放；确认不再有可见人形，检查帧率、WebGL 错误、纹理刷新频率和大屏表现。
- 运行相关 Vitest、Playwright、类型检查和构建；将视觉截图与当前大块热力效果对比。

## 当前结果

两端同步使用连续热力场。现有游线、人数统计和代表点生成未改变；没有新增虚构人群。最终验收以最新视觉修正规则及对应截图为准。
