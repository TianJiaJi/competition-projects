# 智慧校园质量测试工作台

> **最新重置规则（取代下文早期临时会话说明）**：刷新、关闭后重开、栏目切换与热更新均保留已记录进度。只有左下角“测”隐藏按钮或工作台服务进程真正重启才清空。服务启动标识由`/__workbench_session`提供；短暂断网不视为重启。右上角重置入口已移除。已记录任务自动保存到浏览器，存储被禁用时会提示无法保存。

固定面向 **智慧校园 / 知行校园五端项目** 的交付验收工作台。以项目交付消息和测试任务为入口，所有解析、生成、测试和反馈都由讲解者手动触发；进入页面、接收交付或生成用例不会自动运行测试。任务中心另展示3条只读历史示例，明确标注来源，仅供展示，不写入本轮任务证据、统计或报告，不提供其他真实项目切换。

## 启动

在 `qinglan-scenic` 目录运行：

```sh
pnpm dev:testing
```

统一启动工作台 `http://localhost:5180`、校园五端 `5500–5504` 和预约请假服务 `5606`。已启动的对应项目会通过源码标识/只读服务响应核验后复用，不重复启动。遇到错误进程占用端口会明确失败，不杀原进程，也不静默更换端口。结束时只停止本启动器创建的子进程；Windows会清理这些子进程树，复用的校园进程保留。

`pnpm dev:all`同样经过校园联动入口。单独运行 `pnpm --filter @scenic/testing dev`仅启动工作台，适用于隔离开发；现场推荐使用统一入口。需要预先安装两个项目的依赖，启动器本身不执行安装。构建输出为 `apps/testing/dist`。

右上角环境状态支持查看六项校园服务和重新检查。环境核验不计入测试，也不触发任何用例。单独部署静态构建没有开发服务器环境检查路由时显示明确提示，仍可打开项目入口。

## 固定交付内容

- 一个固定项目、版本、交付消息和任务：`CAMPUS-DELIVERY-2026-001` → `MSG-CAMPUS-001` → `QA-CAMPUS-001`。
- 前端交付人周宁、后端工程师陈工，来自智慧校园一体化解决方案。
- 学生服务、教师工作台、管理后台、公共大屏、运行大屏五个真实页面入口。
- 12项预约/请假API材料：健康检查、可用时段、申请列表、创建、教师审核和学生取消；携带真实项目对应的方法与路径及预制请求/响应示例。示例中的“交付后第二天”为日期占位说明，不用于实际请求。
- 四项后端专项要求：重复提交去重、同教室时段并发预约、跨账户/班级权限、弱网重试去重。
- 旧系统目录与原始存储不被删除或覆写；本轮不提供其他项目切换和多平台自动发现。

## 手动操作路径

推荐顺序为 **UI → API → 并发 → 专项 → 验收报告**，侧栏、交接说明与验收统计保持一致。接收任务后进入交付概览，点击“开始测试”进入首个待完成项目；流程切换与进度计数位于顶部栏中间，不在内容区域增加卡片；窄屏使用现有左侧/顶部导航切换，顶部只保留开始或下一项操作。材料解析、用例生成、执行测试及报告查看均由操作者手动触发（UI直接使用交付检查清单，并发复用API用例）。执行结果及报告自动保存，不另设重复保存动作；完成本项及人工补充检查后，点击“下一项”前往后续未完成项目，不会自动开跑。存在前面未完成的项目时会引导补齐，不会跳过未测项直接允许完结。最后手动汇总验收报告，再确认提交报告并完结任务。

API每次执行（含筛选、单项及停止）会自动保存独立报告；执行结束后点击“查看API测试报告”打开弹窗，查看统计、逐项HTTP状态及断言并导出JSON。报告不会自动弹出；刷新后可从API页面或验收报告的原始执行报告列表重开。该快照只包含本次执行结果，不将单项/分组结束冒充全部计划完成；报告查看不改写证据。

1. **任务中心 → 接收上游交付**：初始展示3条历史示例，可筛选全部、进行中和已完成，也可查看历史摘要。点击页面上方“接收上游交付”才新增既定的校园任务、消息与协作时间线；同版本接收按钮随后禁用，刷新不会重复建单。历史示例不计入本轮待办。点击“进入测试空间”查看上游交接说明：上游要求验证什么、本次实际交付什么、需要执行哪些测试、完成后需要回交哪些材料。页面入口、12项API清单和4项后端标准与交付源一致；110项是后续生成的测试场景，不冒充额外交付接口。交接单展示UI/API/专项/并发的计划范围与验收依据，以及综合报告、问题/未测清单、原始证据和本地回执要求；不展示执行统计或协作时间线，不虚构代码压缩包等附件。入口只导航，不自动解析、生成、执行或提交。当前任务状态由已保存的证据计算，不因打开页面自动通过。
2. **UI测试 → 打开项目预览**：五端入口、手机/桌面及尺寸切换，内嵌真实页面，也可新窗口打开或重新加载。点击预览工具栏的“放大”，在灰色遮罩上展开近满屏预览：隐藏地址栏与底部说明，只保留紧凑工具栏，手机默认原始100%内容密度并按高度适配竖屏，避免组件挤在一起；右侧继续填写、保存页面检查清单，窄屏通过工具栏的清单图标展开右侧抽屉，不挤占预览高度。工具栏“刷新”图文按钮只重新加载当前预览，不清除检查草稿；点击“关闭”文字按钮、灰色背景或按 Escape 返回，保留预览当前页面、尺寸和未保存的检查草稿，并恢复普通模式的内容密度。逐项手动选择待检查/通过/需整改，填写观察备注，保存页面检查。逐页保存至全部17项完成后自动生成并弹出独立UI报告。点击“一键完成五端检查”则直接补齐并保存全部检查，不再二次确认，也不自动打开报告；完成后原按钮切换为“查看报告”，刷新或切换栏目后仍可查看。修改未保存的检查草稿后按钮恢复为一键保存，避免展示旧报告。已有需整改项与备注保留，缺少问题说明时阻止提交。报告也可在验收报告的测试记录中重开和导出。一键完成属于操作者批量确认，不执行自动浏览器检查，也不会完结整个项目任务。检查结果与预览尺寸使用统一绿色自定义下拉菜单，支持方向键、Enter选择、Escape取消及点击外部关闭；选择选项不会自动保存。需整改必须提供问题描述。页面加载不自动记为通过。
3. **API测试 → 解析API材料 → 生成测试用例**：解析前不导入或展示任何API列表和请求/响应详情；解析完成后显示12项原始交付接口，但仍不展示请求参数与预期响应。生成后才显示场景详情，并将完整110项用例迁入同一卡片的左侧列表，不截断为原12项；右侧展示所选场景的请求、预期响应、验收点及执行结果。上方操作区集中“解析API材料”“生成测试用例”“运行全部API”和停止按钮，执行动画与进度也位于同一卡片内，原下方重复列表已移除。列表右侧展示实际HTTP响应码（未执行或取消不伪造状态码）。桌面仅列表和详情内部滚动，窄屏上下排列。基于12项原始交付材料生成110项测试用例（正常契约、参数边界、权限和状态场景），全部初始待测试；可搜索、筛选业务组，单项/分组/全部执行。执行时当前用例固定在列表表头下方，列表自动滚动；搜索与分组在运行期间锁定。点击结果查看该场景的请求参数、固定响应、契约断言和本地证据来源。新增用例是本地模型，不代表增加了98个已部署接口。旧12项执行记录会保留，新98项等待手动执行。
4. **专项测试 → 生成专项用例 → 一键测试**：生成前仅展示后端工程师4项指派、怎么测试及不可修改的验收标准，不显示交互案例或用例补充。点击生成后约3秒（编排动画节奏整体放慢12%）展示“分析需求 → 模板匹配 → 条件/请求/断言拼装 → 校验 → 发布”的编排过程；实际从本地4项场景模板构造配置，不连接远程AI，取消时不发布任何半成品。生成成功才展开交互案例，上游要求默认收起、可重新展开。一键测试按指派顺序执行每项的“准备条件 → 触发请求 → 核验结果”，显示进度、请求动画及断言结果，完成一项后短暂停留再切到下一项；已有核验记录跳过，未完成步骤可继续。执行中刷新后保留已记录进度，需再次点击一键测试才继续；同一步中已经处理的请求不会重新应用写入或重复累计回执。栏目切换不打断测试，停止仅重置当前未完成场景，保留已核验项，后续项不误记为通过。全部完成显示“已完成”，自动静默保存专项报告，不弹窗；点击“查看报告”读取最新快照，重复查看不会重复归档，刷新后仍可打开。参数/补充检查变化后报告重新生成，旧快照保留；人工补充检查不会被一键测试自动确认。仍支持单场景三步手动执行、重新运行、补充检查和阶段报告，请求卡与流水可查看输入、响应及前后状态。
5. **并发测试 → 开始并发测试**：默认2000目标并发、30秒、自动吞吐（上限0）；并发范围5–10,000，时长10–120秒，支持手动加压和停止。仅在启动后按预热及五级阶梯推进，不自动执行下一轮或其他测试。未启动前没有测试曲线或虚构指标。

新打开的负载配置默认使用2000并发、30秒；旧曲线及旧报告始终保留它们本次执行时的原配置，不会被新默认值或后续表单修改覆盖。

新一轮模型在第5级峰值阶段使用 **1%–4%正向随机演示波动**（低并发按整数取整，至少增加1）。目标值与前四级计划不变，扰动后的模型负载参与吞吐计算和曲线记录，不单独篡改报告峰值。每轮保存随机种子与扰动范围，模型采样时间相同即可复现，查看、导出和刷新不重新随机；旧报告保持原样。报告首屏明确标注模型随机波动与“非实测数据”，这种展示效果不能作为真实服务容量或真实性能达标的证据。

并发报告以**本次目标是否达到**为核心：目标取本次报告保存的负载配置，有完成请求的有效采样峰值达到目标即显示“通过”；未达到显示“未达标”，明确列出目标、峰值、达成率和差额，并将问题关联至验收问题清单和本地反馈。空曲线、仅有计划升档或没有有效请求时显示“待补测”，不能判通过。报告弹窗、JSON与HTML使用同一判定逻辑。完整执行但未达标属于已执行的整改问题，不冒充通过；提前停止即使峰值已达标，仍需补齐设定时长才可完结任务。目标通过与请求契约异常分别记录；本地模型不能证明真实服务的承载能力，报告持续保留来源说明。
6. **验收报告 → 汇总验收报告 → 提交报告并完结任务**：手动汇总独立快照，区分需整改、待补测和本轮已记录检查通过。正式提交需全部计划测试完成（含人工补充检查和完整结束的并发测试）、当前无执行中的测试且报告为最新版本；确认弹窗勾选核对声明后才生成本地归档回执。任务随后为“已完成”，先保存独立归档快照，再自动清空 UI / API / 专项 / 并发测试的工作记录、草稿与临时界面状态，并返回任务中心（不再显示重复的任务完成提示框）；待办归零，侧栏不再保留上轮已检查数量。任务、交付关联、时间线、验收报告及原始报告均保留，可点击该任务的“查看验收报告”只读查看、导出。查看归档不会把旧测试记录重新填回当前工作区。此操作不调用左下角大重置，不清除任务或归档。存在整改项也可如实提交完整测试结论，但结论仍为“待整改”，不冒充验收通过。部分报告仍可“提交验收反馈”以提前同步问题，但任务保持待补测，不会完结。

API展示节奏在原25ms/项加速20%后两轮各减速8%（每轮时长÷0.92）；展示等待预算按实际用例数计算（110项约2.71秒，当前128项约3.15秒），按累计截止时间调度，渲染与保存开销不再逐项叠加到等待时长，包含三次约240ms的模拟网络停顿，停顿不额外延长预算（实际总时长还受浏览器渲染影响）。不再等待模型响应耗时；报告中的响应耗时仍为模型值，不冒充真实请求测量。API、并发与专项执行状态及取消控制相互独立，运行中可切换栏目、保存UI检查或启动其他测试；同类任务不重复启动，正在运行的用例不允许编辑。隐藏重置在任一任务运行期间禁用。停止API保留已完成记录，不把取消记为成功。取消当前专项动作会重置该场景，其他场景保留；一键测试同时停止后续队列，不会自动继续下一项。切换栏目、刷新或重新打开页面保留已记录的任务和场景；只有隐藏重置按钮或工作台服务进程重启才清空。

### 用例调整

- API允许调整名称、预期HTTP状态、耗时预算、备注和人工补充检查；保存后清除旧结果。原始交付路径、方法和响应契约保持不变，修改错误的预期状态会产生失败，而不是随预期伪造相同响应。
- 专项参数有受支持的固定选项；修改参数/重跑重置当前场景。备注和人工补充检查可调整，工程师原始标准不变。
- 补充人工检查不会被模型自动判为通过，需测试完成后人工确认，未确认进入报告未测范围。
- 新测试/检查修改使原综合报告过期，提交反馈或完结任务前必须重新汇总。旧报告的证据快照不被后续修改篡改。
- 任务状态：待测试 → 测试中 / 待补测 → 待汇总 → 待提交 → 已完成。正式提交前可取消，未确认或取消提交不会生成任务完成记录；重复提交不会生成第二份归档回执。
- 已完成任务的归档禁止修改或重新汇总。当前测试工作区已清空且无进行中任务，不能在归档任务上重新执行测试；普通导航进入 UI / API / 专项 / 并发页面只显示空白初始状态，验收报告导航不自动混入历史报告。需要查看旧报告时，从任务列表点击“查看验收报告”。刷新与栏目切换保留完成条目和归档，旧版已经完成的任务会自动迁移，保留原报告再清空工作区。
- 只有隐藏大重置或服务重启仍按既定规则开启空白本轮并清除本轮任务归档，3条静态历史示例保留；自动工作区清空不执行这些操作。归档与反馈都是本地记录，不代表远程交付团队实际收到。

## 保存、导出与重置

任务、已保存的人工检查、用例、测试结果、报告和反馈自动保存在 `service-test-workbench.campus-task.v1`。连续测试中以约200ms间隔保存检查点，非运行中的操作及API结束/停止时立即保存；正常刷新、页面隐藏或离开前同步保存最新进度。异常强退或浏览器崩溃仍可能丢失尚未写入的最后一个检查点。进度统计不再生成或复制完整验收报告；只有手动汇总时才创建独立证据快照。刷新或重新打开时恢复。`service-test-workbench.service-session.v1`关联工作台服务启动标识，标识变化才清空上一轮任务；普通热更新和网络失败不清空。不修改校园业务数据或旧系统配置。

原始报告保留最近8份/24000条记录，持久化仍受浏览器容量及150万字符预算限制；需长期保存的证据请主动导出。浏览器禁止存储时仍可操作，但会明确提示刷新可能丢失进度。

综合报告支持JSON和独立HTML（可打印），原API/并发/专项报告支持原始JSON，并发/专项还支持HTML。综合导出区分：

- `dataSource: local-manifest`；
- `executionMode: local-model-and-manual-ui`；
- `automatedBusinessRequestCount: 0`；
- UI人工检查、API契约模型、专项场景、并发统计和本地反馈回执各自保留来源。

左下角“测”头像是唯一手动重置入口，点击直接清空并回到任务中心，不弹确认；右上角重置入口已移除。任一任务执行期间头像禁用，但不锁定其他测试栏目。重置仅清理工作台，不清空校园预约/请假业务数据。

## 演示边界

**本工具不接真实岗位消息系统，不执行真实AI生成，不向校园服务发出API/专项/并发测试请求。** 交付包、岗位指派、生成过程与反馈回执是本地可操作状态流转。UI内嵌加载真实本地项目；环境核验会发送只读HTTP探测，这两类网络访问不属于自动业务测试请求。

API固定响应和本地专项约束不代表实际校园后端已实现全部幂等、重试、并发或权限机制；模型并发测试不能当作真实服务性能验收。文案、证据详情、JSON与说明区分了来源，避免把本地模拟当作真实测量。
