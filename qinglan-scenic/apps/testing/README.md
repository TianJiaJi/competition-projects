# 服务测试工作台

独立 Vue 3 / Vite 本地演示工具，提供可配置的系统目录、110 项 API 验证、五级阶梯压测、实时图表和报告导出。API 响应和压测数据全部由预制契约与模型生成，不访问被配置的业务服务，也不依赖后端、数据库或 API 代理。

在 `qinglan-scenic` 目录执行：

```sh
pnpm install --frozen-lockfile
pnpm dev:testing
```

访问 `http://localhost:5180`。`pnpm dev:all` 也会启动测试端。构建输出为 `apps/testing/dist`。页面保留常规测试工作台的名称与操作流程，不展示模式标签；原始 JSON 通过 `executionMode`、`measurement` 和 `source` 标记数据来源。

## 配置系统与接口

右上角“管理系统”支持新增、编辑、复制、删除系统，统一保存后切换到所选系统。默认服务可编辑但不能删除；删除当前系统后选中默认服务。支持最多 20 个系统，每个系统 1–200 个接口。

- API 地址支持 `/api/v1` 等同源路径，以及 HTTP/HTTPS 地址。地址和路径仅作为配置及报告中的接口标识，不用于发送请求。
- 默认景区目录提供 110 项验收用例：保留原有 30 项基础、字段与边界检查，新增启动身份、预约订单、入园核销、路线导览、互动消息、知识问答、园区运维、运营管理八组，每组 10 项。各项配置独立名称、路径、响应材料和字段契约；部分用例针对同一接口检查不同契约，110 项不代表新增 110 个后端路由。
- 预制响应匹配用例的预期状态码、数据结构与延迟预算；400、401、404 等预期拦截也是正常的用例通过结果。自定义接口按配置生成对应状态码及 JSON，204、205、304 允许无内容。
- 支持按分组、状态和关键词筛选。首次读取未修改的旧 9 项或 30 项默认目录时自动升级至 110 项并保存；已编辑目录、自定义系统和升级后的手动删减均保留。
- 系统配置保存在 `service-test-workbench.systems.v1`。损坏时恢复默认配置；浏览器禁用存储或配额不足时，当前会话仍可使用，并显示保存提示。
- 测试进行中不能切换系统或修改配置。切换系统重新初始化结果和曲线，记录页面仅展示当前系统的历史报告。

## API 验证与展示节奏

接口验证和单独重测使用 `simulatedSample` 生成本地响应，最多三个用例同时推进。显示旋转加载弹窗；每轮展示时间随机约 3.8–4.4 秒。进度条从零分段增长，在不同位置短暂停顿后加速，已核验数字依次递增；计数胶囊在零项时为灰色、部分完成时为黄色、全部完成时为绿色。

可随时停止。已完成结果保留，正在等待的步骤记为取消；取消不伪造为成功，也不进入完成数分母。接口耗时记录模型生成的响应耗时，展示等待不计入该耗时。运行全部、单独重测和自定义服务均不会发送业务网络请求，外部服务返回 500 或不可达不会影响演示。

总览和 API 页的 P50/P95 卡片每 900 毫秒在原值 ±2 ms 内波动。列表平时保持固定，仅在每次测试完成后更新本次接口的 ±1 ms 展示偏移，不累积漂移。详情、断言和导出报告保留本轮生成的原始数据。

响应延迟趋势与卡片共用展示数值，每 900 毫秒续接一个点，滚动保留最近 60 个点；重测不会清空展示曲线。报告使用本轮独立记录，展示用的持续波动不会写入报告。

## 阶梯压测

默认 60 秒、1,000 目标并发、自动吞吐（上限填 0）。预热并发为 100，然后经过 200、400、600、800、1,000 五个档位，达到峰值后保持到本轮结束。

“加压一级”立即升一档，在图上留下事件标记。手动加压后下一次自动升档至少间隔五秒；到第五级后禁止继续加压。停止冻结曲线并保留停止时刻之前的结果，重跑创建新记录。

完成量采用闭环模型：`吞吐量 = 当前并发 × 1000 ÷ 窗口平均耗时（ms）`。例如 1,000 并发、200 ms 对应约 5,000 req/s；耗时增至 400 ms 时约为 2,500 req/s。设置非零吞吐上限时再取较小值，上限随加压档位同比变化。

每段完成数按吞吐量乘以区间时长累加，保留小数余量。每秒生成一个统计窗口，在升档、停止时补齐不足一秒的区间；实时吞吐等于该段完成数除以区间时长。窗口延迟分布随压力、时间波动及升档后的瞬态变化。吞吐右轴随本轮峰值扩展，累计数、曲线与报告共用同一份记录。

每个窗口以最多 64 条带权重的模型记录保存延迟分布，权重之和是完成请求数。总完成量不受记录条数限制，平均值、通过率及 P50/P95/P99 均按权重计算（weighted nearest-rank）。标签页延迟唤醒时按既定时间补齐阶段。

参数范围：目标并发 5–1,000、时长 10–120 秒、吞吐上限 0–50,000 req/s（0 表示自动）。会话保留最近 8 份报告，压缩模型记录累计最多 24,000 条；超出时移除最旧报告，不截断单轮完成请求数。

## 智慧校园目录与服务发现

“管理系统”中已配置“智慧校园”：110 项 GET 接口验证用例。保留原有 30 项，平台基础、校园空间、设施运维、后勤工单、教学服务、权限审计各扩至 15 项，新增生活服务、安全巡检各 10 项，共八组。包含 B1 楼宇、F4 设施、T1 工单的关联材料，账户与岗位使用稳定编号。接口列表可按业务组筛选，名称、地址、预期状态码和延迟阈值均可编辑。110 项采用本地预制响应，并不新增业务后端路由；整轮验证仍约 4 秒，报告对应 110 条结果、330 项断言。

“服务发现 → 发现并接入新服务”按顺序读取本地发布清单、校验契约并生成测试配置，完成后自动保存三个平台：智慧后勤服务平台、教学空间预约平台、校园安全巡检平台，各 12 项接口。目录卡片显示来源模板、交付岗位、版本及接入时间；接入记录按实际处理步骤追加。可从左侧目录查看配置并切换测试，或关闭管理窗口后在“当前系统”中直接选择。

发现处理读取的是仓库预制的发布清单，不侦测实际部署、局域网或远端员工操作，不发送业务网络请求。`system.registration.dataSource = local-manifest` 随原始 JSON 导出。重复扫描保留已有配置；达到 20 个系统时停止新增；关闭进行中的发现会取消本轮尚未提交的结果。自动接入不会保存手动编辑草稿，也不会产生 API 通过记录或自动运行压测。

老配置只补充一次智慧校园目录；未修改的旧 30 项校园目录自动扩至 110 项并保存，保留当前选择、已有编辑和发现接入的平台。已编辑目录不会被覆盖，手动删除后不会在每次刷新时重新添加。系统配置持久保存于当前浏览器，测试报告仍按会话保留。讲解时可按“其他岗位使用模板完成平台交付 → 读取发布清单 → 自动生成测试目录 → 选择新平台开展验收”推进。

## 专项验证

侧栏“专项验证”提供六个独立场景，每场按“准备条件 → 触发操作 → 核验结果”手动推进，场景之间保留进度。每次操作由本地场景引擎计算业务状态，流水与证据直接读取同一运行记录，不连接业务服务。

| 场景 | 参数选项（默认） | 核验要点 |
| --- | --- | --- |
| 多账户抢单 | 2 / 5 / 10 个账户（2） | 只产生一次领取和一个订单持有人 |
| 重复提交 | 3 / 10 / 20 次（10） | 创建一次，所有返回指向同一订单 |
| 库存防超卖 | 5 / 10 / 20 人（20） | 初始库存 1，成交 1，余量 0，库存不为负 |
| 越权访问 | 查看 / 修改归属 / 取消（查看） | 拦截账户 B 对账户 A 的操作，敏感字段与订单变更为 0 |
| 断线重试 | 1 / 3 / 5 次重试（3） | 首笔写入后回执暂缓，重试复用同一业务记录 |
| 乱序回调 | 1→3→2 / 3→1→2 / 3→2→1（3→1→2） | 最终保持版本 3 和完成状态，旧消息不覆盖 |

准备完成后，账户请求进入待放行队列。触发操作时按队列处理，产生带时间、请求编号、账户、输入、响应及前后状态的记录。抢单和库存竞争保存随机种子及受理顺序，获胜者由本轮顺序决定；预期拦截是防护通过，不是测试失败。点击请求卡片或右侧流水可查看证据。

动作执行期间锁定参数、系统、场景入口和其他测试操作。等待下一步时可以切换场景或分区，返回继续；修改参数或重新运行只重置当前场景。切换系统清空专项草稿，已生成报告留在原系统下。引擎重置或卸载会取消未完成动作，旧回调不能继续写入。

完成至少一场核验后，可生成“专项验收报告”。报告加入测试记录，展示场景数、断言结果和业务证据，支持独立 HTML、JSON 和打印。部分报告只展示已核验场景，JSON 保留全部六场的草稿状态；报告生成后采用独立快照，重跑或更改参数不影响已生成报告。八份报告及 24,000 条数据的预算包含专项事件。

### 3–4 分钟讲解顺序

| 时间参考 | 操作与讲解 |
| --- | --- |
| 0:00–0:15 | 打开专项验证，介绍三步操作和右侧请求流水 |
| 0:15–0:50 | 多账户抢单：完成三步，打开一条领取记录，指出唯一归属 |
| 0:50–1:20 | 重复提交：观察多个请求复用相同订单编号 |
| 1:20–1:55 | 库存防超卖：展示 20 个请求与最终成交 1、库存 0 |
| 1:55–2:25 | 越权访问：展示权限拦截和订单前后状态不变 |
| 2:25–3:00 | 断线重试：指出首次写入、回执暂缓与重试去重 |
| 3:00–3:30 | 乱序回调：观察 v3 保持、旧版本受保护 |
| 3:30–3:50 | 生成专项验收报告，展示六项核验与 18 项断言，导出 HTML |

以上是操作稿；现场讲述时长与大屏可读性需使用实际设备排练确认。

## 成果报告与 JSON v3

压测自然完成后自动打开本轮报告，集中展示峰值并发、累计完成请求、峰值吞吐、P50/P95/P99、已记录的加压阶段、两张趋势图和本轮测试成果。页面及 HTML 不展示真实网络请求明细、错误日志或模式标签，也不输出真实服务性能验收结论。

手动停止显示“本轮阶段记录已保存”，仅列出已记录的阶段。未运行的阶段不会补造通过结果；完整执行状态和全部阶段标记仍保留在 JSON 中。可从压测页“查看压测报告”或测试记录中的“查看报告”重新打开。

支持下载独立 HTML（本地样式与 SVG、无外部依赖、可打印为 PDF）和原始 JSON。报告采用执行时的配置快照，不受后续修改影响。记录仅保留于本次会话，刷新前应导出。

JSON 文件名使用 `service-test-` 前缀，包含：

- `schemaVersion: 3`、`executionMode: simulation`、`networkRequestCount: 0`，说明数据由本地模型生成。
- `system`：运行开始时的系统与接口配置快照。
- `samples` / `statistics`：生成的响应及统计。模型条目的 `weight` 表示该延迟记录代表的完成请求数，省略时为 1。
- `observations`：新一轮始终为空；兼容历史记录时不改写其中已有的实际观测。
- `frames`：时间、档位、并发、吞吐、延迟；统计窗口另含 `windowSeconds`、`meanResponseMs`、`capacityRps`、`completed`，所有压测帧包含 `cumulativeCompleted`。
- `events`、`config`、`loadSummary`：加压事件、运行参数与本轮汇总。
- 专项报告使用 `kind: special`，以 `scenarios` 和 `summary` 承载场景参数、种子、受理顺序、步骤、业务快照、事件、断言及汇总，不套用请求样本或 P95 指标。

```sh
pnpm typecheck:testing
pnpm build:testing
pnpm test:testing
```

测试覆盖预制契约、零业务网络请求、断网运行、配置持久化、取消与重跑、加压调度、带权统计与完成量积分、报告与导出、六类专项场景的全部参数、动作互斥和旧回调取消、三种屏幕宽度。浏览器测试使用 15180 端口，不需要真实服务。
