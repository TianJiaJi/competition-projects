# 前线处置终端功能需求 V1.0

2026-09-13。功能和视觉经本任务确认。本轮交付为独立浏览器本地原型；管理员端 OA 只写需求，不实现后台页面或真实接口。

## 1. 视觉与导航

依据全局视觉规范、手机游客端已确认视觉方案和公共玻璃组件文档。延续浅青 `#EAF3EF`、稳定内容底 `#F8FCFA`、深青文字 `#193B35`、主按钮 `#175F54`；不另选风格。全页复用 `@scenic/ui/contour` 静态等高线背景，浅青底、深青线条 6% 不透明度；内容阅读面保持稳定底色，背景不拦截点击，无持续动画。

页面标题宋体 28px，分组标题 20px，正文与输入 16px，辅助 13px。默认左右 20px 留白，320px 为 16px；按钮圆角 14px，列表整体圆角 20px，行间轻分隔。品牌栏直接使用 `@scenic/ui/scenic-art` 的 `ScenicLogo` 公共 SVG 组件（28px），站点图标也复用同一 SVG 资源。功能图标为 Lucide；操作区至少 44px。底栏复用公共玻璃容器，提高阅读面遮蔽，不给每条任务添加玻璃。

品牌和账号栏固定在视口顶部，正文预留 60px 加顶部安全区；搜索框使用轻浅青底、左侧线性图标、输入后清空按钮和单层整体聚焦描边。日期采用浅青日历弹层，支持年/月选择、前后月份、今天、清除日期和键盘方向键；截止日期早于起始日期的日期禁用。

一级底栏贴合屏幕底部并横向铺满视口，去掉两侧悬浮留白和外圆角；列表底部预留 100px 加安全区，保证末条记录可完整滚动到操作区上方。

下拉选择统一使用 `GateSelect`：14px 圆角、Lucide 箭头、浅青选中底；支持 customizable select 的浏览器使用同色圆角选项面板，其他浏览器保留系统选择器，键盘与移动端原生选择行为不变。

手机主验收 390×844；补验 320/360/430px，平板和桌面保持居中单列。表单和详情隐藏一级导航，采用返回栏和底部操作区。页面自然滚动，留出导航与安全区位置。无持续装饰动画、地图、照片或额外统计面板。

| 路由 | 页面与行为 |
| --- | --- |
| `#/tasks` | 全园未完成任务；搜索标题、原因、位置，类别筛选，全部/待处理/处理中切换 |

## 2. 任务闭环

事件类别沿用 `crowd/parking/cable/restroom/equipment/help/cleaning/inspection`，严重程度沿用 `critical/important/reminder`。当前任务先按严重程度、再按发生时间倒序、最后按 ID 排序；历史按完成时间倒序、最后按 ID 排序。本人任务包括处理中和已完成，沿用当前任务排序。

`pending → processing → resolved`：工作人员自行开始后成为唯一负责人。其余员工只读。完成结果去除首尾空白后 1—500 字；记录负责人和时间，不回退、不转派、不编辑已完成结果。

发生时间使用既有 `startedAt`；实际开始处理使用 `handlingStartedAt`，不能混用。事件完成只关闭此次事件，不改变监测值、设施状态，不推进检修日期。告警复发创建和传感器判断属于后端后续工作。

## 3. OA 协同

处理中任务负责人可以申请：增援、封锁现场、物资、其他。申请原因和具体需求分别必填 1—500 字，不做照片上传和结构化人员调度。每次提交是独立申请，一个任务允许多条申请。

`pending → approved/rejected/withdrawn`。申请人可撤回待审批申请；已提交内容不可修改，需要时撤回重提。管理员批准或驳回均必填 1—500 字意见，记录审批身份、时间。结束后的申请不可再审批或撤回。

只有待审批申请阻止任务完成；批准、驳回、撤回都是 OA 终态。批准仅代表审批决定，不代表现场措施已经落实；任务负责人仍需完成现场工作并反馈结果。封锁审批不直接更改道路、设施和地图。后端必须在同一事务内检查待审批 OA 与任务状态，不能只依赖前端禁用按钮。

OA 新建、撤回和审批都递增关联任务版本，避免旧页面越过结案门槛；申请本身也有独立版本。申请时间线和事件处理时间线分别展示。

## 4. 本地数据和异常

业务通过异步适配器 `src/services/gate.ts` 操作。仅使用 `qinglan.gate.mock.v1`，模拟会话键为 `qinglan.gate.session.v1`。不连接其他端存储或服务，不保存密码。

首次加载和重置按当前真实时间生成一组固定内容样例，后续不会随机刷新；时间展示为上海时区。样例含八类未完成事件、两个负责人、已完成记录和已批准/驳回/撤回 OA；待审批 OA 由真实页面提交产生。

每次写入先验证身份、版本及业务状态；保存成功后更新内存，失败保留旧数据和表单。使用完整持久化快照比较及 Web Locks（支持时）检测标签间冲突。无 Web Locks 时只保证同步写前比较，不宣称跨设备或所有浏览器均具备事务能力。

刷新保留已提交业务；表单草稿保留在当前页面内存，离开、退出或刷新前提醒，明确确认后丢弃。重新加载业务数据不清除当前草稿。检测其他标签变更时禁止旧快照继续提交，重新加载后才恢复。损坏数据提供恢复样例；恢复只替换本端业务键，保留当前会话和其他端数据。
