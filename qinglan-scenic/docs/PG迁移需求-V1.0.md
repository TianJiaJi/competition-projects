# PG 迁移需求 V1.0

日期：2026-09-13。状态：本地迁移已实现；验证与限制见 [实施记录](implementation/PG迁移与本地联调-2026-09-13.md)。以下保留原迁移需求基线。

## 目标与范围

正式存储迁至 PostgreSQL 17，采用 `pg` 驱动、连接池与版本化 SQL 迁移。所有端继续使用当前 HTTP/WS 契约，不让前端感知数据库类型。首期保留文档式业务模型，不同时重构全部业务为关系表；不新增双写、CDC 或读写分离。

当前后端使用 Node.js 24 `node:sqlite`，且绑定 `127.0.0.1`。仅设置 `DATABASE_URL` 不会迁移或切换数据库。当前源码同时涉及两套存储，不能只迁移 QA：

| 源 | 默认位置 / 配置 | 迁移对象 |
| --- | --- | --- |
| 平台库 | `.local/scenic-platform.sqlite`；`SCENIC_PLATFORM_DB_PATH` | accounts、auth_sessions、documents、commands、journal |
| 问答库 | `.local/scenic-platform-qa.sqlite`；`SCENIC_DB_PATH` | sessions、conversations、messages、attempts、scenic_states |
| 版本化静态资料 | `packages/scenic/generated/mobile.json`、后端知识来源定义 | 随镜像发布并记录校验和；不是 SQLite 表，不伪造数据库迁移记录 |

以运行进程的实际路径为准；旧 README 路径和 URL 编码历史路径不得当成唯一数据源。迁移前登记两库实际位置、大小、表行数和应用版本。`documents` 包含运行、选中运行、业务时间、检查点、订单、任务、OA、公告、聊天及审计相关状态，逐集合盘点，不只复制可见页面数据。

## 接口与适配要求

- 新增 `DATABASE_URL`（应用账号）、`HOST`（本机默认回环、容器 `0.0.0.0`）及受控连接池配置。生产连接启用经验证的 TLS；连接串不得进入日志。Compose 私有网络仅用于联调，可不启用 TLS。
- 采用一个 PG 数据库，平台与 QA 表保留名称；结构化 JSON 字段改为 JSONB，包括 documents.data、commands.result、journal.payload、messages.sources、scenic_states.data。非法 JSON 必须报告并阻止切换，不能静默丢弃。
- 文本 ID 保持原值，禁止一律强转 UUID；布尔字段转换为 boolean；毫秒时间戳用 bigint，应用返回原有数值语义；原有文本日期先保留原格式。journal.seq 用 bigint identity，导入后校正序列到已导入最大值之后。
- 保留主键、复合唯一约束、账号外键、密码哈希、token 哈希、幂等指纹及结果。JSONB 改变键序后不能重新计算旧请求指纹；新请求指纹算法保持契约兼容。
- 将 `DatabaseSync`、`?` 占位符、`BEGIN IMMEDIATE`、SQLite JSON 函数、rowid 和 AUTOINCREMENT 转换为 PG 对应实现。历史检查点清理改为一次性、可审计迁移，不在每次启动执行数据修补。
- 仓储、HTTP、AI、仿真、认证、快照及测试调用链改为异步。同一事务借用同一池连接，提交/回滚后在 finally 释放。禁止把同步事务回调改成 async 后提前提交。
- 用数据库约束与事务内锁保证并发幂等、配额及 expectedVersion 校验；后台仿真与请求写入也进入统一写入调度。不能依赖 JavaScript 原来的同步调用顺序。
- 数据库回滚时不得残留已变更的内存运行对象：提交后替换内存快照并广播，失败恢复或重新加载。WS 失效通知仅在提交成功后发送。
- 版本迁移由独立发布步骤执行，记录版本和结果；普通启动不得清空、重置或创建新的展示运行。种子资料只补缺，不覆盖已迁移账号及业务；正式环境禁用自动创建弱密码演示账号。
- 就绪检查必须验证数据库连接、schema 版本及目标为可写主库；存活检查不依赖 LLM。退出时停止接收写入、停止时钟和 AI 任务、等待或取消事务后释放连接。现有 health 接口尚不满足全部要求。

## 迁移与回退流程

1. 在副本数据上演练；备份两库并检查一致性、孤儿记录、非法 JSON、重复约束及历史路径，生成不含敏感值的源清单。
2. 进入维护窗口：阻止所有入口写入，停止活动后端、仿真和 AI；确认没有其他 SQLite 写者。使用 SQLite 一致性备份接口，或全部写者退出并完成 checkpoint 后归档数据库及所需 WAL。不能在线只复制一个 `.sqlite` 文件。
3. 创建空 PG 目标，使用迁移管理员建 schema；按依赖导入账号再会话等数据，批次可重试且重复导入不会重复建记录。生产应用账号只获得业务所需权限。
4. 核对逐表/逐集合数量、主键集合、标准化 JSON 内容校验和、最大日志序号、密码哈希、会话到期、幂等结果和选中 runId。导入错误立即停止，不允许带错误开放。
5. 将未完成生成按当前中断语义处理并登记；启动一个候选后端执行只读与受控写入冒烟，核对六端、业务时间及修订号。建立基线备份并确认主备初始化状态后开放。
6. 开放前失败：关闭候选后端，恢复原版本和成套 SQLite 备份后再开放。开放后出现新写入：暂停服务、备份 PG、登记新增数据并制定回迁/前向修复；不得直接恢复旧 SQLite 后接受业务。

## 验收

- 迁移重跑、非法 JSON、约束冲突、导入中断均有可追溯结果；源库和原始备份不被修改。
- 原账号登录、会话恢复、QA 历史/来源、运行与回放、日志排序及检查点恢复保持语义一致。
- 并发相同幂等键只产生一次业务结果；不同内容同键返回冲突；配额不超卖、版本冲突不覆盖新值。
- 人为制造事务失败，数据、运行修订和内存一致，客户端不收到成功广播。
- 重启不重置场景；六端同运行同修订的公共字段一致；断线重连重新读取快照。
- 报告记录源/目标版本、数据量、停写时长、校验结果和回退演练。通过记录见实施记录；生产主备初始化单独验收。
