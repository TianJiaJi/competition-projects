# 手机游客端视觉与交互方案 V1.0

> 2026-09-12 · 三轮视觉方向已获用户确认：整体气质与信息密度、导览地图与面板比例、路线/预约结果/我的/聊天室。以全局视觉规范为底稿，细化本次确认的手机端范围。本文不是已实现或已验证的产品说明。

## 1. 已确认范围与设计主张

手机端使用 uni-app、Vue 3、TypeScript，同一套业务源码面向 H5 演示与微信小程序编译；平台能力另做适配。底部导航为「首页、导览、预约、我的」。真实 AI 仅为 `deepseek-flash` 文字问答，不做智能体、语音或业务代办。路线为独立偏好表单和预设模板筛选。

预约、位置和聊天先做统一的本地 Mock；聊天包含全园及景点房间、预置消息和本地发送，不宣称多人实时连接。跨端联动预留接口。地图标注演示位置，支持开始、暂停、继续移动。模拟入园在独立演示控制入口，不进入游客业务菜单。本轮不接人脸识别。

**建议视觉方向：以青绿山水呈现景区，以清楚的现代界面完成服务。** 首页建立游览氛围；导览让地图占主导；AI 回答像一篇可追问的讲解；预约和个人页面注重操作效率。沿用浅色主题，不新增深色主题。

## 2. 视觉系统

| 项目 | 首版提案 |
| --- | --- |
| 基准画幅 | 390×844 CSS 像素，补验 360px 和 430px 宽；320px 检查不溢出，允许纵向延伸 |
| 页面与内容底 | 浅青 `#EAF3EF`；稳定阅读面 `#F8FCFA` |
| 文字 | 主色 `#193B35`、次色 `#536B63`；错误 `#B33F36`；状态必须同时有文字 |
| 强调 | 主按钮深青绿 `#175F54`，石青 `#255D78` 用于地图路线；赭金仅做小面积文化细节 |
| 字体 | 展示标题宋体 32–40px；页面标题 28px；分组标题 20px；正文和输入 16px；辅助 12–14px |
| 排版 | 正文行高 1.6，AI 长回答 1.75；左右 20px 留白，320px 可缩为 16px；主要间距 8/12/16/24/32px |
| 圆角 | 按钮 14px，普通容器 20px，底部详情面板 24px；长回答不套大气泡 |
| 图标 | 统一圆角线性图标，24px；实际点击范围至少 44×44px；不混用 emoji 充当功能图标 |
| 玻璃 | 仅用于底部导航、地图工具及少量首页入口；表单、长文和聊天记录使用稳定浅色底 |
| 动效 | 按压反馈约 150ms，面板开合约 280ms；首页远景可缓动，表单和阅读区无持续装饰动画 |

首版视觉示意采用稳定实色模拟玻璃层次，正式样式先用底色、细亮边和轻阴影建立质感。模糊是增强项，不是必须条件。正文对比度至少 4.5:1，不能仅检验透明层的原始色值。

### 导航与公共骨架

- 四个一级页面显示底栏，图标与中文常驻；选中项用深青文字和浅青选中底，不放巨大中央按钮。视觉上可悬浮，布局上必须给底栏和系统安全区留足空间。
- AI 问答、聊天室、预约表单、订单详情、景点详情为二级页面，隐藏底栏，使用统一返回栏。
- 微信端导航避开状态栏及胶囊区域；H5 不绘制假微信胶囊。示意不包含设备状态栏，真实页面按平台测量。
- 重要公告使用静态可展开条目。关闭、预约失败、位置演示性质等关键文字不得靠轮播才能看到。

## 3. 逐页构图与交互

### 首页：先看景，再出发

自上而下为轻顶栏、山水主景、入园预约主行动、四个快捷服务入口、景点推荐与资讯。

- 顶栏显示景区名和简短天气/开放状态；重大停运公告置于主行动前，普通公告放后续内容区。
- 主景约 240–280px，青绿近山、淡青远山和大块留白；短宋体标题位于留白区域。首版建议「在山水间，慢下来」，实际景区名称从共享内容读取。
- 首屏主按钮「入园预约」；已预约时改为「查看预约」，已入园时改为「继续游览」，不同时堆叠多个同等级主按钮。
- 四个服务入口为「AI 问答、路线推荐、服务设施、游客聊天」，两列排列。停车在预约页内明确可见，首页不重复堆满入口。
- 下方推荐景点采用横向图片＋文字的纵向列表，单条保留名称、短介绍、开放状态。图片尚未准备时用明确的视觉占位，不伪称真实景区照片。

### 导览：地图为主，详情按需出现

- 使用现有公共景区二维底图的空间关系、点位和路网，不重新画一套地理布局。正式手机实现不假定 DOM SVG 组件能够直接编译至小程序。
- 顶部为搜索及设施筛选，初始筛选「全部、景点、卫生间、停车、索道」；不把每个状态做成独立悬浮卡片。
- 右侧最多三个工具：「全景、我的演示位置、扫码」。底部保持「路线推荐」入口和当前游览状态。
- 点位被选中后高亮描边，底部面板显示名称、开放/忙闲状态、摘要，以及「查看详情」。景点详情再提供问答与聊天室入口。
- 面板支持收起、半屏、展开三个状态，并提供可点击的展开/收起按钮，不依赖手势。调整地图可视区域，选中点不能落在面板下面。
- 路线深石青实线配浅色外描边；起终点及方向有明确标记。移动标记旁显示「演示位置」，暂停时显示「已暂停」。
- 道路关闭时显示受影响提醒和「重新选择路线」，不静默更换路线。首版状态来源于统一 Mock。

### 路线推荐：用选择完成规划

- 独立二级页。时长、兴趣和节奏置于上部；老人/儿童/无障碍、必去点和避拥堵置于后续分组，允许自然滚动。
- 单选用分段或选项卡，多选用带勾选状态的标签；固定底部「推荐路线」按钮，表单内容预留操作区空间。
- 推荐结果页列出匹配路线，每条显示名称、距离、预计时长、主要途经点和预设推荐理由；不显示模型思考过程。
- 详情页由地图、行程节点和「选用路线」组成。预览与已入园游览保持不同状态；无结果时明确提示调整条件。

### AI 问答：可追问的讲解阅读页

- 首页进入时标题为「AI 问答」，主体是简短欢迎语与三个可直接点击的问题；从景点进入则标题下显示可移除的景点上下文标签。
- 用户问题在右侧使用紧凑浅青气泡；回答左对齐、直接排在稳定浅色阅读面，减少嵌套卡片。
- 回答支持段落、短标题和列表，来源折叠在回答下方，点击展开条目与引用摘要；不接受模型任意 HTML。
- 底部为多行文字输入和发送按钮，键盘弹出后输入区保持可见。生成时按钮变为「停止」，保留已输出文本；用户向上阅读时不强制滚回底部。
- 流式等待显示「正在整理回答」，无虚构推理步骤。中断保留部分正文并标「回答未完成」，提供重试；模型不可用时提供重试和知识阅读入口。
- 动态状态回答附对应业务时刻；本地演示状态可在来源详情中辨识。问答历史从「我的」进入。
- 示意中的回答是排版样例，不能用于声称真实模型接入成功。`deepseek-flash` 的端点和流式能力留至接入验证。

### 预约：步骤清楚、结果清楚

- 一级页顶部切换「入园预约 / 停车预约」，下方日期和可选时段，预约记录入口放在标题附近。
- 入园表单包含人数与联系信息；停车表单包含停车场、时段和车辆信息。余量、免费属性及取消规则在提交前可见。
- 选择、填写、确认按自然分组呈现，不制造不必要的多页向导；固定底部主按钮，错误在对应字段旁展示。
- 成功页显示确认标记、日期时段和人数/车辆，并提供「查看预约」。入园预约不展示旧版扫码核销码，注明按现场指引完成人脸识别；人脸采集本轮不设计。
- 入园预约状态与是否已入园分开呈现，停车预约状态与实际空位分开呈现。取消、改期在详情页可发现，取消需要明确确认。
- 停车是否展示凭证及凭证形态在业务专项中继续细化，不将人员入园方式直接复制为车辆识别。

### 我的与聊天室

- 「我的」采用简洁身份区与分组列表：我的预约、我的收藏、问答历史、游客聊天；使用体验身份，不添加积分、会员和消费统计。
- 聊天室是二级页，顶部显示房间切换，正文采用常规左右气泡。预置游客具有「模拟游客」标识，顶部轻提示「本地演示」。
- 聊天支持文字、表情和本地历史；不显示虚假的在线人数、跨设备送达或已读状态。键盘与输入区规则同问答页。
- 景点详情使用主图、宋体标题、状态、介绍正文和底部动作；「在地图查看」为主，问答、收藏、聊天室为次操作。来源、设施参数和长介绍通过清晰分组展开。

## 4. 状态、素材与平台适配

| 场景 | 视觉反馈 |
| --- | --- |
| 内容加载 | 与真实布局一致的浅色骨架；不全屏遮住已经可用的功能 |
| 无收藏/无历史 | 短说明加明确入口，无大幅通用空状态插画 |
| 预约满额 | 时段标「已约满」并禁用，允许换日期；不用点击后才通知 |
| 设施关闭 | 文字「暂时关闭」优先，忙闲信息降级，地图有额外标记 |
| AI 失败 | 回答位置呈现具体失败及重试，不用全页弹窗覆盖历史 |
| 本地重置 | 独立演示入口操作前确认，游客页面回到一致初始状态 |

素材准备：沿用共享景区名、点位名和底图；首页新增横向青绿山水主景，景点详情需要配套图。首轮示意仅用代码形状表达构图，后续按评审方向准备精修素材。固定标题保留真实文字，不把正文做成图片。

平台规则：不直接复用依赖浏览器 DOM 的 UI 组件；共用色值、间距、图标资源和业务数据，必要时使用 uni-app 组件重建。地图可采用共享底图预渲染资源加交互层，具体渲染方案通过双端技术验证后选定。字体使用本地回退，模糊失效时使用稳定底色；微信分包/资源大小在实施时校验。SSE、键盘、安全区与扫码分别实测，不将「同源编译」表述成所有浏览器能力自动兼容。

## 5. 视觉交付顺序与验收

1. 评审首页、AI 回答、预约页的构图示意，锁定装饰强度、内容密度和标题尺度。
2. 基于真实共享地图完成导览的默认、选点、半屏详情、使用路线四张关键状态稿。
3. 补齐预约成功/失败、我的、景点详情、路线筛选/无结果、聊天室及 AI 中断状态。
4. 将关键页落实为 uni-app 页面，尽早验证 H5 与微信编译及真实手机，后续接入真实问答。

验收：390/360/430px 无遮挡和横向溢出；正文不靠缩小字号容纳内容；底栏和键盘不遮挡操作；每个可见按钮有反馈；选中、关闭、失败不只靠颜色；AI 长回答和长景点名能自然延伸；减少动效和无模糊时仍保持层级。先验收关键页面，再扩展次级页面。

**评审状态：** 用户已确认首轮整体气质与信息密度。保留浅青底、青绿山水、宋体展示标题、稳定正文阅读面和四栏导航，后续不再重新选择风格。接口、真实模型连接、跨端业务及微信真机验证尚未完成。

## 6. 第二轮导览专项（视觉方向已确认）

### 基于现有地图的四种状态

地图来源为 `@scenic/scenic` 的 `createScenicSvg`，景区名称为「青岚山境」。提案直接使用当前共享地形、水系、步道和点位坐标，不单独维护手机景区布局。

| 状态 | 地图与标签 | 底部面板 | 操作 |
| --- | --- | --- | --- |
| 默认浏览 | 展示全园，初始只保留望岳台、镜湖栈道、竹影幽径三处标签；地图缩放或搜索后补充其他点位 | 简短导览说明和路线入口 | 切分类、选点、恢复全景、查看演示位置 |
| 选中景点 | 高亮当前点位，弱化或隐藏其他标签，保持当前点在面板上方 | 景点名、开放状态、忙闲、短介绍 | 展开详情、在地图定位、关闭面板 |
| 展开详情 | 缩小地图可见高度，围绕选中点调整取景；不缩小地图上的文字 | 介绍正文、问答/聊天/收藏入口 | 收起详情后回到地图，打开对应二级页面 |
| 使用路线 | 沿真实步道绘制深石青路线和浅色描边，显示目的地与演示位置 | 路线名、起终点、游览状态 | 开始、暂停、继续、换路线 |

第二轮示意中的「景区入口 → 镜湖栈道」仅验证路线线条、位置标记和控制区的视觉关系，使用共享路网的 `road-7 → road-6 → road-13`；不是正式推荐模板，不据此承诺游览时长或距离。正式约 8 条路线须另行配置与校验。

### 信息密度与操作规则

- 分类条采用「景点、卫生间、停车、索道」，初始选中景点；这是对上一轮「全部＋分类」的进一步简化提案。暂不增加首屏搜索框；正式页可通过搜索入口进入独立搜索层，避免地图上方工具占用过多高度。
- 示例地图保留两个工具：全景、演示位置。扫码入口放在独立搜索/更多服务层，正式实现仍保留扫码能力，不与两个高频工具挤在一起。
- 开放与忙闲放在详情面板，地图默认不同时铺上每个设施的多个状态标签。关闭的点位通过额外关闭标记保留可见性。
- 卫生间与停车等密集点位在正式实现中需要碰撞避让和聚合；打开搜索或列表时能找到全部点位，不能为了减小密度永久隐藏部分设施。
- 面板操作提供明确按钮；手势只是增强项。展开正文后继续自然滚动，固定的真实底栏及安全区不覆盖最后一条内容。
- 第二轮会话示意采用自然高度来比较构图，尚未实现固定手机视口的拖拽面板、地图缩放或小程序安全区行为。正式实现以 390×844 为主检查：默认地图约 340–385px；展开后可见地图约 200–230px，长正文独立滚动。
- 位置动画仅演示行进视觉，点击开始才播放，暂停后位置不再更新；地图静态浏览不自动运镜。真实页面应另处理关闭页面、减少动态效果以及运行重置。

### 本轮检查与后续边界

会话示意已检查四种状态在 320/360/390/430px 下无横向溢出，验证页面状态切换、开始与暂停反馈；底图和路线取自现有数据。此检查不等于设施标签碰撞、完整导航、实际模板、uni-app 双端或业务数据已通过验收。

后续沿已确认风格补齐路线偏好、景点详情、预约结果、我的和聊天室；进入业务编码前汇总视觉稿中的新增决定及仍需适配的交互，不扩大为真实跨端联动。

## 7. 第三轮服务页面（视觉方向已确认）

延续前两轮确认的配色、字体、圆角与信息密度，不再新增一套材质语言。第三轮重点为表单、结果、个人入口和本地聊天室。

| 页面 | 视觉结构 | 主要反馈 |
| --- | --- | --- |
| 路线偏好 | 宋体短标题；时长、兴趣、节奏三组直接可见；同行、无障碍、必去点与避拥堵在可展开分组 | 单选/多选均有勾选和填色，底部只有「推荐路线」主行动 |
| 预约结果 | 居中结果标记与标题；浅色预约信息卡，突出日期时段、人数和独立入园状态 | 成功、已取消及失败文案分开；改期、取消在详情内，不在成功首屏抢占主行动 |
| 我的 | 体验身份、最近待入园预约、四项纵向服务列表、底部四栏 | 未预约时隐藏待入园卡或显示简短入口；不堆叠占位统计数字 |
| 聊天室 | 房间切换、消息区、文字与表情输入；隐藏一级底栏 | 自己与他人左右区分，模拟游客和本地性质可见；切房间保持各自记录 |

### 路线偏好及结果

- 默认展示 2 小时、自然/摄影、轻松、避拥堵；这是演示初始选项，用户可更换，不表示真实推荐计算已经实现。
- 兴趣与同行条件允许多选；时长与节奏单选。必去点在正式页面为多选列表，第三轮示意只用单个选择器表达位置。
- 收起高级条件后，正式页面显示已选条件摘要；无障碍、必去点等约束不能因分组收起而被忽略。
- 匹配结果另页展示，沿用第二轮的地图、路线与行程节点样式。无匹配时在结果区域显示原因及「调整条件」，保留所有已填项，不用成功卡承载失败。
- 本轮示意点击推荐仅回显偏好，不模拟不存在的路线算法或编造时长、距离。

### 预约成功、详情和取消

- 信息卡采用顶部细青绿线及内部轻分隔，避免二维码、条形码、仿票券撕口让游客误以为可以扫码入园。
- 成功页主行动为「查看预约详情」，次行动「返回首页」。详情中才显示改期与取消。取消必须先展示确认操作，确认后结果标题、订单状态与「我的」预约概览同步变化。
- 失败在原表单保留输入，并显示字段错误或余量不足；请求结果未知不能表现为已预约。虽然本轮为 Mock，状态设计仍为后续接口接入保留区分。
- 停车结果复用同一信息卡，替换为停车场、时段、车牌和预约状态，明确「预约不代表已占用实体车位」。停车凭证具体形态仍待业务专项确定。

### 我的与聊天室

- 「我的」四项列表为我的预约、我的收藏、问答历史、游客聊天。昵称编辑只改变体验昵称，不引入会员、实名或积分体系。
