# 手机游客端与文字问答开发任务书 V1.0

> 2026-09-12 · 需求与三轮视觉方向已确认；以下为实施拆解及建议默认值，尚未开始业务编码。未通过的兼容性检查和模型连接不得视为完成。

## 1. 已确认交付

- 手机端采用 uni-app、Vue 3、TypeScript，H5 用于演示，同源编译为微信小程序页面，不使用 WebView 壳替代。
- 底部四栏：首页、导览、预约、我的。视觉以[已确认的视觉与交互方案](手机游客端视觉与交互方案-V1.0.md)为准。
- 真实 AI 仅接 `deepseek-flash` 文字问答：景点上下文、追问、流式回答、来源、历史、重试；不做语音、智能体或业务代办。
- 路线使用偏好表单筛选约 8 条预设模板，与问答独立。地图为二维，共用青岚山境的底图、点位与路网。
- 其他业务使用统一的本地 Mock：入园与停车预约、取消/改期、收藏、设施状态、位置推进、聊天室。先留跨端接口，不实现跨设备同步。
- 模拟入园在独立演示入口。预约不增加在园人数，不把人脸识别接入或扫码核销恢复成本轮任务。

本次工作空间仍保留其他端，手机页面不得直接引用其他应用源码。AI 的最小服务端放入已有 `apps/server` 职责范围，不以接入问答为由开发全部五端后端。

## 2. 页面及状态交付清单

清单按用户可见界面组织；可共享页面组件，不要求每种状态新建一个路由。

| 界面 | 正常交付 | 必须覆盖的状态 |
| --- | --- | --- |
| 首页 | 山水主景、公告、状态化主行动、四服务入口、景点与资讯 | 未预约、已预约、已入园、重要公告、内容加载失败 |
| 导览 | 分类、选点、详情面板、全景/演示位置、搜索及扫码入口 | 全园/选点/展开/使用路线、关闭设施、找不到点位 |
| 景点/文物/设施详情 | 图片、名称、状态、介绍及服务信息，地图/问答/收藏/聊天入口 | 长文、无图、收藏切换、设施关闭、数值未知 |
| 搜索及扫码承接 | 内容与点位检索，景点码/文物码定位到正确详情 | 无结果、无效码、摄像头不可用、运行不一致 |
| 资讯/公告 | 列表和正文阅读 | 空列表、长标题、重要公告、内容缺失 |
| 路线偏好与结果 | 时长/兴趣/节奏/同行/必去点/避拥堵，结果列表与详情 | 多选摘要、无匹配、道路关闭后重选、选用成功 |
| 预约一级页及表单 | 入园/停车切换，日期、时段、人数或车辆资料 | 满额、字段错误、重复点击、保留已填项 |
| 预约列表/详情/结果 | 预约记录、成功反馈、取消、改期、人员/车辆独立状态 | 已取消、已入园、未入园、改期无名额、操作失败 |
| 我的 | 体验身份、待入园概览、四项服务列表 | 未建立身份、昵称编辑、无待入园订单 |
| 收藏与问答历史 | 真实可查询的本地收藏/服务端问答记录，回到详情或会话 | 空记录、内容失效、生成中/未完成标记 |
| AI 问答 | 全屏文字页，景点上下文，问题、回答、来源、输入框 | 初始/等待/流式/完成/无依据/中断/失败/重试 |
| 聊天室 | 全园及景点房间、本地发送、表情、模拟身份标识 | 切房间、空输入、长文本、本地记录恢复 |
| 独立演示控制 | 模拟入园、位置初始值、设施样例状态、重置 | 重复入园不重复计数、取消重置、运行变化 |

演示控制通过独立开发/演示入口访问，不在「我的」里隐藏一个游客可误触的入园按钮。所有仅用于说明的视觉占位，在页面验收时要替换为可操作入口或完整内容。

### 关键异常态的视觉落地

- 空内容：保留页面结构，用短说明与一个可继续的动作；不新增大幅无关插画。
- AI 中断：保留已经生成的文字，标「回答未完成」及重试。网络失败不改成预置答案；来源只展示通过校验的内容。
- 预约失败：留在当前上下文并保留输入，区分字段错误与余量不足。请求未知状态只在接入真实写接口时启用，不能直接显示成功。
- 路线无匹配：显示具体约束原因和「调整条件」；关闭道路不得仍出现在推荐路径。
- 状态变更：我的预约概览、预约详情、导览中的个人游览状态使用同一数据源。取消后不保留「待入园」卡片。

## 3. 数据与接口边界

### 本地业务 Mock（建议实施默认值）

通过数据适配层隔离页面与存储，页面不直接散落写入本地存储。演示身份、订单、收藏、聊天室和游览状态使用同一份带版本的本地数据；默认通过 uni-app 存储接口保留，刷新能恢复。失效版本显示重置提示，不静默清空用户操作。

独立演示重置生成新的本地运行标识，恢复种子状态并中止当前游览；AI 运行上下文同时更新，旧历史不能混入当前会话。H5 和微信是独立体验，不宣称共用本地账号或订单。

预约创建、取消、改期和模拟入园以一次状态变更更新所有相关视图。停车预约不占实体车位，入园预约不增加在园人数；仅模拟入园将订单人数绑定到游览批次。未入园允许路线预览，开始/暂停/换线不重复入园。聊天室按房间隔离本地消息。

路线模板由当前路网中的点位与边构成，展示时长和距离必须注明口径并通过校验。不能用第二轮视觉稿的单段步道自动凑成八条正式线路。内容与模板精修是实际开发任务，不是现有成品资产。

### 真实问答的最小后端

沿用现有接口基线中的创建会话、消息历史、提问和来源详情：

- `POST /api/v1/qa/conversations`
- `GET /api/v1/qa/conversations/{conversationId}/messages`
- `POST /api/v1/qa/conversations/{conversationId}/messages`
- 来源详情沿用接口文档的 `getSource`，不新造第二套来源协议。

保留 `start / delta / sources / done / error` 流式事件及消息 ID，保存可见问题、回答、引用和失败状态。按景点及关键词取预置知识，不加向量数据库；动态状态仅可引用当前演示公开快照。推荐模板文案与模型回答保持可辨识。

模型名配置为 `deepseek-flash`；`baseUrl` 和密钥只在服务端配置，不预设它一定对应某个官方端点。实际可调用性、流式响应及取消能力在 P0 验证，失败必须如实报告，不擅自换模型。

为真实问答建立最小服务端游客身份和会话持久化，不把客户端自报的用户 ID 当成身份校验。其他预约等业务仍保持本地。纯问答端接入不要求运行完整客流仿真。

### 需要明确记录的接口差异

- 原方案前端为 Vite H5，本轮手机端改为 uni-app；共享浏览器组件不能默认直接复用。
- 旧接口游客身份基于 Cookie，微信小程序不能直接套浏览器会话假设；平台身份适配必须在 P0 给出验证记录。
- 旧 `X-Run-Id` 来自后端运行，本轮本地运行与问答服务上下文需要最小映射。客户端提交的 Mock 状态只作演示公开数据，不能作为可信生产状态或授权依据。
- 入园人脸方式替代旧扫码核销；本轮只模拟入园事件。停车凭证仍与人员入园分开，未明确前先以预约记录页承接，不新增虚构核销功能。
- 接口新增或变更必须同步 Markdown 与 OpenAPI；在完成更新前，文档中的规划不视为已有服务能力。
