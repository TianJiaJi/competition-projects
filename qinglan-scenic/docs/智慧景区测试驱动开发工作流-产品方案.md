# 青岚山境 · 让每一次上线，先经历一座景区的考验

**基于超写实虚拟实时数据生成器的智慧景区测试驱动开发工作流**

> 本文面向竞赛评审与产品展示，描述目标产品能力和验证方式。现有工程已具备共享仿真、运行控制与跨端联动基础；视觉写实升级、集群故障演练及完整 AI 质量门禁按目标方案展开。文中的通过条件不代表已经取得的验收成绩，实际状态以[实施记录](implementation/PG迁移与本地联调-2026-09-13.md)和[验收台账](implementation/六端确认与验收台账.md)为准。

## 一、让景区成为可运行、可验证的研发现场

智慧景区的复杂性来自同时发生的业务：游客预约入园、车辆寻找泊位、热门景点逐渐拥挤、设施临时停用，导览建议和智能回答也必须随之变化。一个页面显示正常，并不能证明整套系统已经准备好迎接真实运营。

到真实景区反复制造高峰与故障，成本高且影响运营；等待极端场景自然发生，难以满足版本迭代节奏。分散的测试数据又容易让导览、大屏与手机端各自正确，却无法共同解释同一时刻的现场。AI 加入后，团队还需要证明回答能够依据知识与实时状态变化。

青岚山境将一座持续运行的虚拟景区引入研发过程：用超写实虚拟实时数据生成器提供业务环境，用六端应用承接真实操作，用测试结果决定版本能否进入下一阶段。团队可以主动安排高峰、复现异常、验证恢复，让每次更新接受同一套可追溯的检验。

这里的“测试驱动开发”采用贯穿交付的广义定义：先明确场景和验收标准，再开展开发、测试、部署与联调。**让复杂场景能够重现，让系统变化能够解释，让上线决定有据可查。**

## 二、超写实虚拟实时数据生成器：一座会演化的景区

### 视觉可信，行为有因，数据相互印证

视觉层以地形、植被、道路、设施和游客移动构建可辨识的空间现场，目标是结合细致场景表现、自然运动与即时状态反馈，让评审者直观看到人流如何聚集、疏散和影响服务。现有三维沙盘为后续视觉写实升级提供空间与交互基础。

行为层以游客到达、路线选择、步行停留及设施使用推进运行。预约影响入园需求，入园带来区域流量，热点停留形成排队，停车周转影响余位，设施停用改变可用服务；阈值变化进一步触发告警和处置流程。人数、车辆、容量与业务状态遵循关联规则，避免每块屏幕独立生成互不相干的数字。

“超写实”的产品价值就在于这种可观察的因果关系：看到排队变化，能够追溯需求和运力；看到提示更新，能够找到状态变化的依据。视觉、数值和业务反馈共同说明正在发生什么。

### 时间可控，场景可复现

生成器支持随时间推进的实时运行，以及独立的场景回放。团队可以暂停观察、加速等待、定位关键时刻，并在相同场景版本和初始条件下重复测试。一次缺陷能够连同触发条件被保留，修复后的版本重新接受相同考验。

测试注入通过业务事件或明确标记的场景参数进入共享状态，带动后续演化。生成器负责景区业务负载；并发脚本负责请求压力；基础设施演练负责节点故障。三者共同覆盖业务复杂度、访问强度与运行环境变化，并留下各自的验证记录。

## 三、从代码提交到发布准入的完整闭环

**场景定义 → 开发提交 → 自动测试 → 部署刷新 → 扩容压测 → 故障核验 → AI 升级评测 → 六端联调 → 发布准入**

### 1. 用验收标准明确本次改变

每轮迭代绑定代码版本、场景条件和预期结果，明确页面变化、业务影响及需要同步的终端。前端研发完成本地界面检查，确认布局、交互与状态反馈符合要求，再提交代码，将版本和检查结果交给测试负责人。

测试负责人执行对应的自动测试，检查关键业务规则、接口与回归场景。测试全绿后形成部署依据；失败项关联到本次版本，修复并重新验证后继续流转。

### 2. 让新版本在运行现场可见

平台运维部署通过测试的 UI 版本，核对发布标识与服务状态。大屏刷新后，现场确认新界面已经生效，并检查数据连接、关键交互和异常提示。部署记录与终端观察共同证明本次更新已到达用户使用的界面。

### 3. 用压力证明扩容价值

平台运维执行应用扩容，确认新增副本就绪并接入服务。测试负责人随后运行并发脚本，在明确的请求模型和景区负载下核对请求成功率、响应时间与错误情况。

扩容前后的测试采用可比较的条件，报告说明新增资源是否改善承载能力，以及业务结果是否正确。进入下一环节的依据是压测满足本轮约定标准，具体容量和性能数值由实际测试给出。

### 4. 主动制造故障，检验恢复与数据底线

在隔离的演练环境中，平台运维主动使一半 Kubernetes 工作节点失效，观察故障识别、应用重新调度和服务恢复。演练事先核对剩余节点容量、工作负载分布、控制面与持久化存储条件，使故障影响范围明确、恢复路径可执行。

应用可在存活节点上重新建立副本；失效工作节点的恢复和重新加入，由相应基础设施恢复流程完成。现场分别展示这两个过程，并在恢复后检查副本、连接与服务状态。

测试负责人以故障前已确认写入的记录为基线，核对恢复后的预约、任务及相关业务数据，同时检查重复写入和关联状态。“数据零丢失”作为本次演练的验收目标，由已确认写入记录完整保留的证据支持；超时或结果不明的请求单独核查，避免把未知结果混入结论。

### 5. 让知识与智能体升级接受同等检验

AI 研发提交新版本知识库与智能体配置，说明知识变化、适用范围和预期行为。平台运维更新 AI 服务，确认实际加载版本，再由测试负责人运行黄金用例。

用例覆盖景区知识正确性、实时设施状态一致性、知识不足时的拒答，以及超时、上游失败等异常处理。评测同时核对事实、依据和处置行为，不能仅凭接口成功返回就判定合格。

本轮结论表述为“黄金用例全部满足预期，指定用例范围内未出现无依据回答”。报告关联知识、智能体、模型和用例版本，让后续升级能够重复比较。

### 6. 多端联合确认，形成上线结论

上述检查完成后，测试负责人宣布进入联调，注入约定场景并逐项播报测试内容。前端研发观察导览终端，平台运维观察数据大屏，AI 研发观察手机游客端，依次说明本端收到的变化及其是否符合预期；涉及管理或前线操作时同步核对相应终端。

测试负责人汇总功能、性能、恢复、数据与 AI 证据，确认全部满足本轮标准后，宣布测试完成并形成允许新版本上线的结论。前端研发作为全程主讲，在结束时串联本次改变、验证过程和用户收益。

## 四、六端共同回答同一道测试题

| 终端 | 产品职责 | 联调关注点 |
| --- | --- | --- |
| 游客导览终端 | 提供公共地图、设施查询与路线引导 | 点位状态、热力及路线建议是否响应变化 |
| 园方数据大屏 | 呈现运营态势、趋势、告警与任务 | 指标与现场一致，处置状态可追踪 |
| 手机游客端 | 承接预约、导览、通知与智能问答 | 个人操作有效，提示与回答符合当前状态 |
| 管理员后台 | 维护内容、设施与规则，处理审批 | 管理变更生效，审批记录与业务状态一致 |
| 前线处置终端 | 领取任务、提交 OA 与完成反馈 | 任务流转有效，待审批事项阻止违规结案 |
| 演示控制端 | 管理运行、时间及场景注入 | 各端绑定同一运行，触发条件可追溯 |

以“热门区域需求上升，邻近设施临时停用”为目标联调场景：测试负责人记录初始状态，通过控制端注入需求变化，并执行明确的设施状态变更。生成器推进客流和设施负载，后端按规则形成相应状态、告警与任务。

园方大屏应展示对应区域及任务变化；导览终端应更新设施可用性，并按规则调整提示和候选路线；手机端应呈现适用的游客通知，AI 面对相关询问时应依据当前状态作答。公开终端只接收面向游客的信息，内部任务与审批保留在工作人员端。

前线领取任务、提交申请或反馈，管理员完成必要审批，各端随后核对状态推进。任务完成和设施恢复分别验证，避免仅凭结案就认定服务已经恢复。测试负责人用同一运行标识、业务时间和记录版本核对六端结果，将一次注入转化为可解释的业务验证链。

## 五、四类角色，各自操作、各自举证

| 角色 | 负责的工作 | 交付物与交接 | 现场说明重点 |
| --- | --- | --- | --- |
| 前端研发／全程主讲 | 本地 UI 检查、代码提交、导览端联调及全程串联 | 提交版本、界面检查结果、导览确认记录交给测试 | 改了什么、如何检查、用户获得什么变化 |
| 测试负责人 | 自动测试、并发测试、数据核查、黄金用例及联调组织 | 各阶段报告、缺陷记录和发布准入结论 | 测什么、依据什么、结果如何、是否进入下一阶段 |
| 平台运维 | UI 发布、扩容、节点故障与恢复、AI 服务更新、大屏观察 | 部署版本、资源变化、恢复记录与大屏确认 | 执行了什么、系统如何响应、恢复依据是什么 |
| AI 研发 | 知识与智能体版本提交、预期定义、手机端及问答联调 | 知识变更、配置版本、评测预期和终端确认 | 知识如何更新、回答依据什么、边界如何处理 |

全程主讲负责连接问题、操作和价值，每位成员在自己的操作节点说明工作与证据。测试负责人掌握阶段切换和逐项核对节奏，使多人协作形成清晰的责任交接。

## 六、把一次演示沉淀为持续交付能力

产品的核心创新，是将持续演化的景区场景与版本验证结合。场景可以复用，缺陷可以重现，六端可以共同核对；扩容与故障恢复接受实际测试，AI 升级也有明确的质量门槛。每一轮交付都能积累下一轮可使用的场景、用例与证据。

在竞赛中，这套工作流让研发、测试、运维和 AI 能力通过同一业务目标得到展示；在教学实训中，可以用相同场景对比不同实现与处理方式；在主题园区、展馆及公共服务场所中，可围绕各自的容量、路径和业务规则建立类似验证环境。

**让一座虚拟景区提前经历高峰、变化与故障，让每一次真实上线都拥有更充分的准备。**
