# 沙盘性能与桌面显示适配

## 使用方式

游客大屏、园方端、管理端、演示控制入口均启用桌面整体缩放。前线处置终端（`apps/gate`，不是闸机端）和游客手机端不启用，保持原移动端尺寸和交互。

按最新需求，桌面页面以 **1920 逻辑像素宽度**为构图基准，随可用窗口宽度整体等比缩放。同一窗口宽高比下，系统或浏览器缩放变化后，布局和元素占页面的比例保持一致。1920 CSS 像素宽的页面在 100% 时倍率为 1，即使 DPR 为 2 也不会额外缩小 UI。

窗口变窄时整页同比缩放，不再触发原先按 CSS 视口宽度发生的桌面布局重排。窗口宽高比变化时可用逻辑高度相应变化。前线和游客手机端继续使用原有移动端响应式布局。

已删除显示校准入口及倍率存储的使用；早期版本保存的校准值不会影响页面。DPR 只参与画布清晰度计算，不参与 UI 布局。此约定取代此前“保持控件物理大小、窗口缩小时重排”的方案。

## 渲染与坐标约定

`@scenic/ui/display` 仅在四个桌面入口安装：

- 显示倍率 `scale = innerWidth / 1920`，逻辑宽度固定为 1920，逻辑高度为 `innerHeight / scale`。
- 根元素使用 CSS zoom，建立名为 `desktop-viewport` 的尺寸容器；桌面 Vite 的 PostCSS 插件把宽高媒体查询转换为该容器查询，把视口长度转换为对应的逻辑视口变量。无障碍、减少动态效果、触摸等媒体查询保持原义；手机构建不加载此插件。
- `layoutViewport`、`layoutRect`、`layoutPoint` 用于布局坐标；真实指针和命中测试仍使用浏览器坐标，跨越两者时换算一次。详情连线、唱片导航、滚动条定位和拖动均采用同一约定。
- WebGL 像素比根据 canvas 的实际显示宽度与逻辑宽度之比计算，再乘设备 DPR。1920×1080 输出在五档系统缩放下仍使用约 1920×1080 绘制缓冲区，避免补偿后再次乘 DPR。
- OrbitControls 的拖动速度同步补偿，使同样的物理拖动距离产生相同旋转角度。窗口或 DPR 变化时重新计算；没有修改业务 API 或后端契约。

## 保持外观的性能优化

1. 每帧矩阵序列化、调试 DOM 属性和详细性能采样改为按需开启。少量加载进度和状态属性仍保留。
2. 未显示热力图时不插值游客位置；显示时仅在原有 150ms 纹理刷新周期需要数据时插值，关闭区域遮罩仍随快照更新。
3. 点位与区域的静态地形坐标预计算，使用复合投影矩阵和复用向量；相机、沙盘和视口未变化时不重复发布投影。运动中仍同帧更新标签及连线。
4. 更新沙盘父变换时不再提前递归更新整棵模型树，再由渲染器统一更新后代；灯光世界矩阵仍按需同步。
5. 点位及告警标注层不参与滚动条的自动发现和祖先滚动条的样式观察，避免每帧位置变化触发重复扫描。
6. 水面仅共享所有属性完全一致的顶点，保留三角形顺序、法线、岸线属性及波浪计算。静态合批扩展到嵌套组内的不透明同材质兄弟节点；交互拾取对象、透明材质和状态分组保留。
7. 取消按低帧率自动降低清晰度、关闭阴影、删减水雾的默认行为，不默认锁定 30 FPS。

地形内部隐藏面**保留**。现有方块地形同时参与开场剖切、山底视角和阴影，未证明可安全移除，不以减面数量为验收目标。

## 按需诊断

含沙盘的页面添加 `scenicDiagnostics=1`，左下角出现“沙盘诊断”。等待开场结束，点“重新采样”，操作旋转、详情和返回约 20 秒，再点“导出性能记录”。移除参数并刷新即关闭。

导出 JSON 包括：可获取的 WebGL 渲染器/厂商、浏览器、DPR、逻辑尺寸、实际显示尺寸、绘制缓冲区、绘制次数、三角形数、几何存储信息，以及最近最多 1800 帧的间隔和 CPU 阶段耗时分布。`renderSubmitMs` 是 CPU 提交耗时，**不是 GPU 执行时间**。厂商信息为 null 表示不可获取，不能据此认定软件渲染。

也可在控制台调用 `window.scenicDiagnostics.reports()` 或 `.download()`。普通模式不会安装该 API。

## 本地对比结果

2026-09-20，macOS / Headless Chromium 153，1920×1080、DPR 1，固定 HTTP 快照、随机种子和动作顺序。每段约 4 秒，关闭诊断后用 CDP 统计真实页面脚本与主线程耗时。以下为首轮前后对比，不是实际大屏测量，也不是多轮统计结论。

| 场景 | 优化前脚本耗时 | 优化后脚本耗时 | 变化 | 优化前主线程耗时 | 优化后主线程耗时 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 持续旋转 | 575.7ms | 516.8ms | -10.2% | 806.2ms | 788.5ms |
| 详情运镜及停留 | 652.9ms | 488.3ms | -25.2% | 788.9ms | 621.2ms |
| 返回及旋转 | 531.3ms | 525.9ms | -1.0% | 691.0ms | 731.0ms |
| 热力模式 | 592.9ms | 467.4ms | -21.2% | 870.3ms | 780.4ms |

返回阶段主线程总耗时未改善，不能把脚本耗时下降解释为所有场景都更快。前后 P95 帧间隔均约 16.8ms；单次最大帧间隔容易受首次编译和运行环境影响，不将其作为保证。

固定静态全景和详情截图已逐图查看，未见外观差异。以单像素最大 RGB 通道差超过 12 为阈值，全景变化约占 0.0061%，详情约占 0.00019%；这两张代表图不替代所有动态帧的像素等价证明。开场、拖动、返回、路线及热力另有行为回归；静态截图未覆盖所有开场剖切帧。

最终版本另复测一次，结果保存于 `.local/qa/scenic-performance/final/`：旋转、详情、返回、热力脚本耗时分别为 385.2、433.8、431.1、399.0ms，P95 帧间隔为 16.7～16.8ms。运行环境为 Apple M5 / ANGLE Metal；这些数字不代表低性能大屏表现，也不替换首轮配对数据。导出的几何记录确认水面顶点存储由 31,932 个降至 5,491 个（减少约 82.8%），三角形与完整顶点属性保持不变。截图阶段诊断数据包含重新加载与编译，不能混作上述稳定运行采样。

原始文件位于 `.local/qa/scenic-performance/before/` 和 `after/`（metrics.json、overview.png、detail.png）。后续复测输出到独立目录：

```sh
SCENIC_BENCH_OUTPUT=.local/qa/scenic-performance/recheck pnpm test:performance
```

不要与其他浏览器测试或构建同时运行性能测量。比较时使用相同机器、浏览器、窗口、快照和动作；清空或保留 shader 缓存的条件也应一致。构建优化不能保证修复软件渲染造成的 CPU 满载，真实设备仍需确认硬件加速。

## 回归与复现

```sh
pnpm typecheck
pnpm typecheck:mobile
pnpm typecheck:gate
pnpm test:display
pnpm exec playwright test tests/e2e/touch.spec.ts tests/e2e/scroll.spec.ts
pnpm exec playwright test -c playwright.ops.config.ts
```

`test:display` 共 24 项（22 项首轮通过，2 项亚像素取整容差修正后复验通过），覆盖四个桌面端的五档显示参数、点位/连线/拖动、弹窗、图表、表格、旧校准值隔离、Retina 100% 与浏览器缩放、诊断导出，以及两个移动端不启用桌面缩放的检查。它启动隔离 PostgreSQL 测试 schema 和专用服务，结束时清理；需要本机测试数据库，或指定 `TEST_DATABASE_URL`。五档测试是视口/DPR 仿真，未替代 Windows 显示设置的实机验收。

专项单元测试包括 `desktop-display`、`scenic-optimization`、`heat`、`water`、`camera-flight`、`floating-island`、`scrollbar`、`record-rack-exposure`，共 33 项。游客触屏/开场 12 项、园方相关 14 项、公共滚动条与唱片导航 88 项完成回归；公共组件的报告目录冲突项使用独立输出目录复验。

游客、园方、管理、演示、前线端完成构建，手机 H5 完成构建；仍有既有 Three.js/ECharts 大分包与手机动态导入提示。旧管理/前线业务套件仍沿用历史 Mock 账号与服务假设，本次未宣称其全套通过；新增显示矩阵使用当前隔离服务验证登录、只读页面和交互，不修改线上业务数据。

补充沙盘旧用例中有两项尚未通过：详情运镜的中间帧假时钟断言、推进八小时后固定 HTTP 快照的索道关闭断言。本次未将其计入通过结果；它们仍需与当前快照及时钟机制对齐。
